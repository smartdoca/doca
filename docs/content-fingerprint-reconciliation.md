# 内容指纹与搜索对账

2026-09-30。通用内容来源、知识库订阅和搜索对账使用相同的判断原则：完整枚举当前范围的 ID 与指纹，只处理新增或指纹变化的项；只有完整枚举成功，才判断哪些项已经退出范围。消费进度和业务结果由各消费者负责。

## 通用文档内容块

`packages/core/src/modules/content/blocks.ts` 的 `contentBlocks(title, body)` 提供无数据库副作用的文本块投影。内置内容来源使用它生成清单和正文，消费者通过公开 `content.v1` 接入，不导入此宿主内部文件。

- 独立段落不跨段合并，避免前面插入内容导致后续段落重新分组。
- 超长段落按最多 2000 个 UTF-16 码元切分，优先在空格或换行处分开，不截断尾部或拆开 Unicode 代理对。长单段修改仍可能影响该段后续切片。
- `blockId` 为正文内容寻址标识，并用相同正文的出现次数区分重复块。不使用文档修订号、更新时间、全局块序号。
- 这是内容寻址语义：修改块正文表现为旧块退出、新块进入；不承诺同一逻辑段落编辑后仍保持相同 ID。只有纯文本时，无法区分多个完全相同段落的编辑身份。
- `fingerprint` 覆盖文档标题、所在标题上下文和块正文。文档其他段落变化不影响该块；标题或所属标题变化可能使相关块需重新分析，这是有意义的上下文变化。
- `order` 是当前排列位置，`anchor` 包含块 ID 和所在标题。它们不等同于编辑器持久节点或 Yjs 相对位置；定位由来源解析，不能假定原生编辑器已经支持精确跳转。
- 当前输入是可读文本投影，规范化换行和段落外空白，不是编辑器原始状态或原始文件字节。

该实现不改变现有编辑器数据、`knowledge_chunks` ID 或搜索索引布局。若以后采用原生稳定节点身份，必须另行明确对应格式、版本、历史引用和迁移处理。

## Meilisearch 已有行为与本次优化

现有主文档索引按整篇资源 ID 存储，`content_hash` 为标题和正文的 SHA-256。对账先完整读取远端 `id,content_hash` 清单，再比对本地来源，差异通过已有投影任务修复；文件记录拥有独立投影生命周期，不被文档对账当作孤立记录删除。

本次只优化当前协议的执行效率：

1. 本地每页一次批量读取已索引的 ID/指纹，并批量处理相同项和缺失项，替代逐文档查询与写入。
2. 写索引前的远端指纹核对改为最多 8 个并发请求；只提交变化项，保持输入顺序。
3. 一个核对批次失败时等待该批次请求结束并整体报错，不把故障当成索引内容消失，也不写入部分核对结果。
4. 指纹全部相同时不提交索引任务；仍等待 Meilisearch 的异步写任务成功。

已有无有效 `content_hash` 的远端记录会被视为差异并修复；该行为是已有对账语义，本轮未新增或改变旧格式读取规则。

## 共用范围

内容块提供方可以同时服务未来的块级搜索索引与知识库/插件分析，统一块边界、引用和指纹生成。但用户可见内容枚举和全站搜索索引对账的权限范围不同：不能把某个用户看不到的条目，直接当成全站索引需要删除的条目。来源/配置/授权范围必须明确隔离；查询结果始终复查当前权限。

本次不把现有整篇文档索引转换为块索引，也不替换已有序号型知识块 ID。这样的切换会影响持久索引身份、搜索结果聚合、引用和回退，需要另行确认方案。当前优化可直接回退代码，不需要数据库回滚、数据删除或索引重建。

验证使用隔离数据库及模拟 Meilisearch：`tests/content-blocks.test.ts`、`tests/content-block-inventory.test.ts`、`tests/meilisearch-fingerprints.test.ts`、`tests/search-reconciliation.test.ts`。清单联调覆盖未变化时零正文读取、单段变化只读取该块、旧指纹冲突，以及删除块仅在完整遍历后退出。

`tests/content-subscription-builtin.test.ts` 进一步使用真实内置文档来源和 SQLite 知识库整理流程，验证首次逐块分析、再次整理零新增正文读取/AI 调用，以及单块修改仅重读和重分析该块；来源回调不被数据库事务持锁阻塞。
