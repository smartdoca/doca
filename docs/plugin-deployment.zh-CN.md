# 插件安装与部署

[English](plugin-deployment.md)

管理员通过「管理 → 插件商店」浏览官方插件、上传本地 ZIP、安装、升级、启用、禁用和卸载。操作先保存为全站期望配置，每个实例重启后生效。页面分别显示全站目标版本与响应当前请求的实例运行版本，不代表全站所有实例均已更新。

```dotenv
DOCA_PLUGIN_STORE_URL=https://store.smartdoca.cc
DOCA_PLUGINS_DIR=/data/plugins
DOCA_PLUGINS_DATA_DIR=/data/plugin-data
```

商店地址必须是 HTTPS origin，不带路径、查询参数或凭据。目前默认商店尚未部署；连接失败不影响本地上传和已有插件。插件安装目录留空时使用 `${DOCA_DATA_DIR:-./data}/plugins`。业务数据根目录留空时使用 `${DOCA_DATA_DIR:-./data}/plugin-data`。相对路径基于工作目录。Docker 配置使用容器内路径，仓库 Compose 默认存放在 `/data` 卷中。

仓库的 Docker Compose 部署，在部署目录执行：

```sh
docker compose restart doca
```

多实例需逐个重启；其他部署使用对应进程管理器。页面不执行重启。滚动重启期间若插件 API 新旧版本不兼容，应摘除流量或使用会话亲和，不承诺跨版本零停机。

## 多实例分发

所有实例连接同一个宿主数据库，分布式部署使用 PostgreSQL。数据库保存全站期望清单及完整、不可变的插件归档，包括本地上传包。每个实例使用独立可写缓存目录：

```text
/data/plugins/
  .releases/<sha256>/       已校验插件文件
  .staging/                解压暂存
  .imports/                已导入的手动安装目录
/data/plugin-data/<plugin-id>/   该插件的业务库、凭证和任务
```

启动时对照数据库归档逐文件校验，缺失或损坏就自动补齐，然后加载插件。禁用插件也会同步。无需访问官方商店、安装依赖或编译源码。共享归档缺失或损坏时明确拒绝启动。宿主数据库是安装分发的事实来源，应备份；插件业务数据库与凭据单独备份。

不要让多个运行中的实例共享同一个插件缓存目录。在一个实例安装后，其他实例重启会自动获取，不需要手工复制。历史版本的浏览器资源也可以按需从共享归档补齐，以适应负载均衡路由。

手动目录安装：先停机，将完整发行目录放到 `<DOCA_PLUGINS_DIR>/<plugin-id>/`。启动时会打包并发布到全站清单，再将原目录移入 `.imports/`，避免重复安装。日常推荐管理员上传 ZIP。没有根目录 npm 依赖清单或旧源码加载兼容逻辑。

## 升级、卸载与故障

已安装插件的代码版本升级要求 `doca.dataVersion` 相同，插件初始化时仍须检查自己的实际数据库结构。没有数据库迁移。卸载先调用插件必须实现的 uninstall，由插件删除自己的业务数据库；成功后清除结构标识，之后可以安装另一种结构。调用失败则保持已安装。宿主文件服务中的附件仍保留，直到单独清理。旧缓存和归档为仍在运行的实例保留，首版不做自动归档回收。

所有写操作检查清单修订号，避免多个管理员互相覆盖；操作记录进入安全审计。取消待应用变更会以响应实例的启动配置更新全站目标，并不会立即回滚其他实例。

插件初始化失败时拒绝启动，不静默跳过权限或约束插件。可通过其他健康实例修正安装；首版没有单独修复模式、热卸载或全站完成状态面板。没有原生移动端动态代码安装。

ZIP 必须包含完整依赖，不能依赖 pnpm 软链接树。包大小、路径、SDK、插件依赖、前后端版本和哈希均校验。业务数据不得写入代码包内。协议、打包命令及远端商店交接见 [插件商店协议](plugin-store-protocol.md)。
