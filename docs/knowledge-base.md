# 知识库

一个知识库是一个方向的完整体系。体系就是库里的文档树：每个节点是一个位置，节点正文是放在这个位置的知识。文件、邮件和链接留在原地，通过订阅对上节点。

## 结构说明

结构说明、虚拟连线和确认加入都在知识库侧栏的「知识体系」页，不写成库里的文档。启用之后，所有者和管理者在这一页修改结构说明。来源先记成等待确认的连线，确认加入之后才写入文档树里的节点。助手整理时只按这篇说明放节点。

文首的「拆分：」是整库默认。某一节可以再写自己的「拆分：」。标题就是层级：二级标题是一节，它下面的标题是这一节的子节点。

拆分写成下面几种：

- 按来源：一个文件、一封邮件或一条链接各成一个节点。文件夹或邮箱作为上一层。
- 按知识内容：按说明里的标题归类。多份来源可以写入同一个节点。
- 按目录：说明里的标题就是目录。来源只填进点名的那一节。
- 按其它规则：写在「拆分：」后面，例如「按客户」。助手按这句话归类，不把每个文件或每封邮件自动拆成一篇。

还没有结构说明时，订阅先按来源展开。建立说明之后，文首若不是「按来源」，文件夹和整只邮箱只保留上一层节点，里面的文件和邮件记在这个节点上，等助手按说明归类。

## 来源

订阅挂在知识库上。一行是一个来源：种类、站内编号或站外地址、对上的节点、写入时的版本、状态。状态有正常、来源已更新、来源已经不在。

来源可以是：

- 一篇文档、一个文件、一条链接。
- 一个文件夹。按来源时，文件夹是父节点，里面的文件（含子文件夹，有上限）各成一个子节点。
- 一封邮件。点名的那一封单独成篇，不受邮箱「不加入 / 星标加入 / 完全加入」的限制。
- 一整只邮箱。只收该邮箱当前档位允许的邮件。不加入时，邮箱节点还在，里面没有邮件。

公司可以把交易凭证文件夹和客户往来邮箱收进同一个知识库，方便大家按这套体系查找。原文件和原邮件不搬动，知识库也不回写它们。

来源变了，节点标成可更新。确认之后才改节点正文。来源删除后，节点留着，链接标成来源已经不在。

## 谁能整理整库

整库订阅、按说明归类、改写节点和定时扫描，由所有者和管理者来做。读者、评论者和编辑可以阅读自己能看的节点，也可以改单篇，不能对整库做补充。只看得到一部分材料的人触发整库补充，会把没看见的部分当成缺口。

这类知识库标成 AI 归类。从中搜到的结果同样标上。

## 知识库之间

一个知识库可以订阅维护者在另一个知识库里能读的一篇。内容写到自己的节点上，并记下对方的库、文章和版本。对方更新后，自己的节点变成可更新。之后如果读不到那篇文章，就停止刷新，已写入的节点保留，来源标成已经不在。

## 助手

整理的人是现有的 AI 助手，沿用同一套技能和工具。触发可以是定时扫描、订阅变化，或人在库里说「补充」「按新内容改一版」。助手起草，所有者和管理者确认后才写入。

## 问答

几个知识库可以合成一个问答。检索用这些库里已经写好的节点。问答的使用权限和文档、知识库成员分开：提问的人可以没有库的权限；有界面权限时，回答能检索这些库的内容，但打不开文档树。

接入有三种，范围相同：Doca 里的问答界面、专用于这个问答的 MCP 凭证、对外 API。发布、改绑和停用由所含知识库的所有者或管理者来做。
