# 知识库

> 2026-09-25 更新：本文记录旧版交互与设计，其中旧版流程不代表当前实现。独立问答与整理已完成首批实现，具体状态见新规范第 12 节。新的目标规范以 [知识体系设计](knowledge-system-design.md) 为准，整库改为一份版本化 `KNOWLEDGE.md`，每条来源可附 `SOURCE.md`，问答机器人独立且可绑定多库。完整配置清单、权限边界、迁移和当前实现差距见新规范；输入模板见 [配置示例](knowledge-base-examples.md)。下文“说明不作为文件”“库内问答”等旧设计不再作为后续实现依据。

新设计还明确：知识库保存独立总结与提炼事实，问答不依赖来源内容或当前来源权限。来源消失不降低已入库知识的可回答性，下次整理提示缺源，确认保留后无新证据不重复提醒；人工原创、AI 提炼与人工修订分别记录。下文只保留链接、不保存知识正文的旧模式不满足这一目标。

整库 MD、其引用的专项 MD 和来源 MD 构成本库整理专用 skill。归类、订单去重、统计口径、权重、冲突处理等领域规则写在这些指引中，由 AI 结合通用工具执行；系统不内置订单专用规则。结构化运行配置只负责连接、调度、权限和安全执行等通用约束。

一个知识库是一个方向的完整体系。体系就是库里的文档树：每个节点是一个位置，节点正文是放在这个位置的知识。文件、邮件和链接留在原地，通过订阅对上节点。

## 结构说明

结构说明、虚拟连线、确认加入和触发都在知识库侧栏的「知识关系」页，不写成库里的文档。页首是总开关。打开之后，下面分成结构、预设、数据源、触发四个页。所有者和管理者在这里修改结构说明。来源先记成等待确认的连线，确认加入之后才写入文档树里的节点。助手整理时只按这篇说明放节点。

整库和每一条来源都可以设预设：权重、频率、是否把来源正文复制进节点，以及一份说明。说明写在这个页面上，不放进文档树。生成按结构说明和来源种类填好表单，可以手改，保存之后才生效。整库的频率就是扫描节奏。来源可以沿用整库。不复制正文时，节点只记下位置，正文留在来源。

数据源页直接绑定插件注册的来源：文档、文件、文件夹、邮件、邮箱、链接，以及之后插件用 `selection` 声明的选择方式。定时可以关、每天或每周。人工触发会立刻核对这些连线的状态，不改写节点。来源已更新的节点仍要确认后才改。

问答放在知识关系下面的侧栏入口。提问检索的是本库已经确认的节点。本页问答可用。专用于这个机器人的 MCP 凭证和对外 API 还没有签发。

文首的「拆分：」是整库默认。某一节可以再写自己的「拆分：」。标题就是层级：二级标题是一节，它下面的标题是这一节的子节点。

拆分写成下面几种：

- 按来源：一个文件、一封邮件或一条链接各成一个节点。文件夹或邮箱作为上一层。
- 按知识内容：按说明里的标题归类。多份来源可以写入同一个节点。
- 按目录：说明里的标题就是目录。来源只填进点名的那一节。
- 按其它规则：写在「拆分：」后面，例如「按客户」。助手按这句话归类，不把每个文件或每封邮件自动拆成一篇。

还没有结构说明时，订阅先按来源展开。建立说明之后，文首若不是「按来源」，文件夹和整只邮箱只保留上一层节点，里面的文件和邮件记在这个节点上，等助手按说明归类。

## 来源

订阅挂在知识库上。一行是一个来源：种类、站内编号或站外地址、对上的节点、写入时的版本、状态。状态有正常、来源已更新、来源已经不在。

来源可以是：

- 一篇文档、一个文件、一条链接。
- 一个文件夹。按来源时，文件夹是父节点，里面的文件（含子文件夹，有上限）各成一个子节点。
- 一封邮件。点名的那一封单独成篇，不受邮箱「不加入 / 星标加入 / 完全加入」的限制。
- 一整只邮箱。只收该邮箱当前档位允许的邮件。不加入时，邮箱节点还在，里面没有邮件。

公司可以把交易凭证文件夹和客户往来邮箱收进同一个知识库，方便大家按这套体系查找。原文件和原邮件不搬动，知识库也不回写它们。

来源变了，节点标成可更新。确认之后才改节点正文。来源删除后，节点留着，链接标成来源已经不在。

## 谁能整理整库

整库订阅、按说明归类、改写节点和定时扫描，由所有者和管理者来做。读者、评论者和编辑可以阅读自己能看的节点，也可以改单篇，不能对整库做补充。只看得到一部分材料的人触发整库补充，会把没看见的部分当成缺口。

这类知识库标成 AI 归类。从中搜到的结果同样标上。

## 知识库之间

一个知识库可以订阅维护者在另一个知识库里能读的一篇。内容写到自己的节点上，并记下对方的库、文章和版本。对方更新后，自己的节点变成可更新。之后如果读不到那篇文章，就停止刷新，已写入的节点保留，来源标成已经不在。

## 助手

整理的人是现有的 AI 助手，沿用同一套技能和工具。触发可以是知识关系页上的定时扫描、人工触发，或订阅变化。助手起草，所有者和管理者确认后才写入。

## 问答

几个知识库可以合成一个问答。检索用这些库里已经写好的节点。问答的使用权限和文档、知识库成员分开：提问的人可以没有库的权限；有界面权限时，回答能检索这些库的内容，但打不开文档树。

接入有三种，范围相同：Doca 里的问答界面、专用于这个问答的 MCP 凭证、对外 API。发布、改绑和停用由所含知识库的所有者或管理者来做。
