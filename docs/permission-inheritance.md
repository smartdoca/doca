## 2026-09-19 统一授权模型记录

当前实现已将主动授权、链接授权和父权限覆盖/阻断统一保存在 `grants` 表；`share_links` 只保存公共链接定义，撤销记录单独保存在 `share_link_revocations`。数据库基线不创建 `share_members` 和 `member_exclusions`。

授权表按“文档 + 用户 + 授权来源”保存多条记录：主动授权最多一条，父权限覆盖/阻断最多一条，链接分享按分享 ID 多条。每条记录保存角色、是否包含子文档、来源 ID 和 active/disabled 状态。`share_links` 仍只保存链接定义，撤销记录单独保存一次撤销事件及本次用户 ID 列表，不作为用户黑名单。

权限管理页按用户聚合所有来源，展示计算后的有效权限；详情页展示并操作每一条来源。删除主动授权时保留或生成 disabled 的父权限覆盖记录，防止权限回退；取消该记录后才恢复父文档继承。链接撤销只删除对应分享 ID 的授权记录，因此用户可以通过新链接重新获得权限。

角色和“包含子文档”是两个权限维度，计算具体子文档时必须按文档层级重新判断，不能分别取字段最大值后拼接出不存在的权限组合。

## 协作者与范围

知识库是唯一的文档权限树根，文档优先取父文档，没有父文档时取所属知识库。个人文档没有父文档和知识库归属，始终使用独立权限；新建知识库子文档开启继承。

对一个用户，从当前节点向上寻找最近的明确决定：本节点授权覆盖上级授权（可以降权），本节点取消权限阻断该用户的上级授权。没有本节点决定才继续继承。取消记录保存在 `member_exclusions`，不会因再次开启继承而消失；重新授权会清除取消记录。当前资源所有者不可修改，祖先所有者仅能通过正常继承取得管理权限。

`include_descendants` 决定授权能否向所有后代传播。当前节点的仅本节点授权也会截断更上层的该用户授权；后代可以通过自己的授权重新获取权限。继承关闭时保留本节点授权和取消记录，上级的所有影响停止。

公开权限独立计算，与协作者权限取最高值。因此移除协作者不代表将用户加入公开资源的黑名单。匿名用户的公开权限最多为阅读。

## 作品设置

`permission_overrides` 按字段记录本节点覆盖：公开范围、公开角色、允许申请、公共发现、阅读者历史版本、链接分享总开关。未覆盖字段从上级逐字段解析；本地修改后独立生效，恢复上级设置时清除覆盖并恢复该字段的独立默认值。

关闭继承不会把父设置复制下来：本节点覆盖保留，其余字段使用本节点原本的独立默认设置。重新开启继承后继续继承未覆盖字段。

具体分享链接、邀请和工单不被复制或继承。链接总开关可以继承。用户兑换链接时记录角色及范围快照；修改、停用或过期仅改变后续加入行为。已加入者在成员管理中调整。

## 审批与通知

权限申请角色不可变。审批可选择实际角色与范围，默认申请角色及包含子文档；管理权限申请仍只由资源所有者审批，只有所有者能授予管理权限。

工单调用受限的 `resource.grant` 资源操作，重查当前资源、处理人和申请人权限，在同一事务中完成授权、记录结果和工单状态。若申请人当前权限高于选定权限则返回冲突，不通过旧工单降权。数据库事务和状态校验保证只有一个处理结果生效。

`access_requests`、`tickets` 与 `ticket_events` 的 `operation_json` 保存实际执行角色和范围。详情、处理记录和通知展示实际授权；处理人员隐私规则继续独立生效。旧历史工单没有执行快照时不推测当时实际授权。

## 查询与即时生效

点查与列表 SQL 使用相同的最近决定、授权范围及字段覆盖规则。不会为继承批量复制授权。权限变更时，仅检查当前在线房间的祖先链并刷新相关页面；读权限撤销立即关闭连接，写入仍逐次检查权限。

迁移 `029_permission_inheritance` 给既有授权默认包含后代，并保留已有知识库子文档的历史、发现和链接开关本地设置；新建知识库子文档逐字段继承。个人文档不参与继承。

## 验证

隔离测试覆盖多层继承、降权、取消、未来子文档、授权范围、关闭/恢复继承、逐字段覆盖、公开基线、链接快照、邀请接受、可变审批结果、动态管理员与 WebSocket 子文档撤权。浏览器以独立内存数据库验收卡片设置、成员降权/范围及实际授权工单。
