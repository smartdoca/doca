## 0.1.24 启动自动升级

部署前停止全部旧宿主并备份 SQL、私有存储和配置。0.1.24 对已发布 0.1.22 的 `doca-2026-10-09-history-storage-v1` 自动以最新 DDL 对比整个结构；检查通过后，在 schema 锁事务中对齐声明的新增结构并记录目标代际。全部业务行及发布指针原样保留，包括旧 SQL 成果、运行及人工待办；已有 0.1.23 对象存储数据保持完整，无需手工知识册命令。不新增单独清理、自动正文转换或旧正文运行时适配。残留旧成果可能需要人工处理后才能使用相应知识册。

结构或代际写入失败整体回滚，重复／并发启动保留每条记录。未知、更早或转换中断代际不改数据并停止；其他未知表仍需审查。备份恢复时保留全部数据及后续写入，所有宿主和 Web 构建一起更新。

下方既有维护命令保留为需将旧成果继续保留为可用原生格式时的可选无损方案，须在首次启动前执行，因为结构对齐会改变转换所需的源代际。下方历史验收证明可选无损转换，不代表自动适配残留旧 SQL JSON。

自动结构对齐验收：实际 0.1.22 镜像的 SQLite、PostgreSQL 17/18 隔离样本均保留 114 张业务表的每一行及 20 份 SQL 正文，重复／并发启动后新原生对象可读。PostgreSQL 17/18 各通过 91 项回归，包括事务回滚和原生读取器拒绝旧正文。见[验证记录](verification/book-schema-startup-2026-10-13/verification.json)。

## 执行步骤

使用包含本次改动的新宿主代码及原部署环境。已发布 `smartdoca/doca:0.1.22` 是转换来源版本，未包含新命令。保留原主密钥、存储 ID、后端配置与对象；停止全部宿主后备份数据库（SQLite 包括 WAL）、私有存储和配置。所有实例和 Web 构建一起更新。

命令读取现有数据库，不创建新库。默认执行完整预检，不写入数据库或上传对象；`--apply` 和 `--hosts-stopped` 才开始。恢复清单必须是新的路径，权限为 0600，清单保存原 footprint、记录身份、长度与哈希，不镜像正文。

```sh
pnpm knowledge-books:storage upgrade
pnpm knowledge-books:storage upgrade --apply --hosts-stopped --manifest /secure/book-upgrade.json
```

只接受 `doca-2026-10-09-history-storage-v1`。更早代际先完成其准确支持的历史升级。发现运行中知识册任务、未知正文格式、损坏内容或待审结构差异时停止；需要先处理具体原因，不能强制清库、取消未知任务或填补旧字段。

中断后，普通宿主拒绝转换中代际。使用同一清单路径重新执行原命令继续，已转换正文仍须与清单一致；不能换一份清单来忽略变化。完成后普通启动只接受 `doca-2026-10-12-book-payload-storage-v1`。上线后重启会扫描仍待处理的通知，已结束任务不补发；历史输出与错误保留。

当前回退在修改前拒绝非空的 `knowledge_book_batch_checkpoints`：这些引用须另行确认保全与恢复方案。不能删除检查点或绕过代际、结构检查，见[检查点保留与恢复](knowledge-book-generation-performance.zh-CN.md)。下列历史往返验收早于批次检查点，不证明任意当前库均可降级到 0.1.22。

符合条件的回退前再次停掉所有宿主，保留新备份和新的回退清单。回退预检读取全部对象并验证原始字节；应用回退恢复升级后的新写入，云对象及回退清单保留，不恢复旧备份来丢弃后续成果。

```sh
pnpm knowledge-books:storage rollback
pnpm knowledge-books:storage rollback --apply --hosts-stopped --manifest /secure/book-rollback.json
```

中断回退使用同一回退清单继续。还原全部 JSON 并复验后，仅撤销四张存储元数据表，恢复旧代际和已检查的 footprint。目标是升级前 0.1.22 宿主；要继续回退文档历史存储，必须先完成此知识册回退。SQLite 释放页不自动缩小文件，不自动 VACUUM。

## 隔离验收

实际来源镜像 `smartdoca/doca:0.1.22`，镜像 ID `sha256:a5316eb01bf25b0d89801139de85d34a35528be376699c4981ab8a09fd14f04c`。使用合成用户和来源，由旧版真实运行器生成成功、失败和待发布任务；未访问用户文档或生产数据库。

SQLite、PostgreSQL 17 和 18 各有 20 份非空旧正文。全部执行显式升级、两次普通启动及显式回退；20/20 原始 JSON 字节与哈希一致，状态、错误、配置与人工待办保留。结果记录于仓库 `docs/verification/knowledge-book-storage-plan-2026-10-12/actual-roundtrip*.json`。

| 新 SQL 引用字节 | 7,170 | 7,170 |

元数据数字是对象、引用、操作及依赖边的 JSON 序列化大小，不等于数据库页、索引、WAL 或备份大小。文本重复度很高，不能用该压缩比例承诺生产节省率；真实数据库物理文件需单独测量。

回归覆盖分片边界、转义与 Unicode、同册去重/跨册隔离、并发竞争、租约中断与续转、损坏对象、未知格式无部分 DDL、新写入完整回退、SQL 摘要零对象读取、权限撤销及缓存、回收站与永久删除、迟到上传的持续清理。CI 的数据库矩阵加入知识册与正文存储测试。

浏览器验证记录于 `lazy-candidate.json`：展开前读取 0 次、展开后 1 次、再展开复用缓存，权限撤销移除正文，无浏览器异常。流程图稳定性另见 `docs/verification/knowledge-book-reliability-2026-10-12/preview-result.json`。

## 运维边界

复用宿主私有 local/S3 存储配置；未新增公开下载地址或模块凭据。必须将数据库与对象存储作为一致的备份集合保留。对象缺失或校验失败时读取明确失败；保留成果引用，不返回空正文来掩盖损坏。

清理只删除不可达对象。回收站保留引用，永久删除释放引用；活跃上传依赖受保护，失败和迟到上传保留持久化键以便重试。操作记录不存正文，完成后只保留竞争产生的多余上传键，已安装依赖由对象与边表记录。没有新增历史 TTL。

最终检查：SQLite 相关全套 126 项通过；补充接口及最终权限检查的知识册/存储 60 项通过。PostgreSQL 17/18 各 68 项相关全套通过，最终存储接口套件各 11 项通过。类型检查、Web 构建、文档链接及差异空白检查通过。完整记录为 `docs/verification/knowledge-book-storage-plan-2026-10-12/verification.json`。心跳与对象清理使用独立调度，云请求不会占用心跳扫描。
