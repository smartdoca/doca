# 历史快照分层存储与抽稀

2026-10-09 用户确认：旧快照每 10 个只保留 1 个到文件存储，目标是长期回滚；用户仅看到统一的快照列表，不显示存储位置。最近 20 个仍保留在数据库。本实现替代此前“十个全部打包”的提案。

## 保存与读取

- `document_versions` 保存近期完整快照。超过 20 个的旧快照每凑满 10 个，选择这一组最新的 1 个作为长期保留点。未满一组时暂留数据库，所以正常可以暂留 20–29 个；存储失败时更多。
- 保留点是单个 gzip 压缩 JSON 文件，不打包其余 9 个。文件原样保存 checkpoint、recovery_json、格式/codec/epoch/baseline、附件依赖、作者、标题、时间和版本 ID；原 CRDT 身份不变。
- 使用环境变量配置的文件存储。S3 配置时写入云存储；本地配置时写入私有本地目录。对象位于 `host/document-history/<resourceId>/<versionId>/<sha256>.json.gz`，不会公开或返回给浏览器。
- `document_version_archives` 每个保留点只记录一条小索引。历史接口合并近期表和归档索引，保持相同的分页、字段、权限与版本 ID；前端不显示存储类型。点击某个快照时，服务端自动读取相应存储。
- 抽稀掉的 9 个旧快照不再出现在列表，也不能再回滚。数据库回退命令只能导回保留点，不能还原抽稀掉的快照；需要完整历史时依赖抽稀前的数据库备份。

## 成功条件与故障处理

1. 在数据库事务内选择候选组、计算完整记录摘要并登记转存任务和清理引用。
2. 事务外写入不可变文件，读回核对长度和 SHA-256。断网、写入失败、过大文件或校验失败时保留整组数据库原件。
3. 再次进入事务，确认候选十条的内容、顺序、资源状态和任务身份未变，然后同时登记归档索引并移除十条完整数据库记录。其中一条已在文件存储，其余九条按已确认的抽稀规则淘汰。
4. 稳定任务、不可变对象 key 和数据库唯一约束支持进程中断、重试与多实例重叠。任务使用共享持久队列，故障会保留错误信息并退避重试，不阻塞正文提交。
5. 在线协作 checkpoint、未覆盖增量和附件不参与抽稀。进入回收站保留归档；永久删除文档时才登记文件回收，等待一小时并复核无有效索引或转存任务后清理。副本持有独立文档 ID；不按共享附件对象 key 删除字节。

原图/附件的独立权限与删除规则保持现状。归档保存附件依赖，抽稀不删除附件；历史文件不是被用户删除的附件字节的额外备份。

## 数据格式与升级

新数据库基线为 `doca-2026-10-09-history-storage-v1`。正常启动只接受新基线；没有自动升级、旧数据库读取器或协议适配器。

只允许显式升级上一基线 `doca-2026-10-08-knowledge-books-v2`：增加归档索引、转存操作与文件清理表，更新基线，并排队处理已超出阈值的历史。升级事务本身不抽稀，不改写任何旧快照或附件。其他基线或不完整结构拒绝升级，原数据保留。

现有 RecoveryMetadata v1 保持原样。缺失恢复信息的记录仍保存原字节，预览继续拒绝；未知恢复版本也不自动转换。文件的 envelope 只接受准确版本 1，未知版本、摘要不符、超限解压或索引不匹配均拒绝读取。

停止所有 Doca 实例，完整备份数据库、文件存储和存储配置，然后在部署环境运行：

```sh
pnpm history:upgrade                 # 显示执行要求，不修改数据
pnpm history:upgrade --apply         # 显式事务升级
# 启动新宿主后，后台开始每十个旧快照保留一个。
```

不创建新数据库，不删除旧数据库；SQLite 维护连接要求目标文件已存在。

## 宿主回退

停止所有实例，再提供一个新的清单文件路径：

```sh
pnpm history:rollback --apply --manifest /backup/history-cloud-references.json
```

先用权限为 0600 的清单保留文件引用，再逐条验证并把保留点导回数据库，最后移除新表并恢复上一基线。文件存储中的字节继续保留。大规模导回可以分批提交；开始时标记 `history-rollback-in-progress-v1`，普通宿主拒绝在中途状态启动，防止部分导回的保留点被再次抽稀。中断后修复存储问题，用新清单路径重跑同一回退命令完成导回，再启动上一宿主。

这一显式基线回退与用户在历史列表中的“恢复快照”是不同操作。列表中的富文本和 Markdown 恢复仍产生当前 epoch 内的新提交，先保存回滚前版本并检查 expectedSeq；表格、画布和幻灯片仍仅提供历史预览，不宣称新增这些组件的回滚 API。
