# 邮箱宿主交付范围与进度

2026-09-30：采用用户确认的统一内容来源标准。原先新增独立插件订阅、正文记录和任务三张表的方案已撤回。

## 确认的方案

复用现有知识库订阅与任务机制。来源全量分页返回当前允许读取的块清单与指纹；完整遍历后比对，只读取和分析变化块。无需独立增量日志游标，不保存额外完整邮件正文，不增加旧协议适配或数据库兼容操作。数据库结构未修改。

公开标准为 content.v1，必需 list/read/resolve，可选 search。内置来源和业务插件遵循同一标准，详见 [通用内容来源](plugin-content.md)。

## App 边界

`PluginWebHost.native` 在原生插件容器内提供 storage 和 attachments，Web 环境为 null。详见 [App 公共能力](plugin-native.md)。插件需要调用该接口，已有 IndexedDB 不会自动变成原生持久缓存。

邮箱绑定仅在 Web 提供。App 不接 OAuth，不承诺完全离线冷启动，不做跨设备偏好同步。

## 后续验收

知识库需覆盖完整遍历、内容变化、失败重试、重启、来源注销、当前读取者权限与衍生结果撤销。邮箱需验证九种搜索/知识库范围组合及范围缩小、解绑、禁用。搜索和 AI 必须使用同一当前身份，草稿变更重新审批，发送保持插件持久幂等。App 需真机验证重启缓存、退出清理、换账号、系统保存取消与分享行为。

宿主本地验证：相关 13 文件 88 项测试通过；新增知识消费与权限用例复测通过，覆盖失败不推进指纹、当前读取者隔离、移动文档不解除来源约束，以及真实 SQLite 内置来源不锁死。SDK、Web 构建及 App 类型检查通过。全仓类型检查仍有既有 AI runner、评论选择、编辑规范化和知识库测试 mock 错误；本次新增代码未报告类型错误。
