# 文件存储与历史保留

## 文件对象

所有新上传入口（文件管理、文档附件、头像/封面、评论图、随手记附件、AI 附件及生成图片）使用相同的路径规则和物理对象登记服务。`file_storage_objects` 管理存储位置、实际 MIME、分类、字节数及 SHA-256；`assets` 和 `file_items` 保留各自业务用途、名称、归属和权限。文件复制/引用不依靠移动磁盘目录实现。

普通文件上传在当前存储配置内按 SHA-256、大小、实际 MIME 查找可复用对象，事务内再次检查避免并发重复登记；头像/附件等资产入口仍创建独立对象，不承诺所有入口全局去重。权限通过业务引用检查，不能直接凭物理对象 ID 下载。

```text
objects/<image|video|audio|document|archive|other>/<ID前2位>/<ID第3、4位>/<对象ID>/original
derived/<同样的分类和分片>/<源对象ID>/<处理版本>/<结果文件名>
temporary/<上传会话ID>/upload
```

PDF、Office、文本归为 document。大小是独立处理条件，不进入对象路径；用户、时间和显示文件名保存在数据库。路径只能由服务端生成，存储适配器验证分类、UUID、分片和结果文件名。本地和 S3 使用同样的规则，不接受旧的 `objects/<UUID>` 路径，不提供旧数据迁移。

二进制内容由 `file-type` 检测；无可识别签名时检查 UTF-8 样本，文本扩展名仅用于细分文本 MIME。未知二进制归入 other。类型识别不等于格式完整性或安全审核，实际处理器还需校验输入。HTML、SVG、XML 等主动内容下载强制附件和 octet-stream，并设置 nosniff/sandbox。

普通文件和图片附件保存原始上传字节。头像、封面和评论图片继续执行现有尺寸限制和 WebP 规范化。AI 生成图片保存已有规范化输出。

## 上传与读取

策略常量集中在 `apps/server/src/services/storage-policy.ts`：

| 规则 | 当前值 |
| --- | --- |
| 文件管理单次上传上限 | 2 GiB，仍受账号单附件和存储额度限制 |
| 资产上传上限 | 20 MiB |
| 头像/封面/评论图输入上限 | 5 MiB |
| S3 流式上传切换分片的阈值 | 32 MiB |
| S3 分片大小 | 8 MiB，末片可更小 |
| 图片缩略图处理输入上限 | 20 MiB、2500 万像素 |

文件管理接口直接接收请求流，流式暂存并计算哈希、校验大小和检测类型；身份和目标权限检查后才接收文件。写入存储完成后，在数据库事务中重新校验目标和额度，登记物理对象、业务引用及处理任务。失败清理未提交对象和临时文件。被中断的请求也清理临时文件；进程崩溃遗留且 24 小时未写入的临时文件由后台定期清理。

本地通过流读写；S3 大文件按部件发送并在完成后提交，失败尝试撤销未完成上传。生产 S3 桶还应配置未完成分片的生命周期清理，以处理进程被强杀等情况。**当前分片发生在服务端到 S3 的链路，尚未实现浏览器直传、跨请求断点续传。**

文件管理与资产下载均鉴权后流式返回，支持单个 Range、206/416 和 HEAD。下载不将整个视频读入内存。供 AI/图片处理使用的缓冲读取默认限制为 20 MiB，不让大文件进入只适合小文件的处理链路。

## 衍生文件与后台任务

`registerStoredObject` 在业务事务内向已有的 `projection_jobs` 写入 `file-thumbnail` 任务，复用租约、重试及错误记录。后台每次最多处理两项，关闭服务时等待正在执行的任务。

当前处理器生成不放大的 480×480 范围 WebP 缩略图，处理版本为 `thumbnail-v1`，原文件不被覆盖。`file_derivatives` 按源对象、用途和处理版本唯一登记。重复任务复用结果；租约重叠时以数据库登记获胜者为准，清理未被选中的输出。

- 文件管理：`GET /api/v1/files/items/:id/content?variant=thumbnail`
- 资产：`GET /api/v1/assets/:id/content?variant=thumbnail`

两者沿用原业务对象的权限；资产缩略图也执行原资产审核检查。尚未生成时返回 404，不把原文件伪装成缩略图。文件详情提供分类、衍生结果和缩略图处理状态。后续视频封面、转码、音频分析、文档预览可增加独立处理器及处理版本；当前没有自动视频转码。

删除历史快照或业务引用不直接删除物理文件。将来增加原文件垃圾回收时，必须同时检查 assets、file_items、仍保留的历史依赖及其他引用；不能按用户目录或上传日期批量删除。

## 在线文档历史

历史仍保存在数据库，协同检查点和增量不迁移到文件存储。`history.versions` 改为每篇滚动保留的数量：正数 N 保留刚保存的快照及其余最新 N−1 条；null 无上限；0 不保留新历史。插入与淘汰在同一个事务，失败不会丢失此前的历史。手动、自动、AI、恢复相关快照共用规则；额度降低在下一次记录历史时收敛。详细约束见 `collaboration-sdk-contract.md`。

验证使用隔离数据库和临时存储目录；S3 通过 SDK 模拟验证命令、分片完成/撤销和流生命周期，真实云端配置需另行部署验证。
