# 插件架构下的 AI 交付与消耗优化

## 本次实现

- 技能目录按稳定 ID 排序，同一技能集合不因安装/查询顺序改变模型前缀。工具注册表已有稳定排序，无需重复处理。
- 宿主按本轮请求和引用文档格式，自动将对应已启用文档 skill 的完整手册放入当前请求，不加入系统前缀或持久上下文快照。新建或读取文档确认其他实际格式时，通过 `editingSkill.instructions` 回执补载，每次执行同一手册只补载一次；手动 `load_skill` 也计入已加载集合。未识别的手册仍须编辑前 `load_skill`。不按猜测的用户意图裁掉可用工具。
- 富文本工具显式列出位置、表格和文字范围字段，并说明各命令的字段归属。当前 SDK 将数组类型错误附带的数量上限误报为字符串字符数时，模型回执明确要求对象数组和最多 80 条操作；输入仍按原校验拒绝，原始错误留在执行记录中。
- 上下文超限时，同时处理数组 content 与 content.parts 历史形态，且不修改持久消息。
- 旧工具回执压缩保留审批、分页、文件和调用标识。超长错误和保留字段也受长度限制，避免错误内容绕过压缩。最新回执优先保留原文。
- 保留逐项交付验收、完整读取证据、有限修订和真实保存回执检查，不为省 token 跳过验收。

这些属于确定性修复，不代表已测得线上缓存命中率或任务成功率提升。字符/字节上限仍是输入预算的近似值，不是 provider tokenizer。

## 后续优先级与验收方式

1. **插件交付契约**：公共 ai.v1 目前只有工具与技能注册。底层 ai-host 有验收器，但尚未通过公共 SDK 开放。下一步应定义版本化的结果/验收贡献接口，包含工具 ID、callId、资源引用、审批/完成/失败状态以及恢复方式。插件负责业务验收，宿主负责权限与执行状态。不能将普通工具执行成功直接算为用户任务交付成功。
2. **恢复摘要**：当前折叠整段历史主要提取文档状态，尚不能保证保留任意插件任务的业务状态。需要从持久执行账本生成按调用/资源分组的恢复摘要，保留成功副作用、待审批项和未完成项；避免重复执行。超长标识被截断后只能作为线索，不得直接用于执行；需要按原 callId 读取完整回执的受权接口。
3. **工具目录增长**：插件数量变多后，引入稳定的小型能力索引和按需发现工具协议，按任务固定已加载工具集。发现接口仍复核插件状态与权限，不能用关键词过滤永久隐藏工具；需验证动态工具加载与当前执行框架的兼容性。
4. **调用与任务观测**：沿用宿主原始用量账本，并由模型配置把输入、输出和图片张数统一折算为 Token；核心不处理币种、售价、会员或额度。补齐任务结局与验收轮次、失败阶段、插件/版本、模型和实际 provider 尝试的关联。未报告的 token 为 null，失败和取消产生的实际消耗也要统计。

## 对比指标

在隔离数据库/文档上，固定任务集、模型配置、插件版本和权限；覆盖纯问答、检索、多步插件操作、审批、部分失败恢复及长上下文。不对用户真实文档运行编辑评测。

- 首轮交付率与最终交付率分别统计；等待审批/补充输入、取消、执行失败和验收失败单独列出，不并入成功。
- 缓存读取 token / provider 语义下可比较的输入 token；缓存写入独立报告，未知量不当成零。按 provider 分组，避免包含关系不同导致失真。
- 每个成功交付任务的总输入/输出 token、调用次数、验收消耗，以及 P50/P95 耗时。包含失败尝试和修订消耗；同时报告全任务总成本，防止遗漏失败任务。
- 相同输入的冷启动与重复请求分别比较；前缀相同仅代表具备缓存条件，最终命中以 provider usage 为准。

上线门槛应由基线数据确定：token 降低不能以权限回归、重复副作用、遗漏要求或交付率下降换取。
