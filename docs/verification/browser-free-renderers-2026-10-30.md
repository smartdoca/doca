# 无浏览器渲染器改造验收

验收日期：2026-10-30（Asia/Shanghai）。本记录保留发布前工作区改造及本机候选镜像的验收结果；正式 0.2.27 双架构发布见[发行验收](release-0.2.27.md)。`smartdoca/doca:0.2.26-renderer-candidate` 为 ARM64 候选；AMD64 候选使用同名加 `-amd64` 后缀。在 ARM64 主机的 Docker Desktop 中完成两种 Linux 架构检查，AMD64 属于模拟执行。

## 实现与已同意边界

富文本/Markdown PDF 导出改为固定 WeasyPrint 70.0 的独立 Python 进程；画板继续使用官方 Canvas 0.5.16 的 SVG 导出，经隔离 Node DOM、原生 Canvas 文字测量和 resvg 转为 PNG。这是宿主适配，没有假定编辑器包提供 Node 导出 API，没有升级或修改编辑器包。

PDF.js 的读取、逐页文字/图片与可编辑导入，以及 LibreOffice 的 DOCX/XLSX/PPTX 视觉转换保持各自路径。新运行镜像不包含 Chromium/Playwright，不需要 seccomp 配套文件或额外浏览器共享内存。旧 `DOCA_PDF_CHROMIUM` 明确拒绝，不回退旧渲染器。现有 SDK 历史读取规则保持原路径；没有数据库、文档格式、checkpoint、epoch、附件、权限或主密钥转换。回滚恢复原代码、依赖锁、镜像和部署配置，并保留后续写入的数据。

导出仍限制输入、并发和执行时间，渲染后再次检查权限。Python 仅读取内嵌 data 资源；网络、宿主文件、嵌套 SVG 外部资源和损坏图片均拒绝。取消/超时终止独立进程。Node 只接收宿主已授权素材，沿用 SDK 的场景、选区、裁剪和告警。

## 镜像与交付

新包额外生成独立 YAML 与校验文件，管理员脚本已放入镜像；原宿主脚本入口仍能使用。单文件示例用于全新 SQLite/本地存储站点，已有站点必须保留项目名、卷及原密钥。填写来源和自生成主密钥后保护 YAML 权限。正式发布前需要使用本地候选标签；已发布的 `0.2.26` 镜像尚未包含本次改造，不能直接套用新配置。

构建默认使用官方 Debian/npm/PyPI 源。本机直连下载反复超时，验收构建使用 Dockerfile 的镜像源参数和已有 Node 22 Bookworm 基础镜像，固定 Python/npm 依赖版本未改变。镜像体积按实际 OCI gzip 压缩层总和统计，与已发布 0.2.26 同架构镜像比较；这是整体镜像对比，不能把全部差额归因于单个二进制。

| 架构 | 已发布 0.2.26 压缩层字节 | 候选压缩层字节 |
| --- | ---: | ---: |
| ARM64 | 705,706,643 | 511,783,373 |
| AMD64 | 708,898,836 | 519,903,637 |

ARM64 减少 193,923,270 字节，约 27.48%；AMD64 减少 188,995,199 字节，约 26.66%。首次拉取量与本地解压/多架构占用应分开看待。

## 复核入口与范围

可复跑 `scripts/qa-document-pdf.mts`、`scripts/qa-release-render-image.mjs`、`scripts/qa-release-browser-image.mjs`、`scripts/qa-release-runtime-audit.mjs` 和 `scripts/qa-renderer-compose.mjs`。后者使用 `scripts/pack-deployment.mjs` 的单文件产物，且只清理自身随机项目的卷。浏览器验收可用 `DOCA_QA_BROWSER` 指定开发浏览器；运行时不依赖它。

原始日志、截图、PDF、重导入结果、体积统计和单文件示例位于忽略目录 `artifacts/verification/chromium-alternatives/`。数据均为隔离合成样例，没有使用用户文档、生产数据库或真实模型调用。视觉验收覆盖上述样例，不表示任意复杂 CSS/SVG/Office 文件均像素一致；已有 PDF 可编辑导入的复杂布局近似规则继续适用。没有验证真实 AMD64 硬件或所有 PDF 阅读器，也未执行需要额外 PostgreSQL/Redis 环境的跳过用例。
