# 收录暂存名额自动回收验收

日期：2026-10-26。宿主 0.2.22，扩展 0.2.10；编辑器依赖保持正式 npm `@smartdoca/slate 0.4.26`。

## 生产故障证据

原站点升级至 0.2.21 后，Annual Reviews 页面仍收录失败。扩展 0.2.9 的诊断提示在真实 Chrome 浮动工具条上显示未完成任务达到上限，对应 `clipper_too_many_pending`；请求在正文转换前即被拒绝。此前失败的暂存任务占满了既有十个名额，通用重试文案隐藏了原因。

## 已同意的处理规则

用户明确同意自动回收，并要求每次新收录没有名额时执行。每次新请求在账号锁和事务内检查上限，只回收所需数量的最旧暂存任务：至少三十分钟没有上传或重试活动，且连接没有排队、运行或等待审批的浏览器 AI 任务。上传开始、上传心跳和重试更新活动时间。全部任务均活跃时保留上限，无效新请求不会改变旧任务。

只将旧任务标记为既有 `expired` 状态，保留冻结原文、图片和原定二十四小时到期时间，直到原期限清理。已保存文档不动。无图过期任务也会清理原文。扩展遇到过期任务后，保留原账号、保存位置、选区和图片，使用冻结材料自动重建并重试一次。

收录协议 v1、授权 v2、表列和持久化 JSON 形状不变，无历史数据转换。旧扩展仍可重新收录。回退保留所有数据，并保留到期清理修复，或待已回收任务到期并完成清理后再回退该修复。

## 本地验证

- 全量回归：328 个测试文件通过，3 个跳过；3,429 项通过，11 项跳过。覆盖连续满额新建、并发请求、账号隔离、无效请求不回收、活动上传与心跳、三种活跃 AI 状态保护、原始到期清理及已保存文档保留。
- 扩展覆盖仅重建一次、保持冻结选区与账号、AI 附件材料恢复，以及不覆盖较新的收录、不重试配额和授权错误。逻辑相关四个文件共 160 项通过。最终提示文案调整后，39 项 UI / 内容脚本测试再次通过。
- 类型检查、生产构建、正式编辑器来源检查及 97 页双语文档检查通过。容器验收脚本新增真实 API 名额回收及保存检查，将在发布时分别运行于 amd64、arm64 原生镜像。

运行输出、截图和隔离测试数据均保存在忽略目录 `artifacts/verification/annualreviews-production-2026-10-26/`。本文记录生产故障定位和本地验证；生产服务器仍需升级至 0.2.22、重新加载扩展 0.2.10 后，继续实际网页收录验收，不能将隔离测试结果当作原站点已通过。
