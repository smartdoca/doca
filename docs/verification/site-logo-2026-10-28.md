# System Logo — 2026-10-28

The owner selected `settings` for the system Logo. The implementation adds nullable `settings.site_logo` through current DDL and the existing `schemaEvolution` allowlist. Historical and fresh NULL mean default branding. The compatibility generation is unchanged, and the earlier `account_settings` proposal was not implemented.

Administrators upload PNG/JPEG/WebP through Site & services → Site information. The server bounds input to 5 MB and 16 megapixels, rejects unsupported/animated or invalid images, strips source metadata and normalizes to PNG within 256×256. Strict version-1 JSON is stored directly in the settings field. Unknown versions, extra fields, malformed JSON and corrupt images are preserved and rejected, including attempted API reset. A revision-checked settings update and security audit commit together. Public responses serve validated PNG bytes with an ETag and revalidation; raw stored JSON is not returned by bootstrap/admin settings.

Branding updates navigation, sign-in and non-document favicons. Existing document/title favicons take precedence on document pages. The existing persisted document-startup record retains its format and field list; Logo state comes from the live bootstrap only. Saving Logo does not remount and discard an unsaved site-name form. Server and Web update together. Old binaries' existing structural inspection rejects the new field; preserve later data for separately reviewed recovery, without dropping columns or resetting databases.
