# 产品与架构：重新设计基线

状态：产品目标基线，部分已实现。实际实现边界见 [云端架构](architecture.md)。从零构建，不迁就旧版实现，不预留多空间或组织模型。

## 1. 范围

目标是个人直接使用、小团队通过知识库和文档邀请完成协作。产品以主页文档列表和知识库为主要内容入口；“与我共享”是查询视图，不是新的资源容器。

明确不做：空间、根应用/子应用、团队组织树、组织级资产治理、多租户开通、跨服务联邦，以及跨设备内容自动合并。此前的空间收费方案不再作为当前模型的输入。

本文中的服务实例指一次后端部署；本地资料库标识仅供备份识别来源，不是业务空间，也不承载成员、权限或计费。

## 2. 文档与知识库

### 个人文档

用户无需创建个人空间或个人根文档。未归入知识库的文档直接归个人所有，个人文档之间没有父子关系，主页以列表形式展示。

基础字段：独立随机 ID、所有者、可空的知识库 ID、可空的父文档 ID、文档类型、权限模式、版本、创建/更新时间和删除状态。个人文档权限完全独立，不从其他文档继承。

个人文档可由所有者转移给当前协作者，也可转移到其有管理权限的知识库根或文档节点；知识库文档可由作者转回个人。知识库内部继续使用文档树和权限继承。

### 知识库

用户按需创建知识库，例如学习笔记、项目资料、公司手册。知识库有所有者、名称、协作者和权限规则；内部使用文档树。

仅创建者使用时就是私人知识库，邀请别人后仍是同一知识库，不发生个人/团队类型转换。

## 3. 权限规则（建议基线）

访问范围与操作角色分离：

- 仅受邀者：默认设置，无其他邀请时即私有。
- 本站登录用户：当前后端服务中的所有登录账号；不能将它误称为“同事可见”。
- 公开阅读：匿名用户也可以阅读，不默认开放匿名编辑。

角色分为阅读者、评论者、编辑者、管理者；所有者独立记录。默认开放范围只提供阅读权限，更高权限明确授予个人。

所有者可转移所有权、添加管理者；管理者可管理日常授权，但不能转移所有权。转移时明确指定原所有者是否保留权限。

知识库内文档默认继承权限，允许改为独立权限。本轮采用知识库所有者始终保留库内管理权的基线；独立权限可限制普通成员，但不排除知识库所有者，界面已明确提示。

单独分享库内文档，不自动公开知识库目录、其他文档标题、附件或搜索结果。隐藏文档也不能从 AI 检索或通知中泄露。

系统管理员负责账号、登录与运行设置，不默认成为所有文档协作者；掌握部署主机/数据库的运维人员仍有基础设施层面的访问能力，不承诺对其加密隔离。

## 4. 账号和 SSO

本地桌面首次使用自动建立本地身份，不要求官方账号。连接远端后，远端登录身份独立管理，不将本地用户 ID 当作远端身份凭据。

服务端支持本地账号、注册开关、用户启停及恢复流程。外部 OIDC 接入与本系统作为 OIDC 身份提供方是两个独立模块，按需启用；不附带部门、组织树或组织同步。

身份关联使用明确的外部身份标识，不能仅因为两个账号邮箱相同就自动合并。SSO 认证成功不自动获得他人文档权限。

## 5. 多端和服务结构

- 共用前端：文档管理、编辑器接入、协作者、评论、通知、搜索和 AI。
- 共用后端：账号、内容、权限、协同、附件和事件。
- 运行适配：桌面和 DSH 启动/连接本地后端、管理数据目录与远端连接凭据。

首版采用模块化单体，不引入微服务。文档/表格/演示编辑能力由相应 npm 包接入；协同内容通道与元数据 HTTP 接口分离。

同一客户端可以访问本地和多个远端，但各服务中的普通可编辑文档彼此独立。跨服务复制不产生后续同步关系。

## 6. 资源复制

普通复制：无论本地到远端还是远端到本地，都生成新文档/知识库 ID，归目标端当前用户所有，默认私有；不继承原分享链接或协作者权限。子树和附件关系需重新映射。

普通复制默认包含内容、标题、结构和必要附件，不复制点赞、收藏、原操作审计或历史身份。后续是否支持选带评论/历史版本，另行设计。


## 7. 后续开发顺序

1. 账号、文档/知识库模型、权限和管理界面。
2. 编辑器接入、协同、附件、回收站及内容导出。
3. 桌面/DSH 本地运行、远端连接、独立资源复制。
4. 搜索、AI 工具、评论通知与 Hook 集成；沿用能力需求，不沿用旧源码。

权限、数据持久化和数据库恢复测试是基础验收项。对外 SSO 协议实现需单独验证，不因使用轻量产品模型而简化安全要求。
