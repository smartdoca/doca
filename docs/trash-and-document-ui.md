# 文档交互与回收站验收（2026-09-11）

- 文档引用区改为「本文引用 / 引用本文」标签，保留权限过滤、数量、空状态及键盘切换。
- 短文档空白点击失效的原因是宿主给 `.sk-editable` 设置了过大最小高度，并拦截点击后只移动光标。现在最小高度只交给 `.sk-page`，正文随内容自然增长；由编辑器原生空白点击处理补行、空行复用与聚焦。没有修改包内的协同逻辑。
- 补充边界修复：`.editor-content → .sk-editor → .sk-page-shell → .sk-page` 以纵向 flex 连续撑满正文网格高度，移除外层底部 padding 和引用区顶外边距。评论栏较高时正文不再垂直居中留下不可点击空白。编辑器页底与引用区分界线重合，窄屏规则同样不保留外部底部间距；补行仍由 SDK 原生处理，引用/点赞/评论组件不进入该点击范围。
- 编辑器 `onChange` 对外工具栏刷新按帧合并，大纲回调去重，`onReady` 保持稳定，避免 DOM 选区同步时重复触发宿主渲染。
- 「与我共享」只返回已接受的直接文档授权；不显示未处理邀请、整库继承权限或仅通过链接获得的权限。待处理事项在待办处理。旧 `sharedDocuments` 配置不再控制该列表，管理页已移除旧选项。
- 文档位置列用蓝色个人文档图标 / 绿色知识库图标；日期显示刚刚、分钟前、小时前、今天、昨天或完整日期，悬停可看精确时间。
- 统一待办、通知和用户菜单中回收站图标的对齐。

## 回收站接口与边界

`GET /api/v1/resources/:id/trash-preview`：需要登录、文件仍在回收站且具有管理权限。富文本返回独立只读投影；表格返回原始基线与合并的原始 Yjs 状态，预览不加入房间、不提交保存。知识库返回有管理权限的已删除子文档列表。预览不会创建空的服务端文档状态。

`GET /api/v1/assets/:id/content?trashPreview=1`：附件同样要求对所属已删除文档有管理权限；普通阅读授权不够。正常附件访问仍拒绝已删除文档，预览响应不缓存。

`POST /api/v1/trash/purge`，请求 `{ targets: [{ id, version }] }`：确认框冻结完整目标清单，不受列表类型筛选影响。后端在同一事务核对每个目标的管理权限、删除状态、版本及子树完整性；任一项不满足即全部回滚。恢复或新删除的文件不会混入确认范围。当前单次上限 1000 项；超出会明确提示，不会静默清空一部分。

永久删除正文、版本、评论、权限和相关资源关系；历史审计事件保留并解除资源外键，产生 `resource.purged` 集成事件。撤销所属附件记录的访问，不直接删除物理对象，因为副本可能共享存储对象；物理文件回收需要独立 GC，当前未新增 GC 服务。

## 验证

自动化覆盖：富文本/表格预览、预览不改状态、越权与未登录访问、附件权限、完整子树删除、已恢复/过期版本/重复 ID 的原子拒绝、副本附件保留、已接受分享过滤、日期边界。

独立内存库浏览器验收：短文档及长文档点击底部补行、空末行复用、选区刷新无 React 错误、引用标签切换、图标中心对齐、文档及表格回收站预览、临时文档清空。未在真实用户文档上执行清空。

边界补充验收：在引用分界线上方最后 2px 点击，分别验证短文档、长文档、1700px 高评论栏、1100px/600px 窄屏。页底与分界线误差小于 1px；空末行复用、另一编辑页接收新增段落、引用标签点击不补行、匿名只读不补行均通过。
