# 界面语言

本文是源文件。子包通过 `skills/doca-i18n` 读取同一约定；该 skill 也可安装为 `$doca-i18n`。修改本文时同步更新 skill 的 `references/contract.md`，以及每一份已安装的副本。

第一版支持中文和英文。以后增加语言时，只加语言代码和对应字典，不改 key，也不改调用方式。

界面文案用英文 key。中文、英文和其他语言都是这个 key 的译文。不要用中文句子或整句英文做 key。

## 语言代码

| 代码 | 含义 | `html lang` |
| --- | --- | --- |
| `zh` | 中文 | `zh-CN` |
| `en` | English | `en` |

允许的代码定义在 `packages/i18n` 的 `locales`。未知值回退到英文。站点信息可配置默认语言，初始值为中文，不跟浏览器语言走。访客和未设置 `ui.locale` 的用户使用站点默认语言，用户已保存的语言选择优先。

已登录用户的选择存在页面状态 `ui.locale`。浏览器同时记在 `localStorage` 的 `doca.locale`，移动端记在本机。助手可以通过现有的 `page_state` 修改 `ui.locale`。

## 宿主字典

字典在 `packages/i18n`。英文目录 `en` 是 key 的来源，其他语言必须正好覆盖同一组 key。

```ts
t("account.expires", { date })
// en: Expires {date}
// zh: 到期时间：{date}
```

约定：

- key 用小写英文和点号，按界面区域分组，例如 `nav.trash`、`settings.language`。
- 占位符写成 `{name}`。不要把句子拆开再拼接。
- 需要单复数时，字典写 `files.count.one` 和 `files.count.other`，调用仍是 `t("files.count", { count })`。英文按 `count === 1` 选 `one`，其余选 `other`。中文可以让两份文案相同。
- 找不到译文时先用英文，再退回 key 本身。
- 语言的自称不翻译：`locale.zh` 永远是「中文」，`locale.en` 永远是「English」。
- 日期和排序使用当前语言的 `Intl` 区域，中文用 `zh-CN`。
- 文档标题、正文、评论、邮件、文件名、用户输入不翻译。

网页通过 `useI18n()` 取 `locale`、`t` 和 `setLocale`。Ant Design 与 Ant Design X 的组件语言跟着这个 `locale` 走。

服务端用户可见错误目前仍是中文句子。新的校验错误使用稳定代码，例如 `invalid_locale`，由界面翻译。已有接口错误不在这一版改完。

## 持久化系统状态

数据库、任务检查点、事件流和接口响应中的系统状态只保存稳定的英文代码与结构化参数，不保存任何语言的展示句子。网页和移动端收到代码后，使用当前界面的字典生成标题、说明和阶段名称。

```ts
// 存储和传输
{ code: "folder_available", data: { name: "Research" } }

// 展示
t("ai.progress.event.folderAvailable", { name: event.data.name })
```

阶段、事件、审批，以及作为状态字段保存的错误原因都遵守这条规则。状态判断只能比较代码，例如 `phase === "completed"`，不能比较 `t(...)` 的结果或中文、英文展示文案。用户输入、模型回答、文档标题、文件名和网页来源仍保存原文，不把自然内容改写成代码。

## 给子包的要求

编辑器子包自己保存自己的界面文案，不要引用 Doca 的字典，也不要读取 Doca 的页面状态。

宿主会传入：

```tsx
<RichTextEditor locale={locale} />
```

`locale` 是字符串，当前只有 `zh` 和 `en`。以后可能出现其他代码。子包不认识的代码按 `en` 显示。

子包需要做到：

1. 组件 props 增加可选的 `locale?: string`。缺省时按 `zh` 显示，和现在的中文界面一致。
2. 字典 key 使用稳定的英文标识，例如 `toolbar.bold`、`find.replaceAll`。不要用中文，也不要用会随文案修改的整句英文。
3. 至少提供 `en` 和 `zh` 两份目录，key 集合相同。新增语言时加一份目录即可。
4. 占位符使用 `{name}`。需要数量区分时提供 `key.one` 和 `key.other`，由 `count` 选择。
5. 切换 `locale` 只更新子包自己的按钮、菜单、占位符和提示。不要因此重建文档、Y.Doc、协同适配器或插件列表。
6. 可以额外接受 `messages?: Record<string, string>`，用来覆盖个别文案。没有这份 prop 也可以。覆盖项只替换对应 key，其余仍用子包内置译文。
7. 用户写进文档的文字、公式、单元格内容不翻译。

宿主在安装包的类型声明包含 `locale` 之后，在对应编辑器的挂载处传入当前 `locale`。不要把 `locale` 放进会重建文档、Y.Doc、协同适配器或插件列表的依赖里。

## 增加一种语言

1. 在 `locales` 里加入代码，并补上 `html lang`。
2. 增加一份与英文 key 完全相同的宿主目录。
3. 补上该语言在界面上的自称，例如 `locale.ja`。
4. 网页补上 Ant Design 对应的 locale 对象。
5. 每个编辑器子包增加同一语言的目录。
6. `ui.locale` 会自动接受新代码，因为校验读的是同一份 `locales`。
