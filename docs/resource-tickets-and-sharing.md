# 分享卡片与资源工单

分享卡片先展示当前用户和实际权限。低于管理权限、且资源允许申请时，显示申请按钮；点击后选择更高权限并填写选填说明。编辑者可查看协作者，管理者可调整协作者。公开和申请设置收进右上角“作品公开”；邀请和链接分享沿用原有规则。公开权限仍为阅读、评论、编辑，匿名用户最多阅读。

“相关工单”使用新标签页链接：`#/tickets?resourceKind=document&resourceId=<uuid>`。列表支持工单类型、多个状态、待我处理、资源类型与资源 ID 筛选，筛选条件保存在 URL 中。

## 新建文档默认权限

独立新文档默认私有且允许申请访问，链接分享开关打开，公共发现和阅读者查看历史版本关闭。开关开启不自动生成分享链接。各编辑格式、导入入口使用相同创建流程；复制文档重置为这些默认值，不沿用源文档的公共发现或阅读者历史设置。

系统管理员仍可覆盖新建文档的默认访问范围。知识库与子文档保留已有权限继承规则，已有文档不随默认值调整而改变。

## 授权与节点

工单记录 `resource_kind`、`resource_id`、申请/受邀人和发起人。申请人、邀请发起人以及当前对资源有访问权限的用户可以查看。查看工单不授予审批权限。普通工单不会因为用户是系统管理员而向其开放。

审批节点按当前资源权限解析，不持久化审批人名单：

- 权限申请：当前资源管理者可审批；申请管理权限仅资源所有者可审批。
- 协作邀请：受邀人接受或拒绝；所有者可撤销任意邀请，管理者只能撤销自己发出的普通权限邀请。
- 撤权后不再凭历史参与者身份获得查看或审批权；保留的申请人/邀请发起人身份只用于查看自己的历史与允许的操作。

管理员信息仅在可见性策略允许时查询和返回；隐藏规则仅屏蔽该申请/受邀人。保留创建时的隐私限制，后续关闭可见性也能隐藏已存在工单。通知接收人按变化时的审批规则计算，通知不作为访问凭据。

## 注册审核

注册审核独立存储在 `registration_reviews`，仅管理员后台“注册审核”处理，不创建普通工单、不发放注册工单会话。注册或登录遇到待审核账号时返回 `{status:"pending"}`，前端提示等待审核后重新登录。

- `GET /api/v1/admin/registration-reviews?status=pending&offset=0`：分页查询审核记录。
- `POST /api/v1/admin/registration-reviews/:userId`：`{decision:"approved"|"rejected", message?:string}`。
- 待审核用户不能通过普通用户状态接口绕过审核页面。审核以条件更新保证只能处理一次，记录审核人、备注与安全审计。

注册审核直接使用 `registration_reviews`；资源工单使用 `tickets`、`ticket_events` 及其当前字段，不创建旧参与者表或注册工单会话表。
