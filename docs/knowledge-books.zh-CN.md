# 知识册

[English](knowledge-books.md)

知识册是编排生成的只读 Markdown 文档树。可编辑的文档、知识库、文件、文件夹、网页和经过授权的 `content.v1` 插件内容是它的来源。多人共同维护来源、流程和验收规则；个人 AI 助手使用与页面相同的命令和权限，不再提供第二个共享机器人，也不共享个人会话或记忆。

## 多人共建

打开「知识册」创建项目，通过「权限管理」邀请协作者。权限面板和角色逻辑与个人文档一致：读者查看，评论者提交反馈，编辑者维护配置和自己的来源授权，管理员还可以管理权限、移除其他贡献者的来源。只有贡献者可以更改自己来源的范围。配置、来源和反馈都使用版本校验，多人同时保存会返回冲突，不覆盖他人的修改。

知识册复用知识库资源承载权限。普通文档创建、移动、复制接口不能向其中写入内容；标题、权限、回收站等生命周期仍由宿主管理。生成页面属于不可修改的成果版本，不作为协同编辑文档保存。

## 配置与运行

1. 设置目标、模型、第一层知识类型和最大目录深度。
2. 添加来源。短列表以卡片展示；逐个校验来源及其子内容的原权限。知识册管理员身份不授予来源访问权。
3. 调整 X6 流程图。拖动节点排版，通过连线或节点面板选择输入，修改规则、来源范围、权重和验收项。保存时校验输入类型、环路、标识、可达性以及唯一发布节点。
4. 定义验收标准。所有配置的验收项必须得到评估，必需项必须通过才能发布。
5. 发起持久化运行，查看节点结果并处理人工待办。排队不等于已生成成果。

节点包括来源读取、人工反馈读取、事实提取、汇总决策、文档树组织、验收、人工审阅和发布。运行冻结配置及输入版本；普通运行拒绝配置或来源变更。失败后显式继续当前流水线时仍使用它的固定配置，即使后续运行的设置已修改；来源及反馈必须保持一致。发布前再次校验来源内容。不支持的格式、过大输入、提取未完成、伪造引用、模型输出截断都会明确失败，不默默发布不完整成果。

知识册卡片为编辑者提供重命名，为拥有者提供删除。删除复用资源回收站及恢复流程，配置、来源和成果保留。从知识册打开的助手携带本册作为当前资源，泛化的知识库意图不覆盖当前知识册。

定时整理按 UTC 的每日或每周周期执行。自动发布是显式配置；关闭时，验收通过后生成发布待办。运行失败保留上一个已发布版本，并产生异常处理待办。

## 来源组与网络来源

「运行流水线」以左侧列表、右侧画布铺满子页面，列表独立滚动，列出状态、触发人或定时任务、开始时间和持续时间。点击立即切换选中项，已有缓存先展示，再读取最新授权数据；过期请求不能覆盖新选择。画布使用精简接口，不加载完整节点正文和密集溯源。轮询只更新变化的节点，保留当前视角；离开页签或浏览器隐藏时停止轮询。窄屏打开失败流水线时先定位失败节点。选择一次运行查看其冻结流程；直接点击节点，在右侧抽屉查看对应日志、错误与人工待办。点击抽屉遮罩或画布空白关闭节点详情。日志记录实际的来源、分批、模型请求/输出字符数和重试，未记录的历史日志不补造。执行中持续刷新，等待审核时间计入总持续时间。

AI 助手启动或重试运行后保留原任务等待后台执行；后台完成或人工决定唤醒同一任务，恢复前复验当前权限。助手可以说明待审批事项并继续等待，不会因为收到通知就代替用户审批。其他安装插件可使用同一[公开唤醒服务](plugin-ai-continuations.zh-CN.md)。

独立的 5 秒补偿巡检在模型请求执行期间继续运行，回收 15 秒心跳已失联 5 分钟的工作进程，唤醒已经登记等待的助手，并发送执行失败、人工审核、待发布的站内通知。待处理人工任务作为持久化通知来源，按任务 ID、revision 和接收人去重，支持重启补发及多实例并发。通知记录中的原运行发起人（仍有编辑权限时）和当前知识册管理者，读者不接收；通知列表和未读数复验编辑权限，可见导航铃铛显示未读数字，已读后同步更新；点击进入对应待办。目前是站内通知，未接入邮件或设备推送。

此次通知扩展已获得同意，复用当前 notifications 表和数据库代际，不增加表列或执行迁移。历史流水线、错误、待办和通知不改写；启动补发仍待处理的任务，不补发已解决、已取消的任务。现有严格来源格式及数据库代际拒绝规则不变。宿主和 Web 构建需要一起部署；回退时保留新通知记录，旧界面可能无法正确显示其类型。断点仍以已完成节点为单位，不把单个模型请求的部分批次保存为独立检查点。模型返回后以及节点失败/完成写入时复验工作租约，防止旧模型响应迟到后覆盖恢复流水线的已完成节点。

一个来源卡片可以绑定多个文档、知识库、文件、文件夹、外部链接或插件配置，也可混合绑定。配置只接受 `{version: 1, items: [...]}`，每项有稳定的 `id`。每组最多 50 项，禁止重复和嵌套；旧单项配置明确拒绝，不转换历史数据。组贡献者必须有每项的原资源权限。

网页选择器支持批量链接和网络搜索。搜索使用系统配置的 SearXNG 等搜索服务，可限制站点。正文校验、有效来源保存和流程中的来源读取统一使用 AI 设置绑定的网页读取服务（内置、Firecrawl、Jina 或 Tavily）。带章节片段的链接通过所选服务返回的 HTML 验证并截取准确范围；Firecrawl 和 Jina 支持此方式，Tavily 需使用整页链接或改选支持 HTML 的读取服务。服务失败会明确报告，不自动切换到其他服务。结果卡片供选择，摘要不是证据。加入链接前验证实际正文、所选片段和内容大小，保存有效来源时服务端再次抓取。任何链接失败都不会部分保存。暂停来源保留配置，重新启用需验证。私网来源地址、携带凭据的 URL、缺失片段和不可读页面拒绝使用；向外部服务提交来源链接前仍由宿主校验公开地址。

通用 `content.v1` 提供方同时可用于原知识库订阅和知识册，没有另外一套知识册专用插件注册接口。组中可以多次选择同一提供方的不同配置。绑定或贡献者失权时阻止新读取；成果展示仍检查具体证据引用。

编排画布左侧按来源与人工输入、AI 知识整理、审阅与发布分组展示已有节点类型。点击加入节点后配置规则、连接输入。卡片显示节点类型、规则摘要及来源／验收范围；点阵画布支持曲线连线、平移、缩放、适应画布和展开。拖动或修改规则保持当前视角，展开后可按 Escape 收起。画布工具按钮左对齐，节点面板可单独收起，顶部工具栏也可隐藏；画布保留恢复按钮。发布节点保持唯一，保存仍验证完整流程。

流程设置直接点击画布中的节点修改；下方不再重复显示节点编辑卡片。左侧节点面板的图标、名称和说明统一左对齐。修改后点击「保存」。

## 人工介入

所有人工审阅节点、发布审批和失败节点都进入「人工待办」，同时支持跨知识册和知识册内查询。按类型、状态过滤，查看候选正文与验收结果，然后通过、退回或继续执行。处理动作使用版本校验，避免重复审批；输入已变化的待办不能批准旧结果。异常待办通过 `resume` 继续当前固定流程；独立的 `retry` 接口仍按当前配置创建新运行。内容重做后，下游人工审批重新进入待办并增加任务版本。同一待办再次处理时，原有决定、处理人、意见和时间保留在宿主安全审计中。

通用验收项只定义一次，各验收节点通过 `criterionIds` 复用；领域特有范围保留在节点规则。验收以运行冻结配置中的描述及明确的例外为准，`grounded` 等 ID 没有内置的“只能使用 Manual”含义。明确允许准确行业常识时，不能仅因来源没提到就拒绝；要求来源支持时仍须检查证据，允许常识也不代表允许技术矛盾或算术错误。修改当前配置后，`resume` 仍使用旧运行的冻结规则，应用新规则需要新建重试。

多个节点使用同一个必需验收项时，每个节点仍独立评审，任何未通过项默认阻止发布。对有完整候选正文、完整验收结论且因必需项失败而停止的验收节点，人工待办提供“接受已知问题并继续”。必须填写接受哪些已知问题，再确认当前候选；技术失败、缺少正文或缺少有效验收结果不提供此操作。失败 checks 和节点失败状态原样保留，不改成模型通过；决定、操作者、意见、候选与配置哈希进入审计和成果溯源。批准后复用该候选，仍执行后续人工节点；未开启自动发布时，还要完成发布审批。单纯 `run.publish` 不绕过待办。

人工放行使用现有待办的 resolution 记录 `acceptanceOverride.version=1`，配置、流水线和成果仍为 version 1，不增加 SQL 结构、不转换旧记录。没有这个明确决定的旧 resolution 不授予放行。发布前重新检查批准者权限、来源访问、输入快照、当前及冻结配置和原候选；变化后原决定失效。宿主与 Web 应成套更新；回退时先停止新执行，旧代码仍能读取已发布的同格式成果及失败 checks，但不会识别新放行决定，不能依靠旧执行器继续尚未发布的人工放行。

「AI 操作示例」提供补充来源、合并验收项和段落纠错的请求模板，发送前由用户修改确认；「我的操作记录」列出当前用户与该知识册有关的个人会话，其他管理员的 AI 对话和记忆不会一起展示。

评论、纠错、补充和疑问是有版本的编排输入，可以手动添加，也可以要求个人 AI 助手登记。反馈可以定位到某个成果版本、文档和段落；定位受限成果需要原证据访问权限。修改反馈产生新输入版本，不直接改变成果段落。权重和采用规则由节点配置决定，高权重不能使没有证据的说法自动成为事实。

## 成果与溯源

默认使用纯阅读模式，只展示渲染后的文档；切换到「审阅」才展示段落反馈、证据数和采用依据。切换只是页面视图，不改变已发布 Markdown 或溯源。

目录标题完整换行，章节与页面层级清晰，展开图标位于标题前。点击目录会打开其下第一个文档，并展开到选中文档；箭头只控制展开或折叠。目录和正文各自滚动，来源、流程和待办列表也可独立滚动。

正文提供路径面包屑、分级小标题、本页导航和按目录顺序切换的上一篇／下一篇。宽阅读区在右侧显示导航，窄阅读区折叠在正文上方；导航随滚动高亮，可以通过键盘定位。导航来自实际 Markdown 标题，代码块中的 `#` 不作为标题；没有标题的正文不生成虚假的段落目录，原文保持不变。新运行要求汇总与文档树节点输出有意义的二、三级标题，历史成果不被改写。exmd 已发布的 `MarkdownPreviewInteraction` 接口负责渲染定位，宿主保留原图片权限解析。

新生成内容围绕实际知识详解展开：定义、组成关系、运行机制、条件、例外、权衡与有依据的示例；架构与流程使用真实 Mermaid 代码块，不能只写“图”的文字说明。学习指引只作简短引言。普通汇总每批最多处理 40 条知识判断，文档树组织按正文规模分批并保留细节。遗漏不同知识判断、长文没有小标题、组织时删光已有 Mermaid 图都会触发修复。大章节按当前每页 200 段限制分篇，不丢弃正文。这些规则只校验新输出，不改写历史成果。对结构正确但引用或正文量不足的章节，先进行一次同范围的完整补写，仍失败再拆分；结构错误和硬预算错误仍按完整单位缩小请求。仅剩一个不可再分的知识点时，最后一次有限补写可把达到估算预算 75% 的内容作为候选交给后续检查，此前仍按 90% 补写；整册字数与深度要求继续使用实际正文验收，估算预算不能充抵字数。固定章名与路径长度进入模型私有输出约束，并复验准确值。

显式目标达到两万字的长文先用来源标题和代表性判断规划简短章、节目录，再每批最多 32 条判断归属到固定节，由程序检查每条判断恰好分配一次并汇总。规划不一次返回全册判断的分配表。本批未分配的小节空占位不会丢失判断；分配的格式或覆盖失败也按完整判断继续缩小请求，直到严格满足每条恰好一次，或无法继续修复时明确失败。规划仅存在于本次执行内存，不增加配置或成果字段。撰写按节分批，每批最多 12 条判断，正文汇入固定章节；编排沿用已有章名和路径，不让每个小批次重新扩张目录。 撰写、编排和细节验收以已引用证据为锚点，在最多 160000 字符内补入同一来源的完整关联块；超限时优先保留临近原文块，不截断段落，不引入无关来源。选择的上下文同样复验来源权限。目标中的深度用于因果推导、完整场景/算例、边界反例和证据驱动的故障诊断，不以更多目录项或重复概览充抵。是否需要各类案例仍由用户配置的目标和验收条件决定。长文验收按更小的章节片段检查（最多 3000 个 Markdown 字符和 12 条关联判断，单个完整段落仍不可截断），避免协议与数值错误被大上下文掩盖；每片明确标注检查范围，在汇总中组合章级义务的实际证据。保留案例前核对协议身份、收发方向与原规范算法。验收 JSON 修复保留事实失败，并要求准确的验收项标识。标题、关键词和字数不能作为深度通过依据。版本 1 格式与已保存数据保持不变。

写作请求触及输入上下文、输出字符保护或模型 Token 上限时，按完整知识判断或段落继续拆小请求，汇总通过校验的结果；不足 40 条判断的章节也可以分多次生成。截断或结构无效的多单元 JSON 会丢弃并继续拆小请求，不反复请求同一份大输出；不可拆分的单元只做有限次修复，仍无效时明确失败。配置、流程和成果仍使用第 1 版格式，已有数据不转换。单来源组、单次响应和发布规模保护保留；节点组合来源不再受 120,000 字符的旧上限约束，模型输入按批次处理。`book_size_limit` 是共用的错误分类，不能由此推断整册总字节配额。新错误通过已有展示协议的 `data.detail` 保留具体原因，历史仅存通用代码的错误不能逆向恢复。大册存储与剩余限制见[存储评估](knowledge-book-storage-assessment.zh-CN.md)。

提取、写作、文档树组织和详细验收在单节点内最多两路独立批次并发，失败会取消并等待另一路结束。显式字数目标先分给写作分支，再分给批次。正文字符数不包含代码和图表源码；图表数按实际 Markdown 代码节点统计，不计外层代码块中的示例。新写作和编排结果在带超时限制的隔离工作线程中通过已安装的 Mermaid 解析器检查，语法错误进入有限次修复；这一步不渲染 SVG，也不改写历史发布版。组织时缩减超过 10% 的正文会被拒绝，继续拆小的请求也执行此限制。验收先将每个已配置条件拆成局部与全册义务，不把来源中的教学目标增加为验收要求。总字数、完整主题覆盖和图表类型是否存在属于全册检查，批次只检查当前呈现的断言与图表。验收按完整段落携带关联判断和证据检查，再用宿主统计、目录和有界的批次结论检查全册要求，不把全文重新交给最终模型请求。任一最终详细批次失败都会阻止对应验收项通过。验收独立判断当前候选正文，旧失败意见只交给内容修复，不进入新验收结论；每个验收项必须完整返回一次。每次模型调用，包括全册汇总，都复验相关来源权限。

助手调整节点前先读取输入类型规则。同类写作节点串联仍不允许，错误会指出具体连线。修改配置只影响后续运行；patch 节点后调用 `run.resume` 不会把新参数应用到冻结运行。需要应用新配置时，在明确要求新建重试后使用 `run.retry`。

成果复用 exmd 的只读渲染，页面包含文档树、版本选择、段落反馈、采用依据和经过校验的来源引文，不提供 Markdown 源码编辑器。

溯源图完全由实际运行结果生成，连接来源版本、证据、知识判断、采用决策、段落、文档、节点执行和成果版本，也记录人工审阅决策。它不能单独编辑。可以查看整个网络，或查看某篇文档的上游关系，点击节点检查具体依据。默认按来源合并证据、按当前查看范围合并知识判断，同类关系合为标注数量的连线；点击分组查看原始成员，也可关闭合并查看细节。只调整展示，不修改成果中保存的原始关系或证据。

来源全文保留在来源系统和运行时内存中。成果与节点日志只保留引用到的精确片段、哈希、来源定位及生成内容，不再建立额外的全文副本库。来源更新不会改写历史成果。读取成果及节点日志时检查原来源权限；外部来源删除、解绑或提供方不可用时，相关成果停止展示，保留的数据不被删除。

贡献者失去知识册编辑权限后停止抓取其来源。之前生成的数据可以保留，但保留不等于授予显示权限。任意模型上下文来源不可访问时，合并成果保守地停止展示，包含模型最终没有引用的输入。

## 人工与 AI 共用接口

路由前缀为 `/api/v1/knowledge-books`：

| 路由                                | 用途                                                   |
| ----------------------------------- | ------------------------------------------------------ |
| `GET /`、`POST /`                   | 列表、新建                                             |
| `GET /:id`                          | 配置、来源、反馈、运行及已发布成果                     |
| `POST /:id/commands`                | 人工与 AI 共用命令                                     |
| `POST /:id/source-search`           | 检查编辑权限后通过已配置服务搜索网页                   |
| `POST /:id/source-web-check`        | 验证链接正文与所选片段                                 |
| `GET /:id/runs/:runId`              | 执行与候选结果                                         |
| `GET /:id/runs/:runId/pipeline`     | 经授权的精简画布数据，不返回完整节点正文及溯源         |
| `GET /:id/releases/:releaseId`      | 不可修改的成果版本                                     |
| `GET /human-tasks`                  | 按知识册、运行、节点、关键词、类型、状态、偏移查询待办 |
| `POST /human-tasks/:taskId/resolve` | 带预期版本通过、退回、继续或新建重试                   |

命令包括 `configuration.save`、`configuration.patch`、`workflow.node.patch`、`workflow.node.add`、`source.remove`、`source.save`、`feedback.save`、`feedback.withdraw`、`run.start`、`run.cancel`、`run.resume`、`run.retry`、`run.publish`。配置、来源和反馈保存必须提供 `expectedRevision`。`packages/core/src/modules/knowledge-books/protocol.ts` 是第 1 版协议定义。AI 的 `knowledge_book` 工具调用相同业务函数，个人助手的会话和记忆仍属于真实用户。AI 读取目录清单后，通过 page 分页读取正文和证据，或用 find 定位段落；登记的反馈保留真实操作者和手动/AI 助手入口。来源节点与分析节点权重相乘，同一证据从多个来源节点到达时取最高权重，避免重复输入抬高可信度。

## 旧整理卸载与数据库边界

旧知识库整理和问答机器人已移除，不再提供整理会话、工作器、设置、指引、条目或生成普通文档的投影。文档、来源订阅、索引和搜索保留。知识库导航移除「来源与订阅」入口，已有订阅记录保留。

当前源码数据库基线为 `doca-2026-10-12-book-payload-storage-v1`。0.1.24 对已发布 0.1.22 的 `doca-2026-10-09-history-storage-v1` 启动时自动检查并对齐结构，在同一 schema 事务中记录目标代际。全部业务行及发布指针原样保留，包括旧 SQL 生成成果；运行时仅支持新版对象引用，不增加旧正文读取适配，不自动转换或单独清理。残留旧成果可能需要人工处理后才能使用相应知识册。已有 0.1.23 对象存储数据原样保留。见[运维与恢复](knowledge-book-storage-verification.zh-CN.md)。知识册目标表保留，旧知识库整理表及字段继续停用。正常启动拒绝更早、未知及转换中断的代际；仅准确的上一历史基线可按[部署步骤](deployment.zh-CN.md#从-0113-升级)显式离线升级历史存储。旧文件绑定保留且继续拒绝访问，不恢复旧整理协议；不得删除已有数据库来启动新版。

失败或取消的运行通过 `run.resume` 继续当前流水线，保留运行 ID、固定流程、已完成节点和失败日志。继续前复验来源登记、反馈、原权限及完整的实时来源清单，包括证据标识、版本和内容哈希；来源内容增删或改变时拒绝混用输入。验收未通过时，从最近的上游内容生成节点及其下游修复，保留知识抽取和无关分支，把此前验收结果作为修复依据。重复失败或后台执行中断使用原节点与待办记录，保留已记录的失败事实及处理意见。只接受当前第 1 版配置，不转换旧格式、不迁移或删除数据。

负面验收意见先复验其候选页面与当前已完成内容是否一致。编排已修复候选、随后验收遇到接口或结构错误时，旧候选的负面意见保留为历史诊断；续跑复用当前编排并重新验收，不再次用旧意见覆盖新内容。对当前候选的真实负面验收仍触发内容修复。比较使用已有 v1 页面内容，不增加存储字段或按旧错误文案猜测原因。

修复失败验收时，只有已审阅候选正文的引用范围与当前授权上游范围完全一致、重复页面标识内容一致，编排才以该候选正文为起点，使意见中的页面标识能正确定位并保留前一轮修正。带页面定位的意见交给对应批次，缺少标识时可用独特代码值定位；无法定位的意见仍检查是否适用，不静默丢弃。未受影响的候选批次经结构复验后保留原段落，不重新改写。详细验收失败意见附上当前页面标识，为每个失败批次保留摘要，避免总长度截断隐藏后续章节的错误；仍按当前证据独立核实，不将旧意见作为事实依据。前次候选正文不会整册进入模型请求；完成节点和已存第 1 版格式保持不变。

原 `run.retry` 仍是独立的新建运行操作。重试保留原运行，只有冻结配置、来源登记、反馈及完整的当前来源清单均一致时，才复用完成节点；来源不可用、增删块或内容变更均阻止复用。人工审批节点及其后续节点重新处理。每个复用节点在审计与溯源中记录原运行。每次厂商模型调用之前都复验贡献者授权，包括分批提取与格式修复。

公开只读视图只显示渲染成果和溯源，不暴露编辑配置或构造虚假的默认流程。历史成果遵循原文档历史权限。溯源可定位到文档或段落，流程执行和模型上下文关系可单独开启。

## 正文对象存储

节点输出、运行成果和发布成果使用宿主现有私有对象存储。正文字符串按同册哈希共享，原始 JSON 字节和第 1 版成果结构完整保留；相同运行/发布成果共享根清单。数据库保留严格引用、权限清单、摘要、对象依赖和上传清理日志。界面与助手轮询使用摘要；展开候选成果才读取正文。缓存命中仍复验当前来源权限。回收站保留引用，永久删除释放引用后由持久化清理回收不再使用的对象。详见[实施方案](knowledge-book-payload-storage-plan.zh-CN.md)。

分片验收按原始验收项限制局部义务：明确标为教学模拟的自选初始值无须逐字出现在规范算例中，但必须满足规范条件且计算、字段及状态变化正确。缺少整章案例或排障步骤在章级汇总判断，不要求每个片段重复整章义务；按章合并时保留具体初始状态、推导、结果和判别证据，不能只保留“深度良好”的结论。

长文细节验收列出当前完整段落中的逐项断言，模型须为每项原始标识返回结论，遗漏、重复或未知标识均触发有限修复。程序根据逐项结论生成原有第 1 版 checks，不写入新的持久化字段；总体正面评价不能覆盖具体失败。中间提取的判断若与原文冲突，正文和采纳说明必须明确纠正或排除，不能照抄错误。

每句断言只核查一次，以违反的验收项标识关联结果；没有违反项时返回空列表。各验收项的章节深度观察单独汇总，避免为每个验收项重复整套断言列表。通过断言只写简短判断，错误保留具体计算或规则冲突。已验证的 Doubao Seed 2.1 请求原生 JSON 对象输出，继续由宿主严格检查业务结构；不接受双重转义或思考文本替代对象，接口拒绝时明确报错，不静默回退。

逐项检查使用最多 24000 字符的相关规范块作为上下文；断言提示伴随完整段落，不替代或截断正文。细节失败记录具体段落和原句；能准确定位的段落优先决定修复批次，其他批次复验后保留。新模型图源语法失败时，可为单层方括号标签补上双引号，再经真实解析器检查；节点文本、连线和图类型保持原义，复杂语法错误仍由有限模型修复处理。历史成果不自动改写。

针对已确认能力的 Doubao Seed 2.1，实质抽取、撰写、编排和验收请求开启原生思考；目录规划和判断归属保持短输出。普通实质请求使用 medium 思考投入，逐项检查也使用 medium，由现有固定 SDK 映射到官方参数。参数拒绝会报错，不自动切换模型或静默降级。本次不修改提供方已有的 Responses/Chat 和可选 reasoning 摘要适配逻辑。配置中的模型、输入与输出预算以及 v1 存储协议不变。

同一次执行在有界内存中保留完整失败断言，只有候选正文哈希与证据／判断范围哈希均匹配时才用于修订。持久化仍使用原第 1 版验收摘要，保留可执行的错误原因及段落位置。正文已改后发生的技术性验收失败，续跑复用该已完成正文，不把旧失败评价重新套到它上面；来源及权限继续复验。真实模型验收脚本先独占执行再启动 HTTP 阅读服务，避免后台执行器抢占测试运行而绕过诊断观察。

有界逐项验收先保留已引证据，再按当前段落中的协议、字段和状态术语选择完整相关规范块，最后补入临近块；不引入未关联来源。每个子句、字段数量、位宽和计算结果分别核对。

数字形式的条目／字段数量子句还会作为同一完整段落中的独立原文片段接受检查，不能用正确的字节总和证明字段数量正确。这些提示仅用于执行，不增加持久化验收字段。

教学类比不能建立另一个协议的算法、状态迁移或诊断操作建议。这类建议仍须有目标协议的原始依据；同一句中正确的源协议规则不能替无依据的其他协议断言背书。

逐项检查存在失败结论时，可将同一已授权来源的范围从24000字符扩大到最多100000字符，对不变的段落独立重检一次。段落与诊断中的特有术语继续排序完整规范块；扩大范围也能补入翻译后缺少来源语言匹配词的规则。补证不依赖拒绝理由的语言、措辞或缺失关键词。配置的模型输入预算仍是硬限制。两个尝试均保留诊断记录，内容修订仅采用最终判断；证据不变则不重检，不删除必需验收项，实际计算矛盾仍须拒绝。这是补入依据后的实质复验，不是为了修复JSON格式把失败改为通过。

一次执行的总时限为四小时，使长册的细致验收和有界证据补查可以完成。单请求输入／输出保护、显式取消、十五秒租约心跳和五分钟中断恢复继续生效。续跑仍以已完成节点为检查点，不新增持久化的部分批次检查点。

第1版验收摘要超过4000字符时，最多保留24个均匀分布失败范围（含首尾）的具体错误与唯一段落定位，并明确列出省略的失败范围数量。省略项仍阻止验收通过；内存限制内的完整候选诊断继续用于同一次执行的修订。历史摘要不回写。

证据检索保留完整标识，同时匹配空格、连字符、驼峰词的组成部分及带数字的事件前缀，使常见文字写法能够找到同一规范事件；不改写原文或来源权限。

片段验收额外携带前后各两段、合计最多6000字符的完整相邻上下文，解析前文定义和后续图表，不增加被审断言；原始全证据范围继续复验权限。当前Mermaid语法由真实解析器检查，合法等价写法不能仅因形式差异被拒绝，真实语法错误则阻止对应已配置图表／格式验收项通过。语法通过不能覆盖语义失败。

厂商及传输暂时异常，包括成功HTTP响应的SDK处理失败和缺少完成标记的流，在既有三次调用上限内重试同一有界请求。丢弃未完成的流文本，重新校验来源权限，取消仍立即生效。参数拒绝、鉴权／权限失败及请求容量错误不按暂时异常重试；不切换模型、参数或响应协议。

中间验收汇总仅合并当前最多12个检查结果及其章节身份，使用明确的局部范围，不携带整册目标作为该组的通过义务。未出现的其他章节留待后续全册判断；该组已有失败或矛盾仍须保留。最终验收继续使用原始条件、完整目录、统计和全部章节汇总，不能因局部汇总通过而省略章节要求。

数量子句的检查提示保留“第”等序号前缀及其空格，避免把“第4个报文丢失”误读为“四个报文丢失”。完整原段落继续作为检查上下文；提示抽取不改写正文或历史验收记录。
