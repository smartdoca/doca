# 知识册

[English](knowledge-books.md)

知识册是编排生成的只读 Markdown 文档树。可编辑的文档、知识库、文件、文件夹、网页和经过授权的 `content.v1` 插件内容是它的来源。多人共同维护来源、流程和验收规则；个人 AI 助手使用与页面相同的命令和权限，不再提供第二个共享机器人，也不共享个人会话或记忆。

## 多人共建

打开「知识册」创建项目，通过「权限管理」邀请协作者。权限面板和角色逻辑与个人文档一致：读者查看，评论者提交反馈，编辑者维护配置和自己的来源授权，管理员还可以管理权限、移除其他贡献者的来源。只有贡献者可以更改自己来源的范围。配置、来源和反馈都使用版本校验，多人同时保存会返回冲突，不覆盖他人的修改。

知识册复用知识库资源承载权限。普通文档创建、移动、复制接口不能向其中写入内容；标题、权限、回收站等生命周期仍由宿主管理。生成页面属于不可修改的成果版本，不作为协同编辑文档保存。

## 配置与运行

1. 设置目标、模型、第一层知识类型和最大目录深度。
2. 添加来源。短列表以卡片展示；逐个校验来源及其子内容的原权限。知识册管理员身份不授予来源访问权。
3. 调整 X6 流程图。拖动节点排版，通过连线或节点面板选择输入，修改规则、来源范围、权重和验收项。保存时校验输入类型、环路、标识、可达性以及唯一发布节点。
4. 定义验收标准。所有配置的验收项必须得到评估，必需项必须通过才能发布。
5. 发起持久化运行，查看节点结果并处理人工待办。排队不等于已生成成果。

节点包括来源读取、人工反馈读取、事实提取、汇总决策、文档树组织、验收、人工审阅和发布。运行冻结配置及输入版本；普通运行拒绝配置或来源变更。失败后显式继续当前流水线时仍使用它的固定配置，即使后续运行的设置已修改；来源及反馈必须保持一致。发布前再次校验来源内容。不支持的格式、过大输入、提取未完成、伪造引用、模型输出截断都会明确失败，不默默发布不完整成果。

定时整理按 UTC 的每日或每周周期执行。自动发布是显式配置；关闭时，验收通过后生成发布待办。运行失败保留上一个已发布版本，并产生异常处理待办。

## 来源组与网络来源

「运行流水线」以左侧列表、右侧画布铺满子页面，列表独立滚动，列出状态、触发人或定时任务、开始时间和持续时间。点击立即切换选中项，已有缓存先展示，再读取最新授权数据；过期请求不能覆盖新选择。画布使用精简接口，不加载完整节点正文和密集溯源。轮询只更新变化的节点，保留当前视角；离开页签或浏览器隐藏时停止轮询。窄屏打开失败流水线时先定位失败节点。选择一次运行查看其冻结流程；直接点击节点，在右侧抽屉查看对应日志、错误与人工待办。日志记录实际的来源、分批、模型请求/输出字符数和重试，未记录的历史日志不补造。执行中持续刷新，等待审核时间计入总持续时间。

AI 助手启动或重试运行后保留原任务等待后台执行；后台完成或人工决定唤醒同一任务，恢复前复验当前权限。助手可以说明待审批事项并继续等待，不会因为收到通知就代替用户审批。其他安装插件可使用同一[公开唤醒服务](plugin-ai-continuations.zh-CN.md)。

一个来源卡片可以绑定多个文档、知识库、文件、文件夹、外部链接或插件配置，也可混合绑定。配置只接受 `{version: 1, items: [...]}`，每项有稳定的 `id`。每组最多 50 项，禁止重复和嵌套；旧单项配置明确拒绝，不转换历史数据。组贡献者必须有每项的原资源权限。

网页选择器支持批量链接和网络搜索。搜索使用系统配置的 SearXNG 等搜索服务，可限制站点。正文校验、有效来源保存和流程中的来源读取统一使用 AI 设置绑定的网页读取服务（内置、Firecrawl、Jina 或 Tavily）。带章节片段的链接通过所选服务返回的 HTML 验证并截取准确范围；Firecrawl 和 Jina 支持此方式，Tavily 需使用整页链接或改选支持 HTML 的读取服务。服务失败会明确报告，不自动切换到其他服务。结果卡片供选择，摘要不是证据。加入链接前验证实际正文、所选片段和内容大小，保存有效来源时服务端再次抓取。任何链接失败都不会部分保存。暂停来源保留配置，重新启用需验证。私网来源地址、携带凭据的 URL、缺失片段和不可读页面拒绝使用；向外部服务提交来源链接前仍由宿主校验公开地址。

通用 `content.v1` 提供方同时可用于原知识库订阅和知识册，没有另外一套知识册专用插件注册接口。组中可以多次选择同一提供方的不同配置。绑定或贡献者失权时阻止新读取；成果展示仍检查具体证据引用。

编排画布左侧按来源与人工输入、AI 知识整理、审阅与发布分组展示已有节点类型。点击加入节点后配置规则、连接输入。卡片显示节点类型、规则摘要及来源／验收范围；点阵画布支持曲线连线、平移、缩放、适应画布和展开。拖动或修改规则保持当前视角，展开后可按 Escape 收起。画布工具按钮左对齐，节点面板可单独收起，顶部工具栏也可隐藏；画布保留恢复按钮。发布节点保持唯一，保存仍验证完整流程。

## 人工介入

所有人工审阅节点、发布审批和失败节点都进入「人工待办」，同时支持跨知识册和知识册内查询。按类型、状态过滤，查看候选正文与验收结果，然后通过、退回或继续执行。处理动作使用版本校验，避免重复审批；输入已变化的待办不能批准旧结果。异常待办通过 `resume` 继续当前固定流程；独立的 `retry` 接口仍按当前配置创建新运行。内容重做后，下游人工审批重新进入待办并增加任务版本。同一待办再次处理时，原有决定、处理人、意见和时间保留在宿主安全审计中。

通用验收项只定义一次，各验收节点通过 `criterionIds` 复用；领域特有范围保留在节点规则。多个节点使用同一个必需验收项时，每个节点仍独立评审，任何一个未通过都会阻止发布。人工页面集中展示同一验收项的结果，保留各节点的具体结论。

「AI 操作示例」提供补充来源、合并验收项和段落纠错的请求模板，发送前由用户修改确认；「我的操作记录」列出当前用户与该知识册有关的个人会话，其他管理员的 AI 对话和记忆不会一起展示。

评论、纠错、补充和疑问是有版本的编排输入，可以手动添加，也可以要求个人 AI 助手登记。反馈可以定位到某个成果版本、文档和段落；定位受限成果需要原证据访问权限。修改反馈产生新输入版本，不直接改变成果段落。权重和采用规则由节点配置决定，高权重不能使没有证据的说法自动成为事实。

## 成果与溯源

默认使用纯阅读模式，只展示渲染后的文档；切换到「审阅」才展示段落反馈、证据数和采用依据。切换只是页面视图，不改变已发布 Markdown 或溯源。

目录标题完整换行，章节与页面层级清晰，展开图标位于标题前。点击目录会打开其下第一个文档，并展开到选中文档；箭头只控制展开或折叠。目录和正文各自滚动，来源、流程和待办列表也可独立滚动。

正文提供路径面包屑、分级小标题、本页导航和按目录顺序切换的上一篇／下一篇。宽阅读区在右侧显示导航，窄阅读区折叠在正文上方；导航随滚动高亮，可以通过键盘定位。导航来自实际 Markdown 标题，代码块中的 `#` 不作为标题；没有标题的正文不生成虚假的段落目录，原文保持不变。新运行要求汇总与文档树节点输出有意义的二、三级标题，历史成果不被改写。exmd 已发布的 `MarkdownPreviewInteraction` 接口负责渲染定位，宿主保留原图片权限解析。

新生成内容围绕实际知识详解展开：定义、组成关系、运行机制、条件、例外、权衡与有依据的示例；架构与流程使用真实 Mermaid 代码块，不能只写“图”的文字说明。学习指引只作简短引言。汇总每批最多处理 40 条知识判断，文档树组织按正文规模分批并保留细节。遗漏不同知识判断、长文没有小标题、组织时删光已有 Mermaid 图都会触发修复。大章节按当前每页 200 段限制分篇，不丢弃正文。这些规则只校验新输出，不改写历史成果。

成果复用 exmd 的只读渲染，页面包含文档树、版本选择、段落反馈、采用依据和经过校验的来源引文，不提供 Markdown 源码编辑器。

溯源图完全由实际运行结果生成，连接来源版本、证据、知识判断、采用决策、段落、文档、节点执行和成果版本，也记录人工审阅决策。它不能单独编辑。可以查看整个网络，或查看某篇文档的上游关系，点击节点检查具体依据。默认按来源合并证据、按当前查看范围合并知识判断，同类关系合为标注数量的连线；点击分组查看原始成员，也可关闭合并查看细节。只调整展示，不修改成果中保存的原始关系或证据。

来源全文保留在来源系统和运行时内存中。成果与节点日志只保留引用到的精确片段、哈希、来源定位及生成内容，不再建立额外的全文副本库。来源更新不会改写历史成果。读取成果及节点日志时检查原来源权限；外部来源删除、解绑或提供方不可用时，相关成果停止展示，保留的数据不被删除。

贡献者失去知识册编辑权限后停止抓取其来源。之前生成的数据可以保留，但保留不等于授予显示权限。任意模型上下文来源不可访问时，合并成果保守地停止展示，包含模型最终没有引用的输入。

## 人工与 AI 共用接口

路由前缀为 `/api/v1/knowledge-books`：

| 路由                                | 用途                                                   |
| ----------------------------------- | ------------------------------------------------------ |
| `GET /`、`POST /`                   | 列表、新建                                             |
| `GET /:id`                          | 配置、来源、反馈、运行及已发布成果                     |
| `POST /:id/commands`                | 人工与 AI 共用命令                                     |
| `POST /:id/source-search`           | 检查编辑权限后通过已配置服务搜索网页                   |
| `POST /:id/source-web-check`        | 验证链接正文与所选片段                                 |
| `GET /:id/runs/:runId`              | 执行与候选结果                                         |
| `GET /:id/runs/:runId/pipeline`     | 经授权的精简画布数据，不返回完整节点正文及溯源         |
| `GET /:id/releases/:releaseId`      | 不可修改的成果版本                                     |
| `GET /human-tasks`                  | 按知识册、运行、节点、关键词、类型、状态、偏移查询待办 |
| `POST /human-tasks/:taskId/resolve` | 带预期版本通过、退回、继续或新建重试                   |

命令包括 `configuration.save`、`configuration.patch`、`workflow.node.patch`、`workflow.node.add`、`source.remove`、`source.save`、`feedback.save`、`feedback.withdraw`、`run.start`、`run.cancel`、`run.resume`、`run.retry`、`run.publish`。配置、来源和反馈保存必须提供 `expectedRevision`。`packages/core/src/modules/knowledge-books/protocol.ts` 是第 1 版协议定义。AI 的 `knowledge_book` 工具调用相同业务函数，个人助手的会话和记忆仍属于真实用户。AI 读取目录清单后，通过 page 分页读取正文和证据，或用 find 定位段落；登记的反馈保留真实操作者和手动/AI 助手入口。来源节点与分析节点权重相乘，同一证据从多个来源节点到达时取最高权重，避免重复输入抬高可信度。

## 旧整理卸载与数据库边界

旧知识库整理和问答机器人已移除，不再提供整理会话、工作器、设置、指引、条目或生成普通文档的投影。文档、来源订阅、索引和搜索保留。知识库导航移除「来源与订阅」入口，已有订阅记录保留。

当前数据库基线为 `doca-2026-10-09-history-storage-v1`。知识册表保留，旧知识库整理表及字段继续停用。正常启动拒绝旧基线，不自动转换；仅准确的上一基线可按[部署步骤](deployment.zh-CN.md#从-0113-升级)显式离线升级历史存储。旧文件绑定保留且继续拒绝访问，不恢复旧整理协议；不得删除已有数据库来启动新版。

失败或取消的运行通过 `run.resume` 继续当前流水线，保留运行 ID、固定流程、已完成节点和失败日志。继续前复验来源登记、反馈、原权限及完整的实时来源清单，包括证据标识、版本和内容哈希；来源内容增删或改变时拒绝混用输入。验收未通过时，从最近的上游内容生成节点及其下游修复，保留知识抽取和无关分支，把此前验收结果作为修复依据。重复失败或后台执行中断使用原节点与待办记录，保留已记录的失败事实及处理意见。只接受当前第 1 版配置，不转换旧格式、不迁移或删除数据。

原 `run.retry` 仍是独立的新建运行操作。重试保留原运行，只有冻结配置、来源登记、反馈及完整的当前来源清单均一致时，才复用完成节点；来源不可用、增删块或内容变更均阻止复用。人工审批节点及其后续节点重新处理。每个复用节点在审计与溯源中记录原运行。每次厂商模型调用之前都复验贡献者授权，包括分批提取与格式修复。

公开只读视图只显示渲染成果和溯源，不暴露编辑配置或构造虚假的默认流程。历史成果遵循原文档历史权限。溯源可定位到文档或段落，流程执行和模型上下文关系可单独开启。
