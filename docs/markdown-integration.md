## 已接入平台

- `markdown` 类型：新建菜单、知识库文档树、主页列表筛选和紫色图标。
- 导入 `.md/.markdown`，512 KB 上限，首行作为标题；导出当前 Markdown 源文。导出保留稳定资源 ID，不是包含图片文件的离线打包格式。
- 固定工具栏、仅编辑/分栏，平台查找替换面板调用 SDK 模型接口；首行变化同步标题，目录标题延迟刷新。
- 使用原有平台连接与提交队列，不启用包内 WebSocket、IndexedDB 或第二条自动保存通道。
- 协议：`markdown-ytext` / schema 1 / protocol 1；原始 Yjs `markdown` 文本根与 `exmd:meta` 元数据。
- 新增 `markdown_epochs` 与 `markdown_receipts`，消息 ID + epoch + payload 摘要持久去重；数据库提交后 ACK，同 ID 不同内容拒绝，普通 checkpoint 不切换 epoch。
- 原始 checkpoint + 增量恢复；50 次提交或 5 分钟形成关键快照并压缩已覆盖日志。
- IndexedDB 按 origin、用户、资源、codec/schema 隔离，存原始 CRDT 副本、epoch 与未确认队列；先读本地副本再与服务器同步。精确 ACK 才移除对应消息，超时重试保留原始 ID 与 bytes。
- 已打开文档断线后可继续编辑；关闭页面后重新联网打开可恢复待提交内容。**不宣称整站离线冷启动可用**：入口页面与身份/资源元数据仍需加载，尚无完整离线应用壳。
- 分享、授权、匿名只读、全文评论复用平台；服务器仍是权限最终裁决者。匿名页面不持久缓存副本。
- 图片通过平台上传、稳定 UUID 写入 Markdown、预览通过鉴权资源接口解析。未知路径及外部图片地址不自动加载；导入不会自动抓取第三方图片。
- 业务历史快照、只读历史预览、回滚前快照、同 epoch 新事务回滚、独立副本、回收站预览和清空。
- 内部文档链接保存相对地址；引用关系从 Markdown 语法树提取，代码块/行内代码/图片不误计为文档引用，读取继续做 ACL 过滤。
- 同账号多页面的会话选区通过平台传输，非空选区已验证高亮；服务器解析 item-based RelativePosition，不错误要求每个位置都包含根名称。
- SDK 未限定范围的样式通过 Vite/PostCSS 仅作用于 `.doca-markdown`，防止 `.toolbar/.workspace/.brand` 污染平台其他页面。

## 必须反馈给 Markdown 包开发者

### 1. 仅预览切回编辑后，编辑视图与协同模型脱节

隔离浏览器复现：

1. 宿主注入已有 Y.Doc/Y.Text 会话，打开一份空文档。
2. 输入 `# Markdown test` 和 `Hello world`，确认另一个页面已同步。
3. 点击“仅预览”，再点击“分栏”。
4. 本页 CodeMirror 显示空白，另一个页面仍显示原内容；随后本页输入、接收远端修改出现异常。

定位：`src/lib/CollaborativeMarkdownEditor.tsx` 在预览模式卸载 CodeMirror，恢复时继续传入旧 `initialEditorValueRef.current`。这个值是最初挂载的文本，不是当前 Y.Text 投影。需要处理视图重新挂载时的初始化与 Yjs 绑定，不能用旧 value 覆盖/脱离当前模型，也不能重新初始化 Y.Doc。

验收要求：空文档/已有文档 → 编辑 → 预览 → 编辑/分栏，反复切换后 `getMarkdown()`、CodeMirror 当前内容、远端页面始终一致；切换本身零正文事务，继续输入、撤销、远端收包正常。同时测试预览期间远端编辑、上传完成、只读切换。

平台临时防护：隐藏并阻止“仅预览”模式切换，只保留不会卸载编辑视图的“仅编辑/分栏”。历史与回收站使用独立只读 MarkdownPreview，不受此编辑视图切换问题影响。未观察到切换动作自动清空远端原数据，但存在误编辑风险，因此不能放开此入口。

### 2. 公开远端选区接口没有普通光标与用户名标签

`src/editor/remote-selections.ts` 的公开绘制层过滤 `to === from`，只对非空选区使用 Decoration.mark；用户名仅在 HTML title 中。宿主已经传入服务端的 sessionId、userId、name、color，并验证相对位置可解析。

请补齐：折叠选区的插入光标、上方用户名标签、每个会话独立着色、跨行选区、远端编辑后定位更新、只读/失焦/离开清除。验收必须通过宿主公开 `renderRemoteSelections` 路径，而非仅通过包内演示 awareness 连接。

### 3. 区域评论尚不是完整能力

已提供 capture/resolve/reveal 相对锚点，但 README 明确尚无批量锚点装饰、点击回调及完整删除后的 orphan 策略。平台本轮只接入全文评论，不把相对锚点定位当作已完成飞书式区域评论。

后续请提供：未激活下划线、激活背景、评论卡片与区域双向定位、取消激活、解决/彻底删除后不展示，以及锚点边界插入的明确语义。当前默认相对位置在文本末尾追加时可能扩大锚定范围，需要明确产品预期。
