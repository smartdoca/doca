# 平台服务凭据

[English](service-credentials.md)

入口：管理员后台 → 平台设置 → 服务凭据。当前宿主持有的平台配置包含：

- 身份认证：具名 SSO Client Secret 和允许的 HTTPS 来源；身份源引用凭据名称。
- 验证码网关：HTTPS 地址、Bearer 密钥和手机/邮箱渠道。
- 文档搜索：Meilisearch API 密钥及允许来源。

文件后端凭据和 CloudFront 签名密钥只通过 `DOCA_FILE_STORES_JSON` 配置，存储管理页只读，不在平台记录中编辑。[插件凭证](plugin-credentials.zh-CN.md)使用独立的服务端加密服务和部署主密钥。

## 持久化与配置优先级

平台配置保存于 `account_settings` 的 `service-credentials` 记录。现有代码只在记录不存在时，从运行环境初始化身份和消息配置；之后已有数据库记录优先，修改环境变量不会覆盖已保存配置。这是现存初始化路径，本轮如实记录，未新增适配器或迁移。当前宿主明确拒绝含旧 storage 形状的记录。

数据库连接、站点地址、监听端口和文件存储仍属于启动配置。数据库连接必须先于持久设置读取；首次管理员仍通过显式引导命令初始化。

## 接口与密钥处理

`GET` / `PUT /api/v1/admin/service-credentials` 只允许系统管理员访问，写请求验证 Origin。GET 用 null 替换已有秘密值；PUT 的 null 保留原值，空字符串明确清空。不要提交伪遮罩字符串。修订号防止并发覆盖。审计只记录动作，不记录密钥；端点继续限制协议、来源和重定向。

服务端保存访问第三方服务所需的可用凭据，数据库及备份按敏感配置保管。密钥不返回普通用户、公共 bootstrap、错误日志或管理员 GET 响应。插件凭证加密不会自动重新加密这些平台设置。

每个实例在 API 请求前检查配置修订号，变更后刷新适配器，无需重启。轮换验证码密钥使未完成挑战失效。存储密钥变更遵循部署方管理的[存储规则](storage.zh-CN.md)，保留稳定存储 ID 和被引用字节。
