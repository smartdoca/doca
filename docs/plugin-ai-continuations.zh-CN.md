# 后台任务完成后续跑 AI

SDK 源码 **0.1.10** 已导出 `@smartdoca/plugin-sdk/ai` 中的 `aiContinuationsServiceToken`，服务名为 `ai.continuations.v1`。所有安装的服务端插件都可申请这项能力，知识册使用同一个宿主机制。源码实现不代表已发布 npm 或部署上线。

插件声明 `sdkRange: "^0.1.10"`，把 token 放入必需注入。缺少服务的宿主拒绝初始化，没有通过 `ai.v1` 的旧宿主适配，也不会推断历史业务任务的等待关系。

插件负责业务任务、当前权限、稳定操作标识、持久结果和通知/outbox；数据使用公开的宿主管理存储。宿主负责助手身份、等待检查点、取消、模型续跑和技术限制。唤醒不构成业务授权，也不能替代人工审批。

1. 在 mount 注册来源：`registerSource({id, pluginId, read})`。id 以 `<pluginId>.` 开头，pluginId 必须等于安装身份；卸载时自动清理注册。
2. `read(context, {operationId})` 根据当前业务权限读取持久结果，返回版本 1 快照；无权或任务不可用时返回 null。上下文包含宿主重新读取的身份与取消信号，结果不能携带秘密。
3. 注册的 AI 工具执行期间，用宿主提供的原始上下文调用 `wait(pluginId, context, {sourceId, operationId})`，返回 receipt。复制、伪造或工具结束后保留的上下文会被拒绝。业务任务先以稳定键幂等启动，再登记等待。
4. 业务结果提交后调用 `wake(pluginId, {sourceId, operationId})`。重复通知只能领取一次助手检查点。即使通知先于助手进入等待，宿主的定期核对和重启恢复也会重新读取持久来源。

快照字段：`version:1`、`state`、`revision`、`summary`，以及可选 JSON `result`。state 为 `running`、`waiting_input`、`completed`、`failed`、`cancelled`。可处理的结果或人工决定变化时更新 revision；仅运行心跳不会唤醒模型。进入人工处理时续跑一次，助手可解释待办并继续等待决定；结束后携带结果事实继续原任务。结束的业务任务结果保持稳定，新执行使用新的 operationId。

宿主只保存完整工具调用与回执。等待释放模型执行槽，保留原任务和检查点，不消耗异常恢复次数。登记、通知和真正续跑时重新鉴权；权限撤回、用户停用、来源卸载或新协议记录无效会停止续跑，显示错误并保留检查点。取消助手等待不会自动取消插件业务任务，后者由插件提供操作。

技术限制：每轮最多 20 个等待，来源标识 120 字符，操作标识与 revision 200 字符，摘要 2000 字符，序列化快照 24000 字符，读取期限 20 秒。按游标分页并限制并行读取，慢来源不占用普通模型执行槽。启动核对在插件组合完成后开始。

[英文文档](plugin-ai-continuations.md) 提供公开 SDK 接入示例。示例中的 jobs 是插件通过 `storage.sql.v1` 实现的业务仓库，不是假定存在的 SDK 导出；幂等启动、权限判断及提交后通知均由插件实现。

## 持久化与回退

只有显式新登记的等待写入严格版本 1 检查点。数据库任务状态约束保持原样，使用既有停放状态；API 和界面展示 `awaiting_dependency`。没有数据库迁移、双写、旧记录补字段转换或历史任务自动唤醒。无效的新等待记录拒绝续跑，保留诊断资料。

回退停止新登记和写入，保留检查点、业务结果与审计记录。旧宿主不会续跑新协议；先取消仍在等待的助手任务，或停机并恢复匹配宿主，再回退。不会清空用户数据。

知识册的节点、来源、批次、模型输出量和重试事实写入现有审计存储，不复制模型正文。运行详情刷新状态、心跳、实际错误与最近 200 条记录；不伪造历史日志，更早的已写日志仍保留在存储中。
