# Doca 0.1.13

[中文](0.1.13.zh-CN.md)

## Changes

- Separate text generation, reference generation, and source-image editing tools, with explicit Volcengine, Qwen, OpenAI-compatible, and optional local protocol adapters and per-tool model selection.
- Persist complete image-batch inputs, user requirements, page plans, candidates, usage, and delivery file links. Large tasks execute in document/page fragments; bounded repairs and candidate selection prevent unlimited regeneration.
- Review against the user's actual requirements. Ordinary tasks allow natural blending and illustration styles; pixel-level checks require explicit precision requirements. Incorrect characters, visible pasted regions, and anatomical defects cannot be reported as successful delivery.
- Simplified AI uploads, global/per-user upload limits, browsable folder references, durable attachment reads, and account/session-isolated browser drafts. Includes the isolated upload directories and actual file IDs from 0.1.12.
- Read complete PDF pages and text. DOCX, PPTX, and XLSX combine LibreOffice-rendered pages with source structures. Docker includes LibreOffice, sandboxed Chromium, and Chinese fonts.
- Knowledge books provide shared sources and editable workflows, web search and authorized plugin sources, acceptance criteria and human tasks, readonly Markdown trees, immutable releases, and provenance from actual executions. Personal AI and the UI share commands and permissions.
- Remove the old knowledge-curation and Q&A bots while retaining editable libraries, source subscriptions, indexing, and search.
- Explicit deployment service addresses accept HTTP or HTTPS, including intranet S3/RustFS endpoints, origins, assets/CDNs, identity providers, AI connections, and plugin services. Browser UUID/SHA-256 and text-copy adapters only supply missing APIs; stored IDs, digests, and documents are unchanged. Arbitrary webpage requests retain SSRF checks.
- Web login lifetime is configurable with `DOCA_SESSION_TTL_SECONDS` (default 86,400 seconds / 24 hours), and mobile lifetime with `DOCA_MOBILE_SESSION_TTL_SECONDS` (default 15,552,000 seconds). Existing Web session records are not rewritten.

## Deployment and data

**The database baseline is `doca-2026-10-08-knowledge-books-v2`. Databases from 0.1.12 and earlier are rejected before schema changes. This image cannot start directly against those databases.**

Preserve the original deployment, databases, files, and configuration. Use a separate empty database and separate storage. No automatic migration, conversion, reset, or old-curation API adapter is provided. Roll back using the previous code and unchanged old database; retain new records and files as well. Never delete an existing database to make the new release start.

Parsing caches require `parserVersion:4`; old caches are rejected and retained. Knowledge-book source groups require the complete `version:1` binding list without converting old single-source records. Existing image models use the approved profile-default rules; new Wan/MFLUX profiles require explicit configuration. Explicit image-batch upgrades retain the original scope, historical jobs, candidates, costs, and attempt counts. Older code may not resume upgraded batches; restoring this release permits resumption.

`DOCA_AI_IMAGE_MAX_ATTEMPTS_PER_PAGE` controls cumulative generation attempts per page, defaulting to 5 and accepting positive safe integers after restart. It limits requests, not guaranteed charges; local adapters also count attempts. This release does not start, download, or package local image models or weights.

## Verification and limits

Release attachments record verification, image digests, and web-asset checksums. Protocol tests use isolated databases and mocked providers; they do not establish actual image quality.

The integrated suite passed 2,523 tests with 3 environment skips; the final clipboard/browser/session increment passed 13 targeted tests. TypeScript, the Web build, 49 bilingual documentation pages, and independent SDK JavaScript/declarations passed. The old-baseline rejection test verifies unchanged tables and records.

Actual Linux amd64 and arm64 containers passed HTTP startup, configured session lifetime, exact upload-ID byte roundtrips, private downloads, independent directories, and knowledge-book creation/source commands/permissions. DOCX/XLSX/PPTX conversions and sandboxed Chromium PDF export passed. All 437 Web assets match across architectures.

**The two whole-storybook image suites have not achieved complete accepted delivery. This release does not claim to pass that end-to-end acceptance.** Model capability, identity consistency, and natural blending depend on the actual model and inputs; failed pages retain their evidence.

Knowledge-book publication rechecks source and contributor permissions. Revoked or unavailable sources restrict affected output reads while preserving stored data. Book-administrator status does not grant source access.
