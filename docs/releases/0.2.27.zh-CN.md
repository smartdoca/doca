# Doca 0.2.27 — 无浏览器渲染与单文件安装

[English](0.2.27.md)

富文本和 Markdown 的 PDF 导出改用固定版本 WeasyPrint 70.0；画板 PNG 导出使用官方 Canvas SDK 的 SVG 输出、隔离 Node 渲染与 resvg。运行镜像不再包含 Chromium、Playwright，无需宿主 seccomp JSON 文件或浏览器共享内存配置。Office 转换继续使用 LibreOffice，PDF 读取与可编辑导入继续使用 PDF.js。

全新 SQLite/本地存储安装可下载本次 Release 的 `doca-compose-v0.2.27.yaml`，保存为 `compose.yaml`，填写 `DOCA_ORIGIN` 和自行生成的 `DOCA_CREDENTIAL_MASTER_KEY`，保护文件权限后运行 `docker compose up -d`。管理员初始化命令为 `docker compose exec doca bash docker/admin.sh bootstrap`。代理、健康检查、密码重置和离线镜像交付见[部署指南](../deployment-without-github.zh-CN.md)。初始化脚本已放入镜像，无需源码或配套 seccomp 文件。

**升级要求：**从容器环境中移除 `DOCA_PDF_CHROMIUM`，空值也应移除。启动和 PDF 导出均明确拒绝此废弃配置，不回退 Chromium。使用新镜像时，删除部署配置中引用 seccomp 文件的旧 `security_opt` 项。已有站点必须保留原 Compose 项目名、持久卷、数据库、附件、配置和凭证主密钥；独立 YAML 用于全新安装，不应覆盖已有站点的配置。

现有 PDF 接口、文档格式、编辑器公开 API 和 SDK 历史读取规则沿用原路径，没有数据库结构或持久化数据转换。回滚时恢复上一版代码、依赖锁、镜像及其配套部署配置，并保留升级后的全部数据。从 0.2.24 之前升级还须遵守 [0.2.24 发行要求](0.2.24.zh-CN.md)。

同时修复导出的表格列宽、中文字体加载及流程图 HTML 标签。含 SVG `foreignObject` 的流程图由导出客户端转成图片以保留标签，普通文档正文仍可选择。PDF 可编辑导入对复杂布局仍采用既有近似规则。测试样例与限制见[渲染器验收](../verification/browser-free-renderers-2026-10-30.md)。

发布目标为 GitHub 发行附件与 Docker Hub 的原生 Linux amd64/arm64 镜像；发布不代表已更新运行中的 Doca 网站。
