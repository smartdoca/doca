# Doca 0.1.17

[简体中文](0.1.17.zh-CN.md)

This release follows 0.1.16 and fixes PostgreSQL image reads and AI message submission. The published plugin SDK remains 0.1.10.

## Changes

- Verify PostgreSQL bigint byte counts numerically. Complete PNGs no longer fail with `file_content_size_changed`, and PDF originals and reference images are no longer reported as changed solely because of the driver representation. Genuinely short files are still rejected; original object metadata is preserved.
- A failed extraction retry waits for its current attempt rather than returning the previous failure. Concurrent background requests for the same database and object share the in-flight extraction.
- Sending immediately transfers text, references and attachments into the outgoing message. Users can type while session creation or uploads are pending; a later response preserves the next draft.
- Failed submissions retain the message and its stable request ID. Restore the original draft only into an empty composer, preserve a newer draft, and reuse uploaded attachments on retry.

## Validation and limits

All 21 attachment tests passed against isolated PostgreSQL, covering PNGs, genuinely short files, extraction retries and successive PDF image batches. Browser checks used an isolated account and a mock model to verify immediate clearing before network completion, next-draft preservation, failure restoration and stable-ID retries. The PNG reached the vision request as image content. The mock response does not validate visual understanding quality.

An independent existing PostgreSQL issue remains: `assets.purpose varchar(16)` cannot store the 18-character `ai_image_candidate`. It blocked 19 generation/revision cases in expanded validation; the other 100 passed. Column widening and an explicit offline upgrade require separate agreement and are not implemented in this release. These blocked cases are not reported as passing.

Full regression passed: 265 files, 2,589 tests passed and 3 environment tests skipped. TypeScript, the Web production build and 54 bilingual documentation pages passed.

Full regression, type checking, builds and image verification are recorded in release attachments and the [acceptance record](../../artifacts/ai-postgres-send-regression-2026-10-10/README.md). No user documents or production databases were modified.

## Deployment

The database baseline, parser cache version 4, composer draft version 1 and plugin SDK retain their existing protocols. This release performs no database or historical-data conversion. Existing 0.1.16 deployments can replace the image; earlier baselines retain the [0.1.15 upgrade requirements](0.1.15.md). Preserve databases, files, configuration and the credential master key.

- GitHub tag `v0.1.17`, with web assets and verification records.
- Docker `docker.io/smartdoca/doca:0.1.17` and `latest`, Linux amd64 and arm64.
- npm `@smartdoca/plugin-sdk@0.1.10`; this release changes no SDK exports.
