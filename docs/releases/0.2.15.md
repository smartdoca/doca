# Doca 0.2.15 — Capture destination tree

[简体中文](0.2.15.zh-CN.md)

Browser Assistant capture profiles now use the same tree presentation as the document Move dialog. New captures can go to Personal documents, a library root, or below a specific document. Libraries load separately from recent documents and have their own pagination, fixing the picker that could show only Personal documents when recent documents filled the first page.

Reopening a saved profile expands its original library and ancestors and scrolls to the selected destination. Read-only documents remain visible as disabled ancestors. Failed directory loads offer an explicit retry without resetting the saved location; failed profile saves retain the selection. Existing create and move permissions remain distinct. The existing library outline limit is 10,000 nodes, with a warning when truncated.

This changes the Doca settings page. Update Doca and refresh Browser Assistant settings; browser extension 0.2.3 remains unchanged. Profile fields, API formats, database structures and stored content are unchanged. No historical profiles are converted or rewritten automatically.

See [destination picker verification](../verification/clipper-destination-tree-2026-10-24.md).

Publication verified: 3365 full-regression tests passed (11 configured skips), 15 targeted tests passed, and three consecutive Chromium/SQLite runs saved and captured content under the selected destination. Both native image architectures, public registry tags and downloaded GitHub assets passed verification. See the [release receipt](../verification/release-0.2.15.md).
