# Doca 0.1.15

[简体中文](0.1.15.zh-CN.md)

This is the final unified release for these changes. It supersedes 0.1.14 with a continuation-boundary fix: scanning changes only explicitly marked new waits and leaves unreadable or unmarked historical results untouched. Official 0.1.14 artifacts remain preserved; use 0.1.15 for deployment. SDK 0.1.10 is unchanged.

## Changes

- Each knowledge-book organization run has a pipeline. The left list displays success, failure, review and publication waits, the triggering person or schedule, start time and duration. Click a node to inspect its logs, errors and human tasks in the right drawer.
- Execution logs record source reads, model requests/output character counts, batches, retries and node outcomes. Each run uses its frozen configuration; failures and saved results remain available, without fabricated historical logs.
- The assistant receives the currently authorized knowledge book, or offers existing titles and a create option elsewhere. Knowledge-book commands, optional search filters and native table field guidance are corrected. Example and repair handoffs prefill editable text; human-task links open the exact task.
- SDK 0.1.10 exposes generic plugin background continuation through `ai.continuations.v1`. Plugins register sources, wait and notify through public services. Background results and human decisions resume the original assistant task. Waiting releases execution slots; new waits survive restart, notifications are deduplicated, and identity/permissions are rechecked before resuming.
- Tiered history retains the latest 20 full snapshots in the database and the newest one in each group of 10 older snapshots in file storage. One unified history list is used. Writes, reads and digests are verified before cleanup; storage failure preserves originals.
- Assistant image attachments upload on send with progress and stable session/file identities for retries; failures preserve drafts. Document uploads default to 20 MB with preflight feedback. Video drops, playback errors and file-save feedback are improved.
- Document/comment/toolbars/navigation, account menus and notifications receive alignment and scrolling fixes. Knowledge books are separated from library lists, totals, pagination and home entries. Plugin installation no longer passes frozen credentials to the mutating S3 SDK.
- Every deployment requires `DOCA_CREDENTIAL_MASTER_KEY`, including hosts without plugins. Keep the original key during upgrades; fingerprint validation and existing ciphertext rules remain unchanged.

## Upgrade and rollback

The database baseline is **`doca-2026-10-09-history-storage-v1`**. Normal startup rejects earlier baselines and never automatically upgrades or resets them.

Only the exact 0.1.13 baseline `doca-2026-10-08-knowledge-books-v2` supports explicit offline upgrade. Stop all instances, back up databases, files and configuration, keep the original credential master key, and follow the [deployment guide](../deployment.md) to run the maintenance container or `pnpm history:upgrade --apply`. The upgrade transaction does not rewrite or sample snapshots; sampling starts after the new host starts.

**The other nine snapshots are removed after verified transfer and cannot be restored through the application.** Rollback restores retained points and preserves file bytes/manifests; complete history requires the pre-sampling backup. Other baselines are rejected. See [history storage](../storage.md).

Generic continuation writes only new strict version 1 wait tickets using the existing parked AI-job state. It neither migrates a database nor automatically wakes historical tasks. Before host rollback, stop new writes and retain records; an older host cannot resume new tickets. See the [public contract and limits](../plugin-ai-continuations.md). Historical attachment directories are not automatically moved.

## Validation and limits

264 test files passed: 2,587 tests passed and three environment checks skipped. TypeScript, Web build, 52 bilingual documentation pages and independent SDK JavaScript/declarations passed.

The GitHub Release verification attachment records full tests, TypeScript, Web build, bilingual docs and independent SDK JavaScript/declaration checks, container digests and asset checksums.

Real-model checks use isolated databases and cover native table creation/editing, current-book context, book selection, failure repair, source-to-acceptance execution, manual publication and automatic continuation of the original task. Fault injection is explicitly marked. One missing task revision was corrected by the model; guidance and examples were subsequently strengthened. This is not a claim that models never submit invalid arguments. Generic continuation tests cover restart, duplicate notices, revoked access, removed sources, cancellation and invalid records.

No user documents or production databases were modified. Mobile waiting listeners compile but were not validated on a device for this release. Actual cloud permissions, configuration rotation and production backup restoration require deployment validation. Full document-rendering dependencies remain in the image; the experimental lightweight image is not released. The previous release's incomplete whole-storybook image quality acceptance is still not claimed complete.
