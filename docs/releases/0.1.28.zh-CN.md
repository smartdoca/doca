# Doca 0.1.28

[English](0.1.28.md)

修正知识册验收提示词与用户规则的冲突，并增加明确的人工接受已知问题流程。SDK 流错误对象使用现有安全分类器处理，避免显示为 `[object Object]` 或被助手误判为内容验收失败。

## 知识册验收与人工放行

验收按运行冻结配置中的描述和明确例外执行，`grounded` 等 ID 不隐含“只能来自 Manual”的固定政策。明确允许准确常识时，不能仅因材料未提及就拒绝；严格来源要求继续检查证据，算术错误与协议矛盾仍按实际规则拒绝。修改配置不会改变已有运行的冻结规则；应用新规则需要新建重试。

对已有完整候选和有效负面验收结果的待办，新增“接受已知问题并继续”。用户必须填写接受哪些已知问题并确认。原失败 checks、节点失败状态及候选正文保留，人工决定、操作者和候选/配置哈希进入审计与成果溯源。批准后复用候选执行后续节点；未开启自动发布时仍有发布审批。缺少正文、无有效验收结果或技术执行失败不能这样放行。

发布前复核批准者权限、来源访问、输入快照及候选/配置是否匹配；变化或失效时阻止发布。取消后续跑可复用仍有效的人工决定。个人助手读取待办能力后说明可执行动作，不再虚构 owner 或页面可以绕过门禁，也不根据错误字符串猜测模型的验收判断。

## 配置示例与升级

两份环境示例显式填写现有默认的 SQLite 插件业务库路径，并说明 PostgreSQL 应注释该路径、配置独立业务库及受限角色。这是部署说明改进，不改变运行时布局或历史数据。

从 0.1.27 升级时停止实例，保留数据库、文件、配置及主密钥，成套更新宿主和 Web。没有 SQL 结构变更或旧数据转换。配置、流水线和成果继续为 version 1；新人工决定在现有 resolution 中记录 `acceptanceOverride.version=1`，旧决定不会自动获得放行能力。

回退前停止新执行并保留所有后续写入。0.1.27 可以读取同格式的已发布成果、失败 checks 和人工决定，但旧执行器不能继续新的人工放行流程。更早版本仍须遵守 [0.1.26 的插件库升级要求](0.1.26.zh-CN.md#从-0125-升级的必要步骤)。

## 验证

全量 2898 项通过、8 项跳过；专项 156 项通过；PostgreSQL 17/18 各 58 项通过。真实模型对照确认严格来源缺失拒绝、允许准确常识通过、错误算术仍拒绝。隔离页面完成接受已知问题、发布审批和发布；冷读回保持成果哈希及失败结论。已发布的 0.1.27 镜像验证新成果可读。详细范围见[验证记录](../verification/knowledge-book-manual-acceptance-2026-10-16/README.md)。

发布附带 Web 资源与镜像部署包。双架构镜像、资源校验和及发布验证清单见 [GitHub Release](https://github.com/smartdoca/doca/releases/tag/v0.1.28)。未重新生成或替用户批准原知识册。
