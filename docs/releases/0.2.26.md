# Doca 0.2.26 — Search relevance and spreadsheet editing fixes

[简体中文](0.2.26.zh-CN.md)

Platform and assistant search now filter candidates against the current authorized title and full source text before counting or pagination. A shared brand such as DOCA alone does not satisfy a multiword topic. Queries with no relevant content return an empty list. Successful empty file searches stay empty rather than falling back to candidate listings. The filter favors precision: semantic paraphrases without shared concrete terms can be omitted. Existing AI score settings and access checks remain in force.

The official npm dependency **@smartdoca/sheet 0.2.15** fixes clicking the **Wrap** and **Merge** labels and prevents frozen panes with unequal row heights or column widths from covering the cell being edited. Host callbacks and public signatures remain unchanged; declaration differences are generated import hashes and union-member order. Model, Yjs, preferences and XLSX runtime bytes match 0.2.14. No host scroll patch, new props, schema change or data conversion is added.

Directory drag operations within one knowledge base now retain trashed descendants while requiring management permission for the entire subtree, as explicitly approved. Descendant contents, deletion states, parent identities and grants are preserved. Failed drag messages remain visible after the list refresh.

This release introduces no database structure or persisted-format changes. Existing historical readers and approved defaults remain in their established paths. Retain the previous deployment and dependency lockfile for package rollback, and preserve all later content. Upgrades from versions before 0.2.24 must also follow the [0.2.24 requirements](0.2.24.md). See the [issue verification](../verification/issue-record-host-2026-10-29.md).

GitHub release assets and native Linux amd64/arm64 Docker Hub images are the publication targets. Publishing them does not update a running Doca site.
