# Doca 0.2.22 — 自动回收闲置收录名额

[English](0.2.22.md)

每次新收录都会检查原有的十个任务上限。名额已满时，服务端从最旧的暂存任务开始，回收至少 **30 分钟**没有上传或重试活动的任务，只释放新请求所需的名额。有关联的排队、运行或等待审批中浏览器 AI 任务的连接受到保护。重试、上传会刷新活动时间，长时间对象上传会发送服务端心跳。活跃任务仍以十个为上限。

回收的任务使用已有的 `expired` 状态；冻结原文、已上传对象和原定 **24 小时到期时间**保持不变，到原期限后才按正常流程清理。已完成文档和图片保留。到期清理补齐了无图过期任务的原文释放。回收名额与创建新任务共用账号锁和事务，无效请求不会回收旧任务。

扩展 **0.2.10** 遇到过期收录时，自动使用手头冻结的材料重建并重试一次，保留账号、保存位置、选区和图片，不重新读取其他网页，不对配额或授权错误无限重试。未知错误码会显示出来。产品内不增加手动管理任务的操作。

用户已于 2026-10-26 明确同意此自动方案。收录协议 v1、授权 v2、数据库表列及持久化 JSON 形状不变；历史暂存任务使用其已记录的活动时间和到期时间，不填造历史默认值或转换数据。旧扩展继续使用原接口，遇到旧任务过期可重新收录。回退时保留全部记录和对象，并保留无图过期任务的清理修复；或等待已回收任务到原期限、完成清理后再回退该修复。

服务端更新到 **0.2.22**，随后下载并重新加载扩展 **0.2.10**。原站点在 0.2.21 后的实际阻塞是未完成任务已满，原通用提示隐藏了这一原因。此前的正文转换降级与图片占位继续有效。

生产定位、已同意的保留规则及回归范围见[验收记录](../verification/clipper-automatic-recovery-2026-10-26.md)。
