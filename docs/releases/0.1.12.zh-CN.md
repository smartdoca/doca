# Doca 0.1.12

[English](0.1.12.md)

## 改动

- AI 本地文件夹上传创建独立的根目录。此前上传过同名目录时，新目录使用编号名称，不再混入旧会话的文件。文件管理器中明确上传到已有目录的操作仍以该目录为目标。
- 文件列表响应绑定请求目录和请求顺序。切换目录后，旧目录的延迟响应不能覆盖当前列表。
- 附件上传和已有文件转为附件的接口同时返回实际文件 ID 与素材 ID。助手上下文提供本轮输入的准确附件与文件引用，已知 ID 直接读取，不再从全局目录或同名旧目录猜测。
- 在环境配置示例中明确开发环境与 Docker 的存储路径。

## 范围与数据

本版处理上传范围与文件 ID 问题。正在开发的整本图片生成改造及其端到端验收不包含在本版，也不宣称已完成。

数据库、持久化附件与消息格式、插件契约及 SDK 接口均未变化。不引入迁移、转换、目录清理或用户数据重置。已有目录保留；独立目录行为适用于新的 AI 本地文件夹上传。部署要求沿用 [0.1.11](0.1.11.zh-CN.md#部署与数据) 的说明。

## 分发

- GitHub 标签 `v0.1.12`。
- Docker 镜像 `docker.io/smartdoca/doca:0.1.12` 与 `latest`，支持 Linux amd64、arm64。
- GitHub Release 附带 Web 资源、SHA-256 校验文件与验证清单。
- 插件 SDK 保持 0.1.9，插件契约保持 0.1.7。公开接口未变，不需要单独发布 SDK。

## 验证

TypeScript 检查、Web 生产构建和默认测试集通过：184 个文件、1,221 项测试通过，3 项环境条件测试跳过。上传测试覆盖旧会话同名目录、明确选择已有目录及权限错误。隔离接口测试确认返回的文件 ID 对应实际创建的记录，并验证即使另一份上传复用同一存储对象，模型仍只获得本轮附件的 ID。SDK 独立 JavaScript 与声明文件验证通过。

容器验证和镜像摘要记录在发行验证清单。本版不宣称验证了外部生图服务或完成整本图片验收。
