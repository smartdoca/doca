# Doca 0.1.18

[简体中文](0.1.18.zh-CN.md)

This release combines the published spreadsheet integration and the remaining workspace changes, including the released 0.1.16 and 0.1.17 fixes. It locks `@smartdoca/sheet@0.2.0-rc.19`; the plugin SDK remains 0.1.10.

## Changes

- The spreadsheet Data validation toolbar action and Insert → Dropdown list use their respective entry points. Plugin-element insertion uses native menu extensions with the current selection, readonly guards and native transactions. Returning from Read to Edit refreshes the toolbar capability snapshot immediately.
- Failed knowledge-book runs continue with their original ID and frozen workflow, retaining completed nodes, failure records and unrelated branches. Continuation revalidates complete source inventories, content versions, hashes and current permissions. Incremental canvas updates preserve the viewport; stale responses cannot replace a newer run selection, and hidden pages pause polling.
- Reading navigation uses actual Markdown headings and wraps long titles. Provenance groups evidence and claims and merges repeated edges. New content generation batches work and checks claim coverage, section headings and preservation of Mermaid diagrams.
- Knowledge-book web sources use the configured fetch service, support HTML section selection and validate public URLs, redirects and response limits. Search administration can clear an invalid embedding-dimension setting.
- Native flowcharts and mind maps can be inserted through the rich-text toolbar and referenced through whole-block comments and AI context. AI diagram changes invalidate derived previews atomically. Upload progress reflects transferred bytes; toolbar tooltips preserve selection.
- Routes, previews and selected large components load lazily; Markdown previews defer PDF conversion dependencies. Static assets negotiate Brotli/gzip with a bounded cache. Production static routes serve CAD resources. PDF Chinese fonts use WOFF2 with the complete original glyph set.
- Login provider icons, file previews, AI panels and narrow layouts improve. Retired in-repository editor archives are removed in favor of locked npm artifacts.

## Verification and limits

The full regression passes 267 files: 2,648 tests passed and 3 environment tests skipped. Frozen dependency installation, TypeScript, production Web build and bilingual documentation results are recorded in the release verification attachment.

The rc.19 public declarations and Yjs/model/XLSX files are byte-identical to rc.18. Existing isolated spreadsheet browser checks cover Chinese/English entry points and readonly disabling; host regressions cover sessions, stable anchors, worksheets, axis sizes, references and XLSX import. Diagram, toolbar, knowledge-book and PostgreSQL evidence remains under `artifacts/`. Final container platforms, startup, asset hashes and static compression checks are recorded in the release verification attachment.

New checks use isolated data and do not edit user documents or production databases. Model depth with real sources, native devices, production backup restoration and cloud configuration require their own acceptance. The PostgreSQL `assets.purpose varchar(16)` image-candidate length limitation recorded in 0.1.17 is unchanged; affected generation/revision cases are not claimed to pass.

## Deployment and rollback

The database baseline remains `doca-2026-10-09-history-storage-v1`. This release adds no compatibility adapter, historical-format conversion, database migration or user-data cleanup. Existing history readers, strict baseline validation and explicit offline maintenance commands retain their current behavior. Preserve databases, files, configuration and the credential master key when replacing a 0.1.17 image. Earlier baselines follow the [0.1.15 requirements](0.1.15.md). Stop writes and back up data before rollback; previous release artifacts and Git tags remain available.

- GitHub tag `v0.1.18`, with Web assets, per-file hashes, checksums and verification records.
- Docker `docker.io/smartdoca/doca:0.1.18` and `latest`, Linux amd64 and arm64.
- npm spreadsheet `@smartdoca/sheet@0.2.0-rc.19`; plugin SDK `@smartdoca/plugin-sdk@0.1.10` has no export changes.
