# Doca 0.2.16 — Browser assistant context

[简体中文](0.2.16.zh-CN.md)

Opening the browser assistant now checks the remembered conversation against the current capture rule before restoring it. A conversation bound to an edited rule stays preserved in Doca; the extension opens a fresh composer for the selected current rule instead of displaying a misleading access-change error. Other authorization and network errors remain explicit, and failed initialization can retry.

New browser messages add their attached webpage to the conversation's operated resources, with the original title and a link that opens in a new tab. The website and extension both show these links; repeated use of the same URL updates one entry. These activity links do not grant document access. The first accepted message names a new browser conversation using its request, webpage title and hostname. Later messages, manually named conversations and historical titles are preserved. A browser icon with an accessible label replaces the repeated source text in conversation history and headers.

Rich-text page navigation and AI buttons stay at the far right when comments are expanded, including narrow layouts.

Update Doca, download and reload browser extension **0.2.4**, and reopen its assistant. Database structure, capture and authentication protocols, persisted queue/session formats and existing content remain unchanged. No historical conversations, queued messages or page records are converted, removed or backfilled. Previously retained legacy queue and authentication policies remain as documented in the [browser assistant guide](../browser-assistant.md).
