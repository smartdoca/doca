# Doca 0.1.14

[English](0.1.14.md)

## 改动

- 知识册每次整理展示一条运行流水线。左侧列表显示成功、失败、待审核、待发布确认等真实状态，以及触发人或定时任务、开始时间和持续时间；点击节点，在右侧抽屉查看对应日志、错误和人工待办。
- 执行日志记录来源读取、模型请求与输出字符数、分批执行、重试、节点完成与失败。运行使用自己的冻结配置；失败记录和已保存成果保留，不补造历史日志。
- AI 助手带入当前有权限的知识册；无页面上下文时提供已有册和新建选项。修正知识册命令、可选搜索参数和原生表格节点字段说明。示例与修复入口预填可编辑文字，人工待办打开准确任务。
- 新增插件通用后台唤醒服务 `ai.continuations.v1`，通过 SDK 0.1.10 的公开接口注册来源、等待和唤醒。后台完成或人工决定后恢复原 AI 任务；等待释放执行槽，重启保留新建等待，重复通知去重，恢复前重新核验当前身份和权限。
- 历史快照分层存储：最近 20 个完整快照在数据库，更旧的每 10 个保留最新 1 个到文件存储。列表统一展示；转存写入、读回和摘要校验成功后才清理，失败保留原件。
- AI 图片附件发送延后上传，显示上传进度，重试沿用稳定会话与文件标识；失败保留草稿。文档上传默认限制 20 MB，上传前提示；视频拖入、播放错误和文件保存提示改善。
- 文档、评论、工具栏、目录、头像菜单和通知对齐及滚动细节改善。知识册从知识库列表、分页、总数和首页入口中分开。修复 S3 SDK 修改冻结凭据导致的插件安装失败。
- `DOCA_CREDENTIAL_MASTER_KEY` 对所有部署必填，包含未安装插件的部署。升级保留原密钥；主密钥指纹校验和已有密文保持原规则。

## 升级与回退

本版数据库基线为 **`doca-2026-10-09-history-storage-v1`**。正常启动拒绝旧基线，绝不自动升级或重置。

仅 0.1.13 的准确基线 `doca-2026-10-08-knowledge-books-v2` 支持显式离线升级。停止全部实例，完整备份数据库、文件存储及配置，保留原凭证主密钥，再按[部署说明](../deployment.zh-CN.md)运行维护容器或 `pnpm history:upgrade --apply`。升级事务不改写、抽稀旧快照；新版启动后才开始每十个旧快照保留一个。

**其余九个快照在转存验证后淘汰，应用内无法恢复。** 回退命令只导回保留点，保留文件字节及清单；完整历史需要抽稀前备份。其他数据库基线不升级。详见[历史存储](../storage.zh-CN.md)。

通用唤醒只写新的严格 version 1 等待票据，使用现有 AI 任务停驻状态，不迁移数据库或自动唤醒历史任务。回退宿主前停止新写入并保留记录；旧宿主不能恢复新票据。详见[公开契约与限制](../plugin-ai-continuations.zh-CN.md)。旧附件目录不自动搬迁。

## 验证与限制

264 个测试文件通过：2,587 项通过，3 项环境测试跳过。TypeScript、Web 构建、51 页双语文档和独立 SDK JavaScript/声明验证通过。

全量测试、TypeScript、Web 构建、双语文档和独立 SDK JavaScript/声明验证结果，以及镜像摘要与资源校验，随 GitHub Release 验证附件提供。

隔离数据库上的真实模型验证覆盖原生表格创建/修改、当前知识册上下文、知识册选择、失败修复、来源到验收的流水线、人工发布和原任务自动继续。故障注入明确标记；一次模型漏传待办版本后自修正，随后加强工具字段说明和示例，不宣称所有模型都不会输错参数。通用插件等待覆盖重启、重复通知、失权、失活来源、取消和异常记录。

未操作用户文档或生产数据库。移动端等待监听通过编译，未做本版真机验收。历史存储的真实云端权限、配置轮换与生产备份恢复仍需部署环境验证；本版保留完整文档渲染依赖，未发布实验轻量镜像。上一版未完成的整批故事书图片质量验收仍不宣称完成。
