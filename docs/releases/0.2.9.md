# Doca 0.2.9 — Smaller Web updates

[简体中文](0.2.9.zh-CN.md)

Published: [GitHub v0.2.9](https://github.com/workhold/doca/releases/tag/v0.2.9) and DockerHub `smartdoca/doca:0.2.9` / `latest` (native amd64 and arm64). All image/render/runtime gates passed. With 0.2.8 layers retained, the first update adds 19,957,274 compressed layer bytes on amd64 or 19,956,943 on arm64; full images contain 707,921,380 / 704,722,946 bytes respectively. GitHub's three assets were downloaded and verified, including all 478 Web assets. See the [publication receipt](../verification/release-0.2.9.md).

This packaging release separates the Web build into reusable image layers. CAD resources, fonts, the HTML entry, eight groups for files at least 512 KiB and 16 smaller-code groups have their own `COPY --link` layers. A Vite chunk's changing content hash does not move its stable name into another group. Files, URLs, permissions and rendering features are preserved.

An isolated OCI experiment with the actual 483-file Web build updates and renames one entry JS chunk and rewrites its HTML reference. It reuses 25 of 27 Web layers; new layers total 334,554 compressed bytes, compared with roughly 19.7 MB for the preceding whole-Web layer. This demonstrates that boundary, not a fixed download promise for every update. Actual transfer depends on changed chunks, dependencies/base images and locally retained layers. Layer headers add a small amount to the complete image.

A second experiment rebuilds an isolated source copy with Vite after a CSS-only change. Hash changes propagate across multiple chunks, but 13 of 27 layers remain identical; new layers total 4,489,097 compressed bytes, about 77.2% less than the preceding whole-Web layer. Both experiments preserve the production build.

The five editor npm versions, browser preferences, server APIs, document codecs, database structure and browser queue records are unchanged from [0.2.8](0.2.8.md). Continue following its upgrade and recovery requirements, preserving all data and stopping older senders as directed. No migration, compatibility reader, renderer download or browser-sandbox change is introduced.

Verification compares every original Web file and directory, checks production Dockerfile coverage and validates every OCI blob hash. Native amd64/arm64 release gates checked the resulting image's complete runtime/Web files, authentication, original image bytes, sandboxed PDF, Canvas pixels and Office conversion before publishing version/latest. Production deployment remains separate.

The earlier UI-image HTTP504 still has no returned image and unknown usage; records remain retained and automatic paid retry stays blocked. The required Mastra memory patch remains unchanged.
