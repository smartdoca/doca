# Doca 0.2.9 — 减少 Web 更新下载量

[English](0.2.9.md)

已发布 [GitHub v0.2.9](https://github.com/workhold/doca/releases/tag/v0.2.9) 和 DockerHub `smartdoca/doca:0.2.9` / `latest`，原生 amd64、arm64 镜像及渲染/运行字节验收全部通过。保留 0.2.8 层时，本次首次升级新增压缩层分别为 19,957,274 / 19,956,943 字节；完整镜像分别为 707,921,380 / 704,722,946 字节。三个 GitHub 附件已下载并校验，其中 478 个 Web 资源与冻结构建完全一致，见[发布回执](../verification/release-0.2.9.md)。

本次是镜像打包优化：CAD 资源、字体、HTML 入口、8 组至少 512 KiB 的大文件及 16 组其余代码分别使用 `COPY --link` 层。Vite 文件内容哈希变化后，稳定文件名仍留在同一代码组。原文件、URL、权限及渲染功能全部保留。

使用实际 483 文件 Web 构建进行隔离 OCI 实验：更新并重命名一个入口 JS，改写 HTML 引用，27 个 Web 层中复用 25 层，新层压缩合计 334,554 字节；此前整块 Web 层约 19.7 MB。这证明该分层边界，不承诺每次真实更新都只下载这些字节；实际取决于代码块、依赖/基础镜像变化及服务器保留的旧层。完整镜像会有少量分层头部开销。

另一次实验从隔离源码副本执行真实 Vite 构建，仅修改 CSS。哈希变化连带传播到多个代码块，27 层中仍有 13 层完全相同，新层合计 4,489,097 压缩字节，比旧整块 Web 层少约 77.2%。两项实验均保持生产构建原样。

五种编辑器 npm 版本、浏览器偏好、服务器 API、文档 codec、数据库结构及浏览器队列记录与 [0.2.8](0.2.8.zh-CN.md) 相同。继续遵循其升级/恢复要求，保留全部数据并按要求停止旧 sender。不新增迁移、兼容读取器、渲染器下载或浏览器沙箱变更。

验证逐项核对原 Web 的文件和目录、生产 Dockerfile 的完整覆盖及所有 OCI blob 哈希。原生 amd64/arm64 发布门槛已核对镜像全部运行/Web 字节、鉴权、原图字节、沙箱 PDF、画布像素及 Office 转换，通过后发布版本与 latest。生产部署单独进行。

此前 UI 生图 HTTP504 仍未返回图片、用量未知，原数据保留且不自动付费重试；必要的 Mastra memory 补丁保持原状。
