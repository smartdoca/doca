# Doca 0.1.11

[中文](0.1.11.zh-CN.md)

## Changes

- Extend the existing `image_generate` tool with optional reference image IDs. The model chooses uploaded images or generated images from the current conversation, including previous turns, without a user-facing mode switch. GPT Image and compatible services use `/images/edits`; Seedream 4.x/5.x sends reference images to `/images/generations`. Unsupported image editing fails explicitly without retrying as text-only generation.
- Validate reference ownership, conversation membership, deletion state, file size, media type and decoded image contents before sending them to the provider. Preserve reference order for multiple images and recheck access before saving the generated result.
- Replace five visible browser-native select controls with the shared dropdown in Meilisearch settings, account contacts, account recovery and the default chat-model setting. Required-field validation focuses and opens the dropdown, and the Meilisearch controls fill their available width.
- Queue browser asset uploads with at most two concurrent requests. AI attachments show local image previews and upload progress; removing an attachment or closing the composer cancels its upload. Server upload errors retain their status and diagnostic payload.
- Clarify Docker local-storage paths and how to diagnose upload `EACCES` errors without deleting persistent data. Development `.env` paths and the container's `/data/storage` path are documented separately.
- Include the bilingual Docsify documentation introduced after 0.1.10.

## Deployment and data

This release uses the same `doca-2026-10-03-credentials-v2` database baseline, plugin contracts and deployment configuration as 0.1.10. Upgrading a 0.1.10 installation does not require a database migration or storage conversion. Back up the database and storage before replacing the application image, and retain the previous image and configuration for rollback.

The [0.1.10 requirements](0.1.10.md#breaking-deployment-requirements) continue to apply when upgrading from 0.1.9 or earlier: preserve that deployment and its data, and use a new empty database and separate storage. No automatic migration, conversion or data reset is introduced.

No new AI tool, SDK package version or persisted attachment/result format is introduced. Image models retain their existing configuration, size rules, return-format rules and usage accounting. Real provider support for image editing depends on the configured service and model.

## Distribution

- GitHub tag `v0.1.11`.
- Docker images `docker.io/smartdoca/doca:0.1.11` and `latest`, for Linux amd64 and arm64.
- Web assets, SHA-256 checksums and a release manifest attached to the GitHub Release. The manifest records the source commit, registry digests and completed verification.
- Plugin SDK remains 0.1.9; plugin contracts remain 0.1.7.

## Validation

TypeScript, the Web production build and the default suite passed: 1,217 tests across 183 files, with three environment-conditional tests skipped. Image-editing tests use mock provider responses and isolated data, covering an uploaded reference, continued editing in a later turn, multiple-image order, rejected references and explicit provider failures. Upload tests cover concurrency, cancellation, progress and error preservation. Bilingual documentation and local links pass validation.

Container startup and asset-upload verification for both Linux architectures are recorded in the release manifest. Real external AI services are not claimed as verified; release checks do not use production user documents or data.
