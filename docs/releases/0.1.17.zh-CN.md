# Doca 0.1.17

[English](0.1.17.md)

本版在 0.1.16 基础上修复 PostgreSQL 图片读取和 AI 消息发送交互。插件 SDK 沿用已发布的 0.1.10。

## 改动

- PostgreSQL 的 bigint 字节数按数值核验，修复完整 PNG 被报为 `file_content_size_changed`、PDF 原稿和参考图片被误判改变的问题。实际短文件仍被拒绝，原文件元数据保持不变。
- 失败解析的重试等待当前尝试完成，不再抢先返回上次失败结果；同一数据库、同一对象的后台提取复用正在执行的任务。
- 点击发送立即把文字、引用和附件移到发送中的消息，上传或创建会话期间输入框即可继续输入。后端响应不会清空下一条草稿。
- 发送失败时保留消息和稳定提交标识；输入框为空时恢复原草稿，已输入新草稿时不覆盖。重试复用已上传附件。

## 验证与限制

隔离 PostgreSQL 上的 21 项附件测试通过，覆盖 PNG、真正短文件、失败解析重试及连续 PDF 图片流程。浏览器使用独立测试账户和模拟模型，验证接口等待期间即时清空、后写草稿保留、失败恢复和稳定标识重试；PNG 实际进入视觉模型请求。模拟回答不作为图片理解质量验收。

另发现 PostgreSQL 既有 `assets.purpose varchar(16)` 无法保存 18 字符的 `ai_image_candidate`。扩大验证中的 19 项生成／修订用例受此独立问题阻塞，其余 100 项通过。字段扩容和显式离线升级需要单独同意，本版没有更改该结构，也不宣称这些用例通过。

全量回归 265 个文件通过，2,589 项通过、3 项环境测试跳过。TypeScript、Web 生产构建及 54 页双语文档检查通过。

完整回归、类型检查、构建和镜像校验结果见发行附件与[本次验收记录](../../artifacts/ai-postgres-send-regression-2026-10-10/README.md)。未操作用户文档或生产数据库。

## 部署

数据库基线、提取缓存版本 4、草稿格式 version 1 和插件 SDK 均保持现有协议。本版没有数据库或历史数据转换。已有 0.1.16 部署可更换镜像；更早基线继续遵守 [0.1.15 的升级要求](0.1.15.zh-CN.md)，保留数据库、文件、配置和凭证主密钥。

- Docker `docker.io/smartdoca/doca:0.1.17` 与 `latest`，Linux amd64、arm64。
- npm `@smartdoca/plugin-sdk@0.1.10`，本次没有 SDK 导出变化。
