# Doca 0.2.8 — Editor fixes and browser assistant reliability

[简体中文](0.2.8.zh-CN.md)

This release combines editor, comment, browser-assistant and AI message recovery fixes. See the [acceptance record](../verification/issue-tracker-2026-10-21/npm-direct.md). [GitHub assets](https://github.com/workhold/doca/releases/tag/v0.2.8) and DockerHub `0.2.8`/`latest` are published and verified; see the [final receipt](../verification/issue-tracker-2026-10-21/release.md). This work has not upgraded the production site.

All five editors use exact official npm releases: Canvas **0.5.14**, Sheet **0.2.11**, Slate **0.4.25**, Markdown **0.4.4** and Slides **0.3.0-alpha.4**. Local editor patches are removed; release checks reject local candidates, version ranges and active editor patches. The separately required Mastra memory reflection fix remains, without a broader SDK upgrade.

Spreadsheet zoom still defaults to **100%**, with default row height/column width increased 10% to **21.78/87.12**. Footer slider/button changes are remembered per browser origin, account and document and restored on reload. Stored dimensions and manual row/column sizes remain intact. The user explicitly approved the new defaults for historical appended/recovery sheets with no stored defaults. Manual dimensions remain collaborative.

Other fixes cover Canvas connectors, containers, notes, titles, native keyboard ownership and minimal-table undo; Sheet hyperlink focus, preview disposal, clipboard, dropdown removal and shared filters; and rich-text headings, diagram input and DOCX styles. Five-format image galleries, automatic comment pagination, upload/send feedback, retained drafts and a sidebar taking real page width have website evidence. Comment keys do not mutate selected document elements.

The browser assistant retains multiple capture profiles with one default and shares the website AI conversation interface. The IndexedDB sender preserves original message IDs, explicit continuation, profile isolation and accepted/withdrawn tombstones. Quick notes explicitly select an authorized existing rich-text or Markdown target and append plain text without AI. Lost-response replay uses the same receipt without duplicate text. Five-minute tickets are process-local; closing the view discards temporary input/target.

Canvas view and future connector/note styles are personal browser preferences scoped by origin, account and document. Existing content and explicit API/AI properties remain intact; unknown/malformed records are preserved. Canvas PNG export delivers a downloadable file, and large-image inspection retains original bytes while using a bounded preview.

The image retains Chromium, Office and fonts for PDF, Canvas screenshots and file previews. Runtime cleanup removes declarations, SQLite compiler inputs and other-platform prebuilds. Common dependencies and each editor have separate layers, with architecture-specific registry build caches. The first layout transition downloads new layers; later pulls reuse unchanged layers. See the [image evidence](../verification/issue-tracker-2026-10-21/image-size.md); the isolated experiment is not a fixed download-size promise.

## Upgrade and recovery

Server database structure, compatibility generation, document codecs/schemas, immutable baselines, checkpoints and collaboration ACK/message identities remain unchanged from 0.2.7. No server migration, historical-document conversion or capture-profile merge is added. Existing browser-assistant authentication and schema requirements from [0.2.7](0.2.7.md#upgrade-and-recovery) remain in effect.

**The user explicitly approved the AI browser-queue storage change twice.** New sends use independent IndexedDB `doca-ai-pending` version 1 / `entries`, isolated by target Doca origin, authenticated user, connection and original message ID, with explicit extension profile revision. The complete payload and source hashes are checked and transitions finish only after transaction commit. Accepted/withdrawn tombstones remain; unknown versions/records and storage failures are retained and refused without a localStorage or memory-only send fallback.

The old 0.2.7 localStorage queues are read only. They are not merged, deleted or automatically replayed. A recognized old item requires individual explicit continuation/withdrawal and current settings; already accepted jobs reconcile without another capture or submission. **Stop sends and close all old website pages and extensions before upgrade or rollback. Mixed old/new senders are unsupported:** old senders cannot see the new tombstones. Rollback stops the new sender and preserves both stores, tombstones and all later data. It neither copies records back nor automatically re-enables the old sender. An old binary without safe sender disablement cannot resume queue sending. See the [approved storage and recovery details](../verification/issue-tracker-2026-10-21/ai-pending-idb.md).

Personal Canvas preferences use separate version-1 records. Absent records preserve current behavior; unknown/malformed records are neither consumed nor overwritten. View changes do not enter content collaboration/history. Rollback disables preference use without deleting records or converting content.

Sheet zoom uses independent version-1 browser records. Missing records use 100% and opening writes nothing; unknown/malformed/extra-field records remain untouched and are refused. Denied storage permits transient current-view changes; anonymous views do not persist. Rollback stops preference reads/writes and preserves records/content. Stored defaults, manual sizes, baselines, seeds, checkpoints, updates and epochs are not migrated or backfilled; only sheets without stored defaults use the approved new display defaults.

Preserve databases, file volumes, settings, credentials/master key and later writes. Deploy matching server, Web and extension artifacts. Retain the previous artifacts and reviewed recovery plan; this release provides no general database downgrade procedure.
