# Doca 0.1.12

[中文](0.1.12.zh-CN.md)

## Changes

- AI local-folder uploads create an independent root directory. If an earlier upload used the same name, the new upload receives a numbered directory instead of merging with the earlier conversation's files. Explicit file-manager uploads into an existing directory continue to target that directory.
- File explorer responses are bound to the requested directory and request sequence. A late response from a previous directory cannot overwrite the current listing.
- Attachment uploads and stored-file attachment creation return the actual file ID together with the asset ID. The assistant receives the exact attachment and file references for the current input and reads known IDs directly, rather than searching global or similarly named directories.
- Clarify development and Docker storage paths in the environment example.

## Scope and data

This release addresses file upload scope and file identification. The ongoing whole-book image-generation redesign and its end-to-end acceptance are not included or claimed as complete.

Database, stored attachment and message formats, plugin contracts, and SDK interfaces are unchanged. No migration, conversion, directory cleanup, or user-data reset is introduced. Existing directories are retained; the independent-directory behavior applies to new AI local-folder uploads. Deployment requirements remain those documented in [0.1.11](0.1.11.md#deployment-and-data).

## Distribution

- GitHub tag `v0.1.12`.
- Docker images `docker.io/smartdoca/doca:0.1.12` and `latest`, for Linux amd64 and arm64.
- Web assets, SHA-256 checksums and a verification manifest attached to the GitHub Release.
- Plugin SDK remains 0.1.9; plugin contracts remain 0.1.7. Public APIs are unchanged, so no separate SDK publication is needed.

## Validation

TypeScript checking, production Web build, and the default suite passed: 1,221 tests across 184 files, with three environment-conditional tests skipped. Upload tests cover same-name directories from an earlier conversation, explicit directory uploads, and authorization errors. Isolated server tests verify that returned file IDs identify the created records and that the model receives only the current attachment IDs, including when another upload shares the same stored bytes. Independent SDK JavaScript and declaration verification passed.

Container verification and registry digests are recorded in the release manifest. No external image generation or completed whole-book acceptance is claimed by this release.
