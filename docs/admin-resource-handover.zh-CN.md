# 管理员资源交接

[English](admin-resource-handover.md)

系统管理员在「后台管理 → 用户管理」找到已停用账号，点击「资源交接」。选择接收人和资源，预览实际变更后确认。接收人必须是另一个正常使用的账号，原账号交接后保持停用。普通用户没有此入口，三个交接接口也独立校验管理员当前身份。

## 资源范围

清单来自现有资源、文件夹、文件及授权记录，仅显示名称、类型、归属和回收站状态等管理元数据，不读取正文或私有凭据。

| 类别 | 行为 |
| --- | --- |
| 文档、知识库、知识册 | 转移所选资源及其后代中原账号拥有的资源；其他人的所有权保留，关联内容在预览中单列。知识库所有者的现有管理范围适用于接收人。 |
| 文档图片和附件 | 文档对应的 assets 及文件目录项随文档转移，文件不能脱离文档单独交接。上传者和历史作者不变。 |
| 普通文件夹、文件 | 转移所选目录中原账号拥有的后代及文件。所选子目录或独立文件的父目录未交接且不属于接收人时，移至接收人的个人根目录；预览会标明。 |
| 文档、知识库保留的授权 | 可以单独勾选。将选中节点的有效授权授予接收人，并移除原账号在该节点的有效授权来源。继承范围保留，链接令牌不会转交。 |
| 共享文件夹授权 | 合并为接收人的文件夹授权，保留接收人已有的较高角色，移除原账号的该项授权。 |
| 回收站中的资源 | 可以交接，继续保留回收站状态。 |

个人 AI 文件、私有会话、凭据及插件业务数据不在交接范围。现有 AI/知识会话文件绑定和普通锁定文件仍受原业务限制；无法识别的元数据也不自动改写。文档附件本身的文件管理锁定不阻止其随文档交接。清单会说明不能选择的文件；所选目录包含受保护的文件时，整批阻止执行。

## 预览与权限冲突

预览展示实际所有权、授权、附件变化，位置调整，以及保留其他人所有权的关联内容。父级选择自动展开，不必重复勾选子项。每批最多选择 500 个清单项，展开的后代可能更多；清单和预览按每页 50 项显示。

接收人的较高授权不降级。原账号的本节点和后代角色无法无损合并、原账号子级存在限制而交接会扩大权限，或者接收人已有明确限制时，预览列出冲突并禁止确认。管理员需要先按现有权限流程复核，或调整选择。不会以管理员身份跳过这些权限限制，也不会复制无关的继承权限。

所选文档或文件夹上，原账号和接收人的待接受邀请会取消，避免稍后接受旧邀请覆盖交接结果。文档邀请保留归档及工单，文件夹邀请保留取消状态及工单；其他人的邀请不变。取消数量在预览中展示。公开范围、分享链接定义及其他协作者保持原设置；公开访问也不会因交接变为用户黑名单。

## 一致性和审计

清单、预览使用数据库一致性快照；提交时重新计算预览指纹。相关账号、资源、授权、附件或目录内容发生变化后，旧确认返回 409，必须刷新并重新预览。两位管理员同时提交同一批次，只能成功一次。

一次确认在一个数据库事务中完成所有归属、授权、邀请、索引任务和安全审计变更。接收人的现有接纳/配额策略仍会执行；任一步失败则整批回滚。文件实体不搬运或删除，正文、版本历史、上传者和原始作者均保留。提交后刷新在线权限并通知涉及账号。

安全审计动作是 `user.resources_handed_over`，记录实际管理员、原账号、接收人、预览指纹、变更和变更前的相关元数据。原账号审计记录不包含接收人的无关私有授权。当前使用同步批次，没有跨进程续跑的后台任务；浏览器断开或响应丢失后先重新扫描清单，避免把已成功的批次当成失败重做。

本功能沿用现有表及数据格式，无数据库结构或历史数据转换。不提供自动反向交接或自动恢复旧权限；需要纠正已确认的业务决定时，应根据审计记录重新核实资源及授权后操作。

## 接口和验证

- `GET /api/v1/admin/users/:id/resource-handover`：资源清单。
- `POST /api/v1/admin/users/:id/resource-handover/preview`：`targetUserId`、`keys`。
- `POST /api/v1/admin/users/:id/resource-handover/execute`：相同选择加上预览返回的 `fingerprint`。

核心及接口回归：`pnpm exec vitest run tests/resource-handover.test.ts`。真实后台流程：`pnpm exec tsx scripts/qa-resource-handover.mts`，使用隔离 SQLite、账号、文档和文件存储，输出到 `artifacts/verification/resource-handover/`。这不代表已完成 PostgreSQL 的运行验证。
