# AI 附件、文档读取与草稿

## 上传入口和限制

AI 输入框的上传弹框提供「Doca 文件」和「本地上传」两个主入口；素材入口位于弹框底部。Doca 文件选择器支持多选文件，以及进入文件夹后选择当前文件夹。本地文件选择器支持多选；本地文件夹由同一卡片内的小按钮选择，也支持拖入。浏览器的原生文件选择接口需要独立的文件夹选择动作。

选择或粘贴本地图片、文件时仅保留当前页面内的文件和本地预览，不上传、不创建 AI 文件记录。点击发送后，文字立即进入对话列表并显示发送状态；新会话创建、附件上传及解析在随后进行，全部完成后才提交消息供 AI 执行。新会话取得 ID 时保留这条发送中的消息。上传或提交失败保留失败消息和重试入口；重试复用已上传成功的附件与消息 ID，避免重复上传及重复任务。排队消息使用同一消息 ID 提交，与已接收的历史记录合并。

文件夹在输入框和已发送消息中都可点击，查看直接子文件、进入子文件夹并打开文件。查看时使用文件管理的实时权限，删除或撤销访问的内容不会因保留了聊天引用而重新开放。

管理员在「AI 管理 → 上传限制」配置文件个数、单文件大小和总大小。全局默认值为 100 个文件、单文件 100 MiB、总计 500 MiB；用户可独立覆盖，每个字段的 0 表示不限。单文件限制用于 AI 附件和文件夹内的文件上传；个数和总大小用于每条消息的附件及本地文件夹的一次批量选择。已有 Doca 文件夹的引用不重新上传文件。

配置是严格校验的 `version: 1`，保存时校验用户 ID 和修订号。没有旧配置适配、双写或自动迁移。取消的排队上传不会发送文件；大上传流式暂存，失败清理临时内容。上传不限不改变账号权限、存储策略、模型上下文容量或生图接口支持的参考图数量。

## PDF 和 Office

生图或原页导出前，宿主按当前任务的正式用户原文和有权限的输入清单核对交付范围。要求全部文档逐页交付时，即使执行模型漏调 `image_batch`，或因文件 ID 与上传附件 ID 混用导致 start 失败，宿主也从本次正式上传记录建立完整的 v5 批次，再进入逐页生图、导出和独立验收；尚未记录交付计划时先要求模型补齐 `task_plan`，不要求用户重述已有要求。明确的子集任务或“读取所有文档制作一张海报”仍走普通图片工具。范围判断是本次运行中的计量模型请求，要求逐字原文依据，截断、非法结构及虚构引文均拒绝，不以文件数量推断范围。附件正文不能作为任务指令。此逻辑不转换旧记录，也不新增持久数据格式；原文、输入快照、批次版本和尝试记录继续按现有合同核验。

PDF 使用 PDF.js 读取每页文字，并逐页渲染完整页面，包含文字、嵌入图片、矢量绘图和布局；原来的 50 页、16 张图片和文本截断逻辑已移除。页面图逐页存入衍生存储，避免同时持有整本书的所有位图。页面图为最长边最多 2000 像素的阅读/生图参考，原文件始终保留。

Word、PowerPoint、Excel 支持 `.docx`、`.pptx`、`.xlsx`。使用独立 LibreOffice 配置目录转成 PDF，再采用相同的逐页读取流程；同时读取源 XML 的正文、图片关系、备注、公式、单元格位置及结构/样式，以补充打印区域以外的内容。旧二进制 `.doc`、`.ppt`、`.xls` 不支持。外部资源、宏和主动嵌入内容会明确拒绝；转换失败不会伪装为完整读取。

**服务端必须安装 LibreOffice**，并让 `soffice` 可执行，或用 `DOCA_OFFICE_RENDERER` 指定其绝对路径。无需打开用户的 Office 程序。转换使用独立进程、120 秒超时和临时目录，完成后清理。复杂字体、公式、动画或打印设置不能承诺像素级一致；页面渲染与视觉模型的识别仍会报告未读取、不可辨认或输出截断的部分。

当前 Dockerfile 已包含 Writer、Calc、Impress、Math 并显式设置 `DOCA_OFFICE_RENDERER=/usr/bin/soffice`；重新构建并发布后才进入对应发行镜像，不代表已有 `0.1.11` 镜像包含它们。部署沙箱、字体、共享内存及可选 Linux SAM 挂载边界见 [Docker 文档渲染器](docker-rendering.zh-CN.md)。

解析结果严格使用 `parserVersion: 4`。旧格式会拒绝读取，原记录和原文件保留，不执行自动升级或迁移。回滚代码不会删除新派生图或用户内容，但旧代码不能消费新的解析和上传规则。PDF 页面渲染配置随包提供的 WASM 解码器，使 JBIG2 和 JPEG 2000 图像可被读取；解析错误直接失败，不能忽略图像后交付不完整的页面。参数依据 [PDF.js 官方 API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)。

此方案参考 [OpenAI 的 PDF 输入处理](https://developers.openai.com/api/docs/guides/file-inputs)和 [Anthropic 的 PDF 支持](https://platform.claude.com/docs/en/build-with-claude/pdf-support)：文字与页面图同时读取，大文档分批进入模型上下文。解析完整保存与模型一次能读取多少内容是独立条件。

## 历史附件和任务

任务完成后保留原任务输入和附件 ID。之前完成时清空输入的行为会破坏参考图的会话归属查询，现已移除。刷新页面和模型历史压缩不会清空附件存储；已删除的文件、已丢失的原内容和无权访问的内容不自动恢复。

模型可使用以下受权工具：

| 工具                  | 用途                                          |
| --------------------- | --------------------------------------------- |
| `session_attachments` | 分页查询本会话历史上传附件及可用状态          |
| `session_images`      | 分页查询当前有效的上传图、生成图和书页参考 ID |
| `attachment_read`     | 按附件 ID 分页读取全文和页面图                |
| `file_read`           | 按 Doca 文件 ID 使用同一解析流程读取          |

文字使用 `offset` / `nextOffset`；图像使用 `imageOffset` / `nextImageOffset`。任一游标未到末尾时不能宣称完整读取。页面读取返回持久 `referenceImageId`，可同人物参考图一起用于 `image_reference_generate`，或以原页作为 `image_edit.sourceImageId`。每次使用派生图仍检查原文件的权限和会话归属。初次上传只将有限预览放进上下文；完整内容在服务器按需读取。

一次上传多份 PDF/Office 文档时，支持视觉的执行模型首轮只接收持久附件清单和有界正文，不预加载书页及同批参考照片。模型先规划完整范围，再用 `attachment_read` 和 `image_view` 实际查看当前步骤所需的原页和参考；图片未进入首轮请求不代表已经失效或完整看过。单份文档、普通图片任务及纯文字模型的既有读取路径不变。原文件、完整解析页面及权限检查均保留，不更改解析缓存或附件记录格式。

## 输入草稿

浏览器草稿采用独立 `version: 1`，按账号和会话隔离，保存准确的文本顺序、文档引用位置、文件夹和已上传附件的持久 ID。切换会话、刷新和关闭页面后恢复；发送成功只清空该会话的草稿，发送失败保留。发送中切换到另一个会话不会清空另一个会话的输入。

草稿保存在当前浏览器的 `localStorage`，不跨设备同步，也不保存尚未上传完成的本地文件二进制。无效草稿严格拒绝解析并保留原记录；不转换旧消息缓存或待发送队列。浏览器禁用存储或容量不足时明确提示保存失败。

未发送的本地图片、文件可在当前页面切换会话后恢复选择与预览；刷新、关闭页面会丢失这些尚未上传的本地二进制，文字及已存在的持久附件引用仍按上述草稿合同恢复。本次不改变草稿、队列或服务器附件的存储格式，也不补归属、不搬动或清理已有顶层文件。

验证使用隔离数据库、临时存储和模拟模型，涵盖权限撤回、重启后的历史附件读取、PDF 后部页面、Office 实际转换、无限上传以及浏览器草稿恢复；不操作用户文档。

浏览器验证可复跑：先构建网页，在一个终端运行 `DOCA_QA_ISOLATED=1 pnpm exec tsx scripts/qa-ai-upload-server.mts`，另一个终端运行 `DOCA_QA_ISOLATED=1 node scripts/qa-ai-upload-ui.cjs`。后者需要安装 Playwright 和 Chrome，或通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 模块。只允许隔离服务地址 `http://127.0.0.1:39351`，数据库和文件存储都是临时创建的；终止服务会清理。

## 批量图片交付

支持视觉的执行模型通过读取工具直接查看原始页面像素，不能把 OCR 文字描述当作人物身份与页面布局。当前安装的 AI SDK 会将工具媒体内容序列化成文字，因此模型调用层将最近一次读取返回的图像作为真实图片输入发送，工具文字回执仍保留；更早的像素按需重读，避免积累整本书的位图。纯文字模型仍通过单独视觉识别模型读取。

`image_edit.editRegions` 支持归一化多边形轮廓局部编辑：第一张参考图作为原页，仅采纳轮廓内的生成结果，区域之外逐像素保留原图，输出无损 PNG，并记录保护像素与修改像素数。轮廓定位与区域内人物、文字是否正确仍需视觉检查，不能仅凭保护像素数宣称整张图符合需求。无需编辑的页面使用 `image_export` 原样交付，不调用或计费生图模型；导出也要检查本页是否确实无需替换。批量交付按书名与页码命名。

规划与验收按用户的实际保留要求区分语义保留和严格原样保留。普通任务未明确要求完全不变时，可以接受符合意图的细微调整，不能自行把“保留背景”等表述升级为零像素差。用户明确要求完全不变、一模一样或指定区域不得改动时，这些范围仍须严格保护；其他区域允许微调不能放宽指定保护区。身份、正常人体结构与自然融合仍须检查。本次95页人物替换仍要求其它内容原样，用户后续明确允许新人物轮廓自然变化及邻近遮挡变化；保护范围按这一明确授权规划，不扩大为整页背景或道具重绘。通用微调规则本身不能放宽本批次标准。

局部编辑前必须调用 `image_edit_preview`，实际查看本页全图和编辑窗口的覆盖预览。绿色表示后续会采纳生成结果的像素，蓝色表示合成时保留原图的像素；目标的躯干、袖子、耳朵和头发要完整覆盖，背景、道具和非目标人物要排除。工具按持久 `referenceImageId` 重新检查权限，返回原图尺寸、来源摘要、精确轮廓摘要、覆盖像素数，以及预览窗口与原图的坐标映射。两张本地 PNG 的最长边均不超过 1600 像素，图例位于图片内容之外；传给模型时采用有界 JPEG 预览。后续生成必须使用同一来源 ID 和同一轮廓，且在预览之后的模型轮次执行；同一模型响应同时提交预览和生成会拒绝，避免尚未看到预览就预先生图。修改坐标后重新预览。预览工具不调用图片生成服务、不保存新图片、不写入图片资产；模型查看预览仍属于普通视觉请求。预览回执和轮次检查仅证明执行顺序符合预检要求，不是轮廓正确或图片质量通过的证明。

轮廓严格使用简单多边形：拒绝自交、非相邻边接触或重叠、零长度边、相邻边回折重叠和退化面积；允许简单凹多边形和沿直线继续的顶点。闭合边由最后一点自动连接首点，显式重复首末点会拒绝，不会悄悄删点或修复轮廓。已保存的无效生成事实也不能绕过校验进行验收；原文件、候选图和原始记录保留，不转换旧数据。

图片模型通过已实现的 `imageProfile` 支持清单选择协议和能力。`image_generate` 只接受文字，`image_reference_generate` 接受参考图，`image_edit` 要求明确的底图 `sourceImageId`；默认共用一个图片模型，也可按三个工具分别覆盖。旧配置按 2026-10-05 用户已批准的默认读取规则处理；实际部署 ID、地址、密钥、历史图片和累计次数保留，旧 `imageEditApi` 不再参与执行。支持范围、旧配置审计与验证边界见[图片模型适配器](ai-image-models.md)。

各协议共用预览、局部窗口和原图恢复流程。原窗口按输出比例加边，生成后去边还原，避免把人物拉伸到模型画布比例。原生 Seedream 整页参考编辑未显式指定 `size` 或 `aspectRatio` 时，按第一张原页的显示方向与比例选择合法高分辨率，宽高不低于原页；不能同时满足原比例、原分辨率和模型范围时，在预留尝试及计费之前拒绝。显式尺寸或比例优先，文生图仍使用模型配置。已知 GPT Image 模型使用同尺寸的透明编辑蒙版；Seedream 5.0 pro/flash 使用官方归一化坐标提示；其他参考图模型使用临时可见轮廓。原图不加标记。蒙版和定位提示不代表模型能严格遵守边界，因此仍以原图像素保护和实际结果验收为准。`referenceCrops` 可选择六视图中的相关视角，只用于第 2 张及之后的参考图，持久 ID 对应的完整原图保留。

所有新的正式图片生成成果统一保存为无损 PNG，实际编码、MIME 和文件扩展名一致；原始候选仍保留厂商的原始 PNG/JPEG 字节，不转换旧成果。25MP 解码限制、20MiB 保存限制和存储额度照常核验。局部编辑适配的动作、姿势和朝向遵循用户明确修改目标；未要求改变时保留原意，不以适配提示强制固定姿态覆盖用户请求。

每张生成图保存实际提示词、来源 ID、编辑轮廓和参考裁切记录。接口显式返回非负安全整数 `usage.input_images` 时，另存为原始调用事实 `providerImageUsage.inputImages`。要求使用参考图而服务明确报告为 0 时，候选直接标记不合格，停止本任务继续生图及额外视觉验收费，保留已发生用量、图片和失败证据。缺失或无效的统计不视为 0，也不能据此断言接口确实使用了参考图。

新的图片调用在裁切、原页恢复和局部合成之前，独立保留厂商原始候选及严格 `version: 1` 回执，记录来源摘要、实际工作空间、坐标映射和厂商用量事实。原始候选是私有过程资产，不进入普通文件列表、最终交付或人物身份参考列表。后续合成、保存或取消失败仍保留已确认的原始候选和实际费用，不能因为最终图片失败就重复付费生成。旧调用没有原始候选时明确拒绝重合成，不从临时文件自动回填旧记录。

`image_candidate_view` 只读查看绑定原页、厂商原始候选及原页坐标投影，最多发送三张有界预览；检查点只保存事实，不保存位图或存储密钥。实际生成窗口之外的投影来自原页，不能声称那里已重新生成。看过候选后，之前的轮廓预检失效，调整轮廓并重新 `image_edit_preview`，在后续模型轮次用 `image_recompose` 复用同一候选本地合成，不产生新的图片模型调用或图片费用。两项工具重新核验账号、会话、原文件权限、原始字节摘要与任务租约；本地保存仍受存储配额约束，失败或无法确认事务状态时保留可核对事实。复用不会修复原始候选本身的人体、身份或姿态缺陷，仍须独立看图验收。 整页原始候选按实际旋转后尺寸检查与源页的比例，偏差超过1%时，在首次写入和配额预留前拒绝重合成，不把方形图非等比拉成竖页；候选与费用仍保留。局部候选沿已记录工作窗口恢复。

复杂的手与道具交错可使用独立的 `image_mask_prepare` 与 `image_mask_compose`。准备工具将原人、新人、保护物、允许遮挡与改字区分别用显式 proposalIds/include/exclude 选区栅格化，保存严格 version:2 回执；旧 version:1 回执保留并拒绝，不补缺字段或转换；保留孔洞和不连通部分，不转换旧回执、不补造旧 raw。允许遮挡仅能位于新人和保护物的交集，不能碰改字区；剩余保护冲突会阻止保存，不自动减保护区裁断新手。先实际查看同页原始候选，后续轮次准备蒙版，再实际接收完整全页和局部覆盖诊断，下一轮才可免费合成。两个诊断帧原子传输，文字、坐标或缺帧不能代替实际看图证明。回执每次重新核验会话、权限、源页/raw摘要、坐标变换和二值蒙版摘要；免费保存仍受租约、取消、存储配额与事务检查约束。数学无冲突不证明真实人物覆盖、身份、姿态或自然融合正确，语义覆盖始终标为未验证，成果仍需独立验收。

独立验收的每一组视觉请求显式绑定宿主确认的来源书名、PDF 物理页号、来源 ID 与成品来源；相同插图出现在不同 PDF 时，仅按本书本页与全局原始要求检查，不套用另一本的动作或文字修改。缺失或非法来源范围在视觉计费前拒绝。该运行时信息不修改持久批次格式或用户要求。

批次中的图片初始为「待验收」；执行者报告通过时，独立视觉请求读取原图、实际保存图和人物参考，以用户原始要求及亲自确认的澄清为最高依据。生成提示词、文件内容和执行者备注不能把「真人替换」改为卡通化，也不能为了保留卡通表情而接受异常口舌、五官或身体结构。局部编辑同时对照最长边 512 像素的全页和最长边 1600 像素的同坐标局部；人物参考按持久 ID 明确标出「生成时图 N」与「验收 Image M」的对应关系。验收必须逐项覆盖目标修改、非目标保留、自然融合和文字四类，以及服务器保存的全部验收标准索引，遗漏、重复或未知项目均拒绝。它使用新的上下文，不采信执行者自述。无法看清、响应无效或缺少有效生成输入证据时不通过。纯视觉模型可以执行此检查，无需支持工具调用，仍遵循账号权限和 AI 用量策略。

需要原生细节验收的大图及局部编辑，须完成宿主规划的全画幅重叠检查。有后续细节计划，或用户标准采用语义验收时，全局检查的原图、成品前两帧使用最长边1600的JPEG Q92/4:4:4有损构图预览，身份参考仍为PNG；所需的细节块仍按原生尺寸传输完整无损PNG。没有后续细节计划的原生精度检查继续使用PNG。有损预览不能证明像素原样，压缩不修改原图、候选或交付文件，不减少已有细节覆盖。

页面分析同时核对原页与必要的邻页；只有原页全部像素严格为不透明纯白时，才省去邻页画面，防止把邻页人物误认到空白页上。近白、透明或含任一非白像素的页面均继续按普通页分析。正式要求若包含在空白页添加内容，仍须执行并独立验收，不自动导出或判定合格。后台失活检查同时采用本任务模型请求的实际开始、完成时间；连续分析和验收不因缺少新工具检查点而误停，任务取消、租约丢失及实际失活仍会中断执行。

已推进到后续书册或整批完成后发现旧页缺陷，可对该页最新交付显式调用 `image_batch review`、`passed:false` 并记录实际缺陷，重新打开对应书册返修。当前页或已完成页才能负验收；过期资产、未知页、尚未开始的后续书册拒绝。正向验收仍只针对当前书册，并执行独立视觉检查。回退保留原始要求、完整来源、冻结标准、attemptScope、全部交付和其他页验收；不重建尝试范围、不清零费用或重复生成已合格图片。返修后再逐书 advance，已有通过结果继续复用。

当前资产已通过时，重复正向提交复用原验收。当前资产已有失败结论时，不把执行者改为 `passed:true` 当作通过，也不永久返回旧失败：先单独 `image_view` 同时查看该页原图和最新成品，完整帧实际送达后的后续模型轮次可申请一次独立重新验收。该运行时许可绑定当前失败、原图和成品字节，消费后不得重放；缺帧、同轮查看与提交、资产变化或期间新增失败均拒绝。重新验收使用当前实际图片和原始冻结标准，可能产生视觉模型费用；没有新的完整实看时不重复计费，不转换旧验收或重建付费次数。

编辑规划先按用户目标选择方法：动作、姿态或背景等任务明确允许自然重绘、仅要求语义保留时，保留原页 `referenceImageIds`，可省略 `editRegions` 做整页图生图，避免把新动作压进旧人物轮廓。只有明确要求特定范围严格原样或局部精修时才用精确蒙版；文字编辑区域必须容纳新句完整宽度。保持原页画布时省略 `size` 与 `aspectRatio`，由宿主按第一张真实来源图确定尺寸与比例，不按外观猜成3:4等常见比例；只有用户明确要求新画布才指定尺寸或比例。不能去掉原图参考转为文生图。严格其他内容原样的人物替换仍执行既有范围保护，不能借此放宽。

同一页的动作、人物和正文先合并为一次完整编辑。`image_edit` 的额外参考图不是实际底图：局部选区外恢复的是 `sourceImageId` 所对应的图像。因此从冻结原页仅框正文返修，会还原上一轮的新动作；允许整页编辑时，将当前成品作为额外参考并重申全部累积要求，不能冒充已经支持直接在成品上累积编辑。严格范围保护时，内容生成与最终像素保护分开，新人生成后才依据原人、新人及允许的邻近变化确定最终覆盖。可信分割可用时优先使用实际原页/raw 的提案及蒙版，避免粗多边形剪掉新人部位。所有结果仍须通过原始要求的独立验收。

继续执行、模型切换、技术恢复或重申已确认角色不新增批次要求绑定，也不清除已有验收。切换书册时 `task_plan` 可以更新步骤，验收标准始终采用当前批次已冻结的完整标准。完整真人替换要覆盖所有原本可见的目标部位；服装颜色、款式和标志的保留，不表示可以保留卡通身体而只替换头像。

整页候选只有一个额外相邻原页参考时，宿主根据同一冻结PDF、实际派生来源、物理页序、文件字节及权限确认场景关系，让每个人物身份核对组都同时收到该相邻页。相邻页仅作为场景资料，不声明肢体归属，也不授权替换其中人物。局部编辑或多个相邻页仍明确说明无法共享此上下文，不声称读过未送达的图。全局检查通过后，原生细节检查每波最多并行两次；已发出的同波调用均完成并保留真实用量，失败阻止后续波次，所有覆盖块通过才允许交付。

预检拒绝编辑或重合成时，`next.input` 返回该次实际原页与完整轮廓；恢复不得改名、舍入或重排坐标。只有同一来源字节、同一轮廓的两帧实际完整送达并正常响应结束后，才清除对应操作的预检失败计数；少帧、同轮、来源变化及忽略恢复仍拒绝，尚未调用图片模型或新增图片费用。

批次最新候选验收失败后，再次付费生成前必须在当前执行过程先用 `image_candidate_view` 查看该交付资产绑定的原始生成操作，并在后续模型轮次决定是否重生成；同轮并列查看和生图不算读过。查看事实只留在本次执行内存，不写入批次格式，也不从旧回执补造 raw。原始内容正确而覆盖裁错时，复杂轮廓优先分割原人和新人，实际核对完整蒙版诊断后免费 `image_mask_compose`；明确简单轮廓才预览后免费 `image_recompose`。原始内容本身不合格仍可重生成，旧生成提示中不符原意的结构、角色或位置也应纠正，不能当作新增用户约束继承。明确的 `reference-export` 原样导出没有付费 raw，首次付费编辑不要求查看不存在的原始候选；`local-recomposition` 按其原始 `generationOperationId` 与 raw 指针核验。

查看许可在最终请求完成范围筛选、每轮四张图限制、预览压缩与上下文裁剪后核验：候选诊断或覆盖预览的两张图必须完整进入同一轮请求，部分图片被省略、替换或损坏时不会记为已查看。候选的当前渲染显式声明三或四帧；有唯一真实相邻原页时，整页和局部候选都保留原页、raw、坐标投影三帧，再附相邻原页作为第四帧。相邻页独立标注自身持久ID、物理页、坐标和来源，仅作场景资料，不能冒充本页投影、人物身份或用户授权。三或四帧作为完整一组选择，剩余预算不足时整组不发送；历史缺少当前声明的输出不默认三帧、不重建查看证明，原事实和文本保留，可重新读取。工具明确列出本轮已传及未传帧，缺失候选用同一 image_candidate_view 单独重查。每张实际图片前附有界来源标签；标签被预算删除或修改时也不登记已查看。用于最终传输证明的内部帧摘要只在运行内存中核对，不新增批次持久字段；媒体生成前后及后续使用都重验场景权限、字节和冻结页序。流式响应在成功结束并完整读到流尾后才提交实际查看事实，再按原顺序释放完整工具调用和能令宿主合成调用的 `tool-input-end`；此前的文字、推理与参数片段继续流式显示，图片生成不会因此新增调用。响应失败、取消或传输中断时许可失效，两种等待中的可执行边界都会丢弃，不执行工具。

未验收和不合格候选保留在任务过程记录，通过的批次成果进入最终图片交付。再次展示图片保留已记录的验收状态。同一批次正式原任务的同一来源页默认最多提交五次付费图片请求，通过服务器环境变量 `DOCA_AI_IMAGE_MAX_ATTEMPTS_PER_PAGE` 设置正安全整数上限，重启生效；0、空字符串与非法值拒绝启动，没有无限开关。按宿主持久尝试范围跨续跑、重试及重新登记计数，改变提示词不能绕过限制，调整上限不清零。降低上限后，序号超过新上限的付费回执或进一步付费请求明确拒绝，原记录保留。已预留、结果或费用待核对的请求也占用次数，实际厂商用量另记，不推断无响应请求免费；原样导出和本地重合成不占用付费尝试次数。普通非批次图片重试沿当前任务真实重试链及已授权关联任务计数，使用同一配置上限；无效编辑路由、认证失败和请求过大直接停止任务。已保存图片及失败证据保留，后续调整方案不放宽用户标准。

后台任务的 15 分钟限制改为无进展超时：持续产生模型流、工具回执或图片的任务不因总时长超过 15 分钟被取消。每次图片请求仍有独立超时，并保留费用核对及重复调用保护。

历史压缩使用固定 `@mastra/memory@1.29.0` 补丁：观察保存后，反射读取实际已提交记录，核验来源、游标、观察 ID 和 token 事实，避免旧快照使游标倒退。宿主按当前已提交 generation 的摘要和游标判断真实推进；原消息和旧观察记录保留，不修补或迁移。当前输入在完成现有来源授权与上下文构造后、压缩调用前执行原有的单次消息保存，压缩失败后刷新仍可看到对应输入和失败任务。补丁由 `pnpm-workspace.yaml` 与锁文件登记，干净的 frozen 安装同样应用；它不适配其他 SDK 版本，不修改消息或观察表格式。

## 复杂任务与分批执行

复杂任务先记录完整意图、范围、执行步骤和可检查的验收标准，只询问影响正确交付的关键歧义。当前书册先分轮核对全部原页、已确认角色及故事关系；跨页连续场景和边缘部分身体结合相邻原页辨认归属，不将同一已确认角色在后页随意当成非目标。人物完整替换指原构图中实际可见的目标部分，不强行补出原先在页外或被遮住的头脸、身体；明确要求新增或改变构图的任务仍按用户原文执行。场景、动作、风格与真人身份参考分别核对用途，验收不预设所有生成参考都是身份图。分批是执行方式，不改变原始交付范围；已成功操作保留回执，失败从未完成项恢复，最终仍按原标准核对全部成果。现有独立验收流程保留，不能由执行者自行放宽标准或以文字自述代替成果。

原页规划的提示词明确区分输入资料与输出事实：只能返回规划 schema 的八个顶层字段，不回显绑定、原请求或 schema。引文索引指向正式用户请求数组，同一请求中的多个句子仍使用同一来源索引。缺字段、非法引用或输出截断继续拒绝，不自动补空数组、改写引用或把未完整读取的规划当作有效事实；输出格式纠正不代替图像质量验收。

首次独立验收返回不完整、非法 JSON 或不符合严格 schema 的记录时，不将成品登记为通过或质量失败，也不为此重新生图。宿主向执行器提供当前原页与成品的精确 ID；两张图片须实际完整送达、模型响应成功结束，再于后续轮次重新独立验收。同一来源、成品、反馈与冻结要求下，累计三次无效验收报告后停止，重新看图不清零次数。连接、权限等其他首次验收失败停止，不自动重新排队重复验收；原图片、反馈及每次真实调用的用量记录保留，未知用量仍未知。完整响应仍须严格解析，不删除多余字段、修补模型 JSON 或降低原生细节标准。

`image_batch` 本次宿主发行的 `image_review_requires_fresh_view` 恢复回执可直接附当前原图和成品两帧，减少执行器忽略 `next` 后重复请求的停滞。只有运行内存中登记的原回执对象和未变摘要能附图；复制或篡改回执不能授予证明。渲染时重新核验账号权限、当前书页与资产、冻结要求、验收反馈及两份实际字节。两帧按完整一组发送，剩余预算不足时全部扣留；完整响应结束后才登记证明，后续轮次仍需原有独立验收。过期回执保持旧 JSON，不覆盖较新的真实判决；普通状态和其他错误不附图。展示本身只读，不调用验收模型、不新增生图请求、不清除无效报告次数或原失败记录。

当前最新图的内容失败与验收未完成分别反馈。手动验收返回准确绑定的实际结果，后续请求突出当前资产的原缺陷及诊断返修下一步；有效 raw 回执只提供 `image_candidate_view` 指引，不授予查看、编辑或遮挡证明。执行器按实际图片、正式原要求及用户澄清自主返修；完整新原图/成品对照后如有可核实反证，仍可在后续轮次请求独立复审，不强制重报 `passed:true`。没有新实看证明的连续三次复审请求仍停止；新资产不继承旧图的缺陷或通过结论，必须完成自己的首次独立核验。上述反馈只用于当前运行，不更改持久批次、验收结构或历史记录，不自动调用生图服务。

多文档逐页图片任务使用 `image_batch` 登记完整来源清单。服务器保存书册和页码、已保存图片 ID、逐页验收证据；只有当前书册全部页面有保存回执且最新结果通过验收才能切换下一本。批次切换保留任务约束和用户已确认的信息，检查点移除已完成书册的视觉调用，交付清单仍可重新查询。重复提交已验收页直接返回保存成果；保存但未验收的页先检查，失败才允许修正重做。其他复杂任务按自身依赖规划，不强制采用书册/页面流程。

当前书册同一原页可用 `image_batch` 的 `action:"select"` 与 `candidate:{referenceImageId,assetId}` 选择之前已保存的较好候选。宿主核验账号、会话、当前批次尝试范围、实际生成回执和持久原始候选绑定。首次只返回实际查看参数，不更换交付；原页与待选图两帧完整送达、模型响应成功结束后，后续轮次再次以同一候选选择才切换指针。候选、来源字节或当前绑定变化时旧证明失效。同页旧验收失效，必须按正式原文独立重新验收；其他页、所有旧图片、生成回执和累计付费次数均保留。选择不是生图，也不能使已用完额度的页获得新次数。

当前批次状态返回 `deliveries`，按书册和物理页列出最新资产对应的真实文件节点 ID、名称、文件夹定位 `href` 和文件下载地址。生成图和原样导出图均位于统一文件管理的 AI 会话目录；图片资产 ID、文件 ID 和在线文档资源 ID 不可互换，不能把资产或文件 ID 拼成 `#/r/`。读取交付节点时重新检查账号、会话及未删除状态，缺失或歧义明确拒绝，不补造或回填文件记录。完整链接清单不重复放入每轮受保护提示词，避免放大上下文。

整批完成时，宿主直接按顺序发布全部最新成果的原生文件卡片，复用既有文件事件和文件管理预览、下载地址；模型正文无需重复数十条长链接。重复查询且文件卡片字段未变化时不重复发布，名称或路径变化时更新对应卡片，不复制图片、不改写历史消息或创建替代文件。

执行器在同一后台任务内继续未完成批次的正常执行分段，包括工具步数、输出长度用尽或提前文字结束；这些分段不消耗独立验收的三轮返修机会，保留原任务、范围、已保存成果和付费次数。整批完成后才进入独立验收。真实提问、待授权、取消、租约丢失和调用失败仍停止或暂停；连续三个分段没有新的宿主进度、有效读取或实际视觉证明时明确停止并保留成果，重复状态查询和文字自述不算进度。该执行机制的隔离回归已通过，真实全量任务仍须另行验收。

整批已保存且最新验收全部通过后，仅开放状态、既有结果展示和资料读取；真实新缺陷通过最新资产的负验收显式重开书册，后续模型请求才恢复生成、分割及重合成工具，同轮隐藏工具调用不得计费或写入。

批次记录使用严格的 `version: 3`，必须有 `attemptScope: {version:1, operationId, taskRootJobId, manifestDigest}`。宿主在用户锁事务内建立独立 `image_batch_attempt_scope/version:1` 操作记录，绑定正式原任务根 ID、账号会话、冻结原文件及完整原页清单；同一原任务重新登记仍使用同一范围，不能重置次数。图片请求只接受宿主验证后的范围，模型输入没有范围字段；生成初始事务再次核验持久批次、当前来源页和权限，并将严格 `paidAttempt/version:1` 事实保存在初始、成功及失败回执中。不增加数据库列，不转换原始用量或 raw 候选记录。先用 `image_batch requests` 按所选附件、文件或原始文件夹引用分页查询正式用户请求，执行者显式指定 `taskJobId`，由服务器读取原始 `ai_jobs.input.text`，同时保存用户消息 ID、重试来源 ID、完整原文、初始来源关联及冻结验收标准。服务器不把最新的「继续」「Kipper」或最早一句自动认作原任务，不读取工具内容或执行笔记来代替用户原文。正式后续确认通过 `image_batch bind` 明确绑定原任务、用户消息 `jobId` 和作用域；有 `ask_user` 提问时核验真实提问回执与任务关系。`batch` 仅用于本批次明确确认或变更；`general` 是未来通用指导，不进入本批独立验收，也不能放宽本批严格要求。已绑定原文、作用域、来源与冻结标准不能静默改写。

`image_batch start` 必须指定 `scope: "all-documents"`。服务器枚举原请求全部实际输入，以文件格式识别 PDF/Office 目标、图片参考和其他上下文，并冻结完整输入清单；登记的 `sources` 必须精确覆盖全部目标，遗漏一本或加入参考图片都拒绝。`requests` 返回完整的 `allDocuments.targetSources`，不按人物外貌、亲属或任务文字猜测目标。目前批次工具只支持原请求的全部文档；文档子集任务使用普通图片工具，没有未经独立范围核验的子集批次入口。

查询 `requests` 时同样显式提供 `sources`；缺少参数是模型调用错误，回执要求从当前附件清单补齐，不能要求用户再次上传或确认已经明确的范围。首个完整请求启动时省略 `clarifications`，原任务自身不能作为后续确认。执行器已经尝试按完整范围启动而启动失败时，本次运行禁止绕过批次直接调用普通生成、编辑或导出工具；资料读取仍可用，修正参数后可以重新启动批次。该门禁只记录本次执行状态，不新增或转换持久批次和任务格式。

新消息引用 Doca 文件或文件夹时，由服务器依据原有个人、共享、公开、知识库和文档目录权限生成独立 `version: 1` 输入快照，保存全部文件 ID、存储对象 ID、版本、MIME、文件名和原输入关联，不受列表显示数量限制。客户端展示名称不能成为文件事实，也不能提交自造快照。同一请求重发和正式重试保持原快照，不把后来新增的目录文件混入；读取冻结文件时重新核验权限及对象、版本、MIME、文件名，变化后明确拒绝，不能默换新版。旧请求有文件引用但缺少有效快照时不自动回填或扫描当前目录来替代原输入。

当前 v3 图片批次在每次执行模型请求前，由宿主对当前书册新保存、尚无匹配最新资产验收的候选自动调用独立视觉验收。它读取实际原页、成品、参考与冻结本书本页标准，只有真实判决可以写入 latest review；不依赖执行者先声明通过。已有最新通过或失败不自动重复审查，显式重复请求正向验收也复用当前判决；旧资产的验收不能覆盖新候选。失败后仍须实际查看绑定 raw 并在后续轮次返修，不能自动生图、跳过页面或推进书册；原导出页也须按本书本页任务核验是否确实无需修改。审批、用户澄清、权限请求或未知付费结果会停止执行；原始用量事实、累计次数和全部页通过门禁保持。独立验收消耗配置视觉模型的正常用量，不增加图片生成次数。全局/身份组先检查完整页面和实际参考；大页或局部窗口通过后，必须再完成整画幅重叠原生PNG细节覆盖，逐块核对小人物数量、遗漏目标、动作、文字、非目标内容与边缘。每块长边最多1536像素，每次一对原图/成品并附两张512全页定位PNG，共四帧，最多16块、16次细节调用，全部原生覆盖不抽样；任何必需块缺失或失败都不能通过，全局或当前块失败不追加细节费用。1780×2357页面需要4块、4次细节调用，1500×2000页面需要2块、2次。源/成品相同的原样导出仍须核实是否遗漏任务要求，不能仅凭字节相同跳过大页细节。发现最新通过图仍有真实缺陷时，可对该asset显式负验收返修；修改工具在此之前明确拒绝，不返回旧图冒充新修改。

独立验收和续批读取持久原文及本批确认，不依赖最近六条消息、压缩摘要或浏览器临时状态。本轮真实用户输入另作为正式用户段传给模型，恢复批次或切书不丢失返修反馈；涉及批次澄清或验收标准变更仍须显式 `bind`，不自动改写冻结标准。最终请求的预算压缩保护宿主注入的正式原文、标准及本轮消息，只压缩执行历史；完整来源段与必要尾部无法同时容纳时，在计费前拒绝，不静默丢掉用户意图。新增本批确认保留已保存图片，但使旧验收失效并重新逐页核验，不自动重生图；通用指导不清除本批验收。旧 `version: 1/2`，以及缺少有效请求、完整范围或持久 `attemptScope` 的 `version: 3` 记录会列为不可续批，原文件、图片和原清单保留，禁止自动转换；需要依据持久原文件及正式原请求显式重新登记。本次原 95 页清单仍保留，原验收为零编辑页通过，重新登记不会使它成为已交付，也不能降低原始严格标准。

用户可以一次上传所有文件；每轮模型读取最多四张当前图片，未展示页明确标记并通过 `image_view` 继续读取。视觉传输使用完整构图的 JPEG 预览（最长边 1600 像素），原文件和页面 PNG 保留；较早像素与工具媒体不重复塞入请求或检查点。当前书册只发送相关工具，避免携带无关工具手册。

## 公开实践依据与验收边界

[Codex 的公开 agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)介绍工具执行循环和上下文压缩；其中 Responses 的专用压缩接口是特定 API 能力，不能假设任意兼容网关也支持。Doca 当前使用可重读的来源 ID、工具回执及按书册缩减的上下文，避免把全部位图复制进每次请求。

[Anthropic 的上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)推荐按需读取和结构化笔记；[长期任务实践](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)使用完整需求清单、增量进度和实际测试避免过早宣布完成。[Claude Code 的验收实践](https://code.claude.com/docs/en/best-practices)强调可执行检查和独立复核。这些做法用于 Doca 的完整清单、检查点和实际图片验收。

[Cursor 的规划文档](https://cursor.com/docs/agent/plan-mode)说明先调查关键歧义并保存计划；[Kimi Work 的 Goal Mode](https://www.kimi.com/en/help/kimi-work/goal-mode)描述持续按固定成功标准推进。[Kimi Code 的媒体读取工具](https://moonshotai.github.io/kimi-code/en/reference/tools)将图片作为真实多模态内容读取，并按模型容量压缩。这支持将任务范围、材料存储和单次模型上下文分开设计，而不是要求用户反复重传。

图片协议参考 [OpenAI 图片生成与编辑文档](https://developers.openai.com/api/docs/guides/image-generation)及 [Seedream 编辑指南](https://docs.byteplus.com/en/docs/modelark/seedream-5-0-pro-editing-guide)。这些公开资料不能证明 Codex、ChatGPT、Claude Code、Cursor 或 Kimi Work 的所有内部图片服务实现相同。
