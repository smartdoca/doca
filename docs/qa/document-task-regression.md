## 文件识别的统一实现

`apps/server/src/services/ai/file-recognition.ts` 是共享入口，聊天附件、AI 的 `file_read` 工具和文件夹 AI 扫描复用同一解析及策略，不再各自维护识别分支。

- Markdown/文本、DOCX 等优先原生提取；文字 PDF 使用 PDF.js 正规解析，包含中文 CMap/字体支持。
- 扫描 PDF 或含视觉内容的页面先渲染为图片，交给配置的视觉模型；文字密集内容要求逐字转录、保留表格/金额，照片和图表要求描述内容。当前 OCR 是视觉模型转录，**没有接入独立 OCR 引擎**。
- 场景区分正文读取与搜索描述：正文读取不能用摘要冒充全文；文件夹索引允许描述/摘要。聊天视觉模型可直接接收提取的文字与页面图片，避免重复视觉调用。
- 缓存版本升级，旧 PDF 乱码缓存失效；不再把旧文本在 pending 状态下交给模型。保持页面顺序，缺页、截断、图片遗漏、未配置视觉能力、OCR 关闭等返回明确限制。
- `file_read` 以文件权限校验为前提，返回正文、状态、警告和 nextOffset；后续分页仍验权。不能将文件 ID 当作文档 ID 读取。
- 识别源文件内容作为资料处理；不执行文件内的指令。

## 其他落实的可靠性修正

1. 同一工具同样参数连续失败 3 次时停止无意义循环；修正参数可继续，成功后清零。该保护在本次运行内生效，跨服务重启不持久化计数。
2. 明确表格单元格模型输入结构，避免 null 空调用；保留公式及样式。
3. PDF 导出生成有效的 Type0/CID 字体结构、分页、表格线及文字布局。
4. 原生 PPT 用准确文本替换接口修改现有文字，保留元素和样式，不传 SDK 不支持的 paragraphs 补丁。
5. 保存回执验收、恢复后的成果分类及编辑报错引导改进。纯回读验收不应要求为了获得回执而修改文件。
6. 收紧图片成功声明判断，普通「工具返回成功」不再误触发图片验收；对应反例已回归。
7. 搜索的辅助结果不应变成所有创建任务的最终文件交付。当前意图判断仍为规则式，需要后续扩充混合/否定语句测试。
