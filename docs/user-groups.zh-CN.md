# 用户组与组授权

[English](user-groups.md)

用户组入口位于侧栏「共享文件夹」下方。列表展示自己加入的有效组，包含头像、组名称和所有者；组内展示全部成员及角色。内部 ID 不作为页面信息展示。头像可上传并裁剪为 PNG。

## 成员与角色

所有者和管理员可以搜索用户发送邀请，或生成七天有效的邀请链接。新成员必须登录并主动接受，始终以普通成员加入。名称邀请沿用现有用户目录校验；在「相关权限用户」范围下，同一有效组成员也构成关联。组内成员列表按组成员身份可见，独立于全站候选用户搜索范围。

| 操作 | 所有者 | 管理员 | 普通成员 |
| --- | --- | --- | --- |
| 查看全部组成员 | 是 | 是 | 是 |
| 编辑名称、头像；邀请成员；撤销邀请链接 | 是 | 是 | 否 |
| 移除普通成员 | 是 | 是 | 否 |
| 设置或取消管理员、移除管理员 | 是 | 否 | 否 |
| 交接所有者、解散组 | 是 | 否 | 否 |
| 退出组 | 先交接 | 是 | 是 |

所有者仅可交接给组内正常使用的成员。管理员不能操作其他管理员或所有者。邀请接受时重新校验邀请人当前身份、账号状态、有效期及组状态。邀请链接只存哈希，重建或撤销后旧链接失效。

## 资源权限与邀请制

文档、知识库、知识册共用宿主资源权限；共享文件夹及其下文件也支持组权限。在「邀请协作者」内选择「个人」或「用户组」，上方输入名称搜索并选择，下方授予权限。协作者页只展示和管理已有个人、组授权，不展示新增授权的搜索表单。插件自有权限适配器不自动获得新的组接口。

每条已生效组授权默认只展示前 3 位正常成员的头像，悬停或激活头像可查看现有用户卡片。「更多（+人数）」在浮层内展开更多头像，可继续分页，不增加授权行高度。成员读取沿用当前资源的管理权限，并重新检查该组授权仍有效；未接受的新组邀请不展示名单。成员接口只返回显示所需身份与头像，卡片复用现有用户资料接口，不开放外部组管理页。

个人与组授权共用两行的公共授权行组件：第一行左侧头像、名称，右侧权限选择和删除图标；第二行放账号、来源或组成员头像，右侧放「包含子文档」。个人另有权限来源入口。删除使用按钮旁的气泡二次确认，取消不写入，失败保留气泡与当前位置。知识库及其文档可单独调整「包含子文档」，修改角色时默认保留该范围。知识库管理权限下限在子文档中只读，需要回到知识库调整；资源管理者不能修改管理授权。

个人授权和用户组授权按用户确认继续独立计算，取最高生效权限。只有组来源的个人行仍可新增个人授权；没有个人来源时，个人删除按钮不可用，应在对应组行撤销组来源。个人角色低于其他来源时显示生效权限，信息入口列出所有权、个人、继承、链接和组来源。普通继承的个人授权可在当前文档覆盖或取消，库管理下限保持原规则。共享文件夹沿用现有个人共享聚合记录，链接加入标记展示在该个人来源上，组来源单独列出；不会凭空拆分历史个人/链接授权。只有资源管理者可枚举组来源的协作者。

文档类资源支持阅读、评论、编辑、管理；共享文件夹支持阅读、管理。只有资源所有者可授予或调整管理权限。组角色与资源角色独立：普通组成员也会获得组已被授予的资源角色。

组授权独立保存，运行时按当前有效成员关系计算，不复制为个人授权。个人授权、各个组授权、链接和公开访问分别计算；移除个人权限不会自动撤销组来源。组权限遵守资源继承边界和下级范围，库管理权限沿用现有管理下限。

沿用资源邀请策略：直接模式即时生效；邀请模式的新授权、升级或扩大下级范围，需组所有者或管理员接受。接受时重新校验邀请人当前资源权限、授权能力和当前组成员准入限制。退出、移除成员或解散后，对应组来源立即失效；用户仍可能通过其他独立来源访问。已连接协作会话重新鉴权；搜索和知识索引重建，知识查询返回前也检查当前权限。

资源所有权交接不改写组授权。旧所有者选择不保留个人管理授权后，仍可能通过组访问，界面会提示。后台停用账号的资源交接清单包含其拥有的组；接收人必须已是该组有效成员，预览后成员变化会使执行失效。

## 用户组搜索范围

管理员在后台「权限与可见性 → 用户目录」配置独立组搜索策略，可设站点默认并按用户覆盖，初始为「仅自己所在的用户组」。

| 范围 | 可以搜索的组 |
| --- | --- |
| 仅所在组 | 自己当前加入的组 |
| 所在组和有权限交集的组 | 所在组，以及与自己对同一文档、知识库或共享文件夹拥有显式权限的组；包含有效继承，公开可见不算关联 |
| 所有有效组 | 所有未解散组 |

搜索只返回组 ID（内部选择用）、名称、头像和所有者名称，不开放外部组成员页。组获得资源权限后，成员成为资源协作者；资源管理者可在权限页查看有效协作者，用户目录也会按已有显式权限交集规则建立关联。这与直接查看外部组成员页是不同入口。后端重新校验新授权的组范围，不能通过提交越界 ID 绕过。收窄范围不撤销已有授权和邀请，资源管理者仍可移除已有组授权。分页游标绑定用户、查询条件和策略版本。

## 解散与清理

解散事务先标记组失效并刷新关联资源权限。服务启动时及每小时清理一次：清理超过 24 小时的已解散组关联，单批最多 100 个。删除成员、邀请、链接与组授权行，保留组失效记录及安全审计。关联正文、个人授权和其他链接保留；`cleaned_at` 防止重复处理。

## 已批准的升级

按最新 DDL 与 `schemaEvolution` 新增八张表，兼容代际不变。组、成员、邀请、链接、两类组授权和资源邀请七张表从空开始；独立策略表首次安装明确写入 `system/member/revision=1`，用户覆盖从空开始。原有个人/链接授权、邀请、公开设置、用户目录策略及数据不转换。已安装后的策略行丢失会报冲突，不静默重设默认。

部署前备份数据库、文件卷与原配置，所有服务实例及 Web 同步更新。旧二进制可能拒绝新结构；降级须另行评审保全与恢复方案，不通过删表、重置或丢弃新写入降级。见[验证记录](verification/user-groups-2026-10-30.md)。
