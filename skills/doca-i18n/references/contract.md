# 界面语言

第一版支持中文和英文。以后增加语言时，只加语言代码和对应字典，不改 key，也不改调用方式。

界面文案用英文 key。中文、英文和其他语言都是这个 key 的译文。不要用中文句子或整句英文做 key。

Doca 仓库里的 `docs/i18n.md` 是这份约定的源文件。子包安装本 skill 后读这份副本。修改约定时，源文件、本副本，以及每一份已安装的 skill 要一起更新。

## 语言代码

| 代码 | 含义 | `html lang` |
| --- | --- | --- |
| `zh` | 中文 | `zh-CN` |
| `en` | English | `en` |

允许的代码由宿主 `locales` 定义。未知值回退到英文。未登录时的默认语言是中文，不跟浏览器语言走。

已登录用户的选择存在页面状态 `ui.locale`。这是宿主的事。子包只接收传入的 `locale` 字符串，不自己读取页面状态、`localStorage` 或浏览器语言。

## 字典

英文目录是 key 的来源，其他语言必须正好覆盖同一组 key。

```ts
t("account.expires", { date })
// en: Expires {date}
// zh: 到期时间：{date}
```

约定：

- key 用小写英文和点号，按界面区域分组，例如 `toolbar.bold`、`find.replaceAll`。
- 占位符写成 `{name}`。不要把句子拆开再拼接。
- 需要单复数时，字典写 `files.count.one` 和 `files.count.other`，调用仍传入 `count`。英文按 `count === 1` 选 `one`，其余选 `other`。中文可以让两份文案相同。
- 找不到译文时先用英文，再退回 key 本身。
- 语言的自称不翻译：`locale.zh` 永远是「中文」，`locale.en` 永远是「English」。
- 日期和排序使用当前语言的 `Intl` 区域，中文用 `zh-CN`。
- 文档标题、正文、评论、邮件、文件名、公式、单元格和用户输入不翻译。

宿主的字典在 `packages/i18n`。子包维护自己的目录，不要引用宿主包。

## 给子包的要求

编辑器子包自己保存自己的界面文案。宿主会传入：

```tsx
<RichTextEditor locale={locale} />
```

`locale` 是字符串，当前只有 `zh` 和 `en`。以后可能出现其他代码。子包不认识的代码按 `en` 显示。

子包需要做到：

1. 组件 props 增加可选的 `locale?: string`。缺省时按 `zh` 显示，和现在的中文界面一致。
2. 字典 key 使用稳定的英文标识，例如 `toolbar.bold`、`find.replaceAll`。不要用中文，也不要用会随文案修改的整句英文。
3. 至少提供 `en` 和 `zh` 两份目录，key 集合相同。新增语言时加一份目录即可。
4. 占位符使用 `{name}`。需要数量区分时提供 `key.one` 和 `key.other`，由 `count` 选择。
5. 切换 `locale` 只更新子包自己的按钮、菜单、占位符和提示。不要因此重建文档、Y.Doc、协同适配器或插件列表。
6. 可以额外接受 `messages?: Record<string, string>`，用来覆盖个别文案。没有这份 prop 也可以。覆盖项只替换对应 key，其余仍用子包内置译文。
7. 用户写进文档的文字、公式、单元格内容不翻译。

宿主在安装包的类型声明包含 `locale` 之后，在对应编辑器的挂载处传入当前 `locale`。不要把 `locale` 放进会重建文档、Y.Doc、协同适配器或插件列表的依赖里。类型里还没有该 prop 时不要先传。

## 增加一种语言

1. 在宿主 `locales` 里加入代码，并补上 `html lang`。
2. 增加一份与英文 key 完全相同的宿主目录。
3. 补上该语言在界面上的自称，例如 `locale.ja`。
4. 网页补上对应组件库的 locale 对象。
5. 每个编辑器子包增加同一语言的目录。
6. 已登录用户的语言选择会自动接受新代码，因为宿主校验读的是同一份 `locales`。
