# 网络层技术：地址自动配置
## DHCPv4与DHCPv6/SLAAC地址自动配置
### 学习目标
本节系统梳理IPv4与IPv6网络中最核心的地址自动配置机制，达成以下目标：  
1. 掌握DHCPv4动态地址分配的完整流程、核心报文与状态机（基于RFC2131）；  
2. 对比DHCPv6的**有状态分配**、**无状态配置**与IPv6 SLAAC（无状态地址自动配置）的原理差异与适用场景；  
3. 掌握抓包诊断工具（tcpdump/Wireshark）在地址自动配置故障排查中的具体应用；  
4. 区分各协议的**必需行为**与**可选行为**，理解安全边界与潜在风险。

### 核心机制：DHCPv4动态地址分配（RFC2131）
#### 机制概述与适用场景
DHCPv4（动态主机配置协议v4）是IPv4网络中状态化地址分配的事实标准，由RFC2131（1997）定义，核心是通过客户端-服务器交互完成IP地址、子网掩码、网关、DNS等参数的自动配置。RFC2131明确支持三种分配模式：自动分配（永久IP）、动态分配（临时IP）、手动分配（静态IP注入），其中**动态分配**是主流——适合IPv4地址池有限、设备临时接入（如宿舍、临时办公区）的场景，可动态回收过期地址（RFC2131第2.2节）。

#### 核心报文与状态机
DHCPv4复用BOOTP报文格式，定义7类交互报文，核心流程涉及4类**必需报文**（RFC2131第3节）：  
| 报文类型 | 方向 | 核心作用 | 规则（RFC2131） |
|----------|------|----------|------------------|
| DHCPDISCOVER | 客户端→广播 | 发现可用DHCP服务器 | 客户端无IP时发送，包含事务ID（xid）、硬件地址，广播地址`255.255.255.255`，UDP端口68→67 |
| DHCPOFFER | 服务器→客户端或中继 | 提供可用IP与参数 | 服务器 SHOULD 检查地址是否在用，例如 ICMP Echo；是否单播、广播或经中继回复取决于标志、地址与中继条件，不是固定单播 |
| DHCPREQUEST | 客户端→广播 | 选择服务器并确认 | 客户端收到Offer后，广播通知其他服务器“已选择某Offer”，同时明确请求的IP地址（若未指定则用已配置的ciaddr） |
| DHCPACK/NAK | 服务器→客户端 | 确认配置或拒绝 | ACK携带最终配置；NAK表示分配失败（如地址无效），客户端需回到初始状态重新发起 |

客户端状态机（RFC2131第4节）：`INIT`→`SELECTING`（发Discover）→`REQUESTING`（发Request）→`BOUND`（成功后）→`RENEWING`（T1计时器，租约半程）→`REBINDING`（T2计时器，租约7/8程）→`RENEWED/REBINDING`（收到ACK回到BOUND，否则释放地址）。

#### 关键字段说明（RFC2131表2）
DHCP报文的核心字段直接影响交互逻辑，需重点关注：  
- **xid**：事务ID，客户端每次新交互生成唯一值，匹配请求与响应（必需，防止报文混淆）；  
- **yiaddr**：服务器分配给客户端的IP，仅在Offer/ACK中有效；  
- **ciaddr**：客户端已配置的IP，BOUND状态时填充，INIT状态时为0；  
- **flags**：广播标志，客户端无法单播接收时设为1，服务器需广播响应（必需行为）；  
- **Requested IP Address（50）与 Server Identifier（54）**：SELECTING 阶段的 DHCPREQUEST 用50表示选择的地址，用54标识选择的服务器；续租等其他状态的字段规则不同，不能说所有 REQUEST 都必须携带50。

### 推演例子：DHCPv4完整交互流程
**场景**：家庭网络192.168.1.0/24，DHCP服务器192.168.1.1，客户端PC（MAC:00:11:22:33:44:55）刚开机。  
1. **INIT状态**：PC无IP，发送`DHCPDISCOVER`：xid=0x876543，chaddr=00:11:22:33:44:55，flags=0（可单播），广播到`255.255.255.255`。  
2. **服务器响应Offer**：服务器收到后，探测地址池中192.168.1.15（未分配）无响应，返回`DHCPOFFER`：yiaddr=192.168.1.15，租约时间=86400秒（1天），网关=192.168.1.1，DNS=8.8.8.8，单播到PC的MAC。  
3. **客户端确认请求**：PC收到Offer后，广播`DHCPREQUEST`，携带`Requested IP Address=192.168.1.15`，xid匹配。  
4. **最终配置确认**：服务器收到后，再次探测192.168.1.15无冲突，返回`DHCPACK`，PC将IP设为192.168.1.15，完成配置，进入BOUND状态。  
5. **租期更新**：T1=43200秒（12小时）后，PC单播Request更新，服务器返回ACK；若服务器无响应，T2=69120秒后广播Request，仍无响应则租期到期后释放地址。

### 核心机制：DHCPv6与SLAAC（RFC8415、RFC4862）
IPv6网络的地址自动配置机制分为两类：**SLAAC（无状态）**与**DHCPv6（有状态/无状态）**，核心差异在于是否依赖服务器维护客户端状态。

#### SLAAC（无状态地址自动配置）原理
SLAAC是IPv6的原生无状态机制，无需DHCP服务器，依赖路由器定期发送**Router Advertisement（RA）报文**（ICMPv6类型134），客户端从RA中获取前缀（如`2001:db8:1::/64`），结合自身EUI-64（或随机生成）接口ID，生成**全局单播地址**；同时自动生成链路本地地址（`fe80::/10`）。  
SLAAC的优点是无状态、无需维护绑定、适合快速接入，但仅提供地址，**不提供DNS、网关等参数**（需额外配置或通过RA扩展补充），适合小型网络或家庭环境（RFC4862）。

#### DHCPv6的两种模式（RFC8415）
DHCPv6是IPv6的客户端-服务器协议，分为两种工作模式：  
1. **有状态DHCPv6**：状态化分配，类似DHCPv4，服务器分配IPv6地址、前缀，维护租约，核心报文为`Solicit`（客户端找服务器）→`Advertise`（服务器回应）→`Request`（客户端请求）→`Reply`（服务器确认），适合企业网络、地址管控场景。  
2. **无状态DHCPv6**：不分配地址，仅提供配置参数（如DNS、NTP服务器），常与SLAAC配合：客户端用SLAAC生成地址，通过无状态DHCPv6获取其他参数，适合需要统一参数但无需管控地址的场景（原RFC3736定义的无状态DHCPv6机制被RFC8415整合并取代）。

#### 机制对比表
| 机制 | 地址类型 | 状态性 | 参数范围 | 依赖服务器 | 适用场景 |
|------|----------|--------|----------|------------|----------|
| DHCPv4 | IPv4 | 状态化（租约） | IP、子网掩码、网关、DNS等 | 必需 | IPv4地址池有限、需管控的网络 |
| SLAAC | IPv6 | 无状态（无租约） | 仅IPv6地址 | 无需 | 小型IPv6网络、快速接入 |
| DHCPv6（有状态） | IPv6 | 状态化（租约） | IP、前缀、其他参数 | 必需 | 企业IPv6网络、地址集中管理 |
| DHCPv6（无状态） | IPv6（无分配） | 无状态 | 仅配置参数 | 必需 | 配合SLAAC补充DNS等 |

### 观测与诊断方法
#### 通用工具：抓包分析
使用`tcpdump`或Wireshark可直接观测协议交互，重点命令：  
1. **DHCPv4抓包**：`tcpdump -i eth0 udp port 67 or udp port 68`（端口对应服务器/客户端）；  
2. **DHCPv6抓包**：`tcpdump -i eth0 udp port 546 or udp port 547`；  
3. **SLAAC/RA抓包**：`tcpdump -i eth0 'icmp6 and ip6[40] == 134'`（此偏移示例只适用于无 IPv6 扩展首部的包；有扩展首部时用能解码链路的分析器按 ICMPv6 类型筛选）（ICMPv6类型134为RA）。

#### 常见故障诊断
- **DHCPv4无法获取地址**：检查是否有DHCP服务器（广播是否有Offer）、客户端flags位是否错误（如设为1但服务器无法广播）、地址池是否耗尽；  
- **SLAAC生成地址失败**：检查RA报文是否正常（是否携带前缀）、网卡是否启用IPv6、是否收到`Router Solicitation`后的响应；  
- **地址冲突**：服务器 SHOULD 检查地址未使用（可用 ICMP），客户端 SHOULD 对新地址做最后的冲突检查（可用 ARP）；客户端检测到地址已用时 MUST 发 DHCPDECLINE。参见 RFC2131 §3.1、§4.3.1、§4.4.1。

### 常见误区与安全边界
1. **误区1**：DHCPv6无状态与SLAAC是同一机制——错误，SLAAC不依赖任何服务器，无状态DHCPv6依赖服务器且仅提供参数（RFC8415第6节）；  
2. **误区2**：客户端必须选择最早的 Offer——具体选择策略由客户端实现决定；选择后的 REQUEST 通过 Server Identifier 指明所选服务器，Requested IP Address 指明地址，不能用地址选项代替服务器标识。
3. **安全风险**：  
   - DHCPv4欺骗：恶意服务器发送虚假Offer，中间人攻击，需配置`DHCP Snooping`防范；  
   - RA欺骗：伪造RA报文分配恶意前缀，流量劫持，需配置`RA Guard`防范；  
   - RFC规范：服务器与客户端的冲突探测为 SHOULD，客户端发现冲突后的 DHCPDECLINE 为 MUST；区分推荐行为和强制行为，不要把每次探测都写成 MUST。

### 自测题
1. 简述DHCPv4动态分配的4类核心报文，对应RFC2131的哪几节功能？  
   （答案：Discover用于发现服务器，对应RFC2131第3.1节；Offer用于提供地址，对应第3.2节；Request用于选择并确认，对应第3.3节；ACK/NAK用于最终确认，对应第3.4节）。  
2. SLAAC与有状态DHCPv6的本质区别是什么？结合RFC4862与RFC8415说明。  
   （答案：SLAAC是无状态机制，无需服务器，依赖RA报文生成IPv6地址；有状态DHCPv6依赖服务器维护租约，分配地址并管控生命周期，适合需地址集中管理的场景）。  
3. DHCPv4客户端收到Offer后为何要广播Request报文？依据RFC2131规则。  
   （答案：依据RFC2131第3.1节，广播Request的目的是通知所有已发送Offer的服务器“已选择某一个Offer”，使其他服务器撤回Offer，避免浪费地址池资源）。  
4. 对比DHCPv4与有状态DHCPv6的T1/T2计时器，说明其作用（依据RFC2131与RFC8415）。  
   （答案：T1是租约半程，客户端单播更新；T2是租约7/8，客户端广播更新；用于主动续租，减少服务器状态维护压力，同时保证地址可用性）。
