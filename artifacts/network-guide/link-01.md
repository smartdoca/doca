# 物理介质、以太网标准与二层链路技术
## 学习目标
1.  结合RFC1122规范及工程共识，列举主流有线物理介质的核心特性；
2.  解析DIX以太网帧与IEEE 802.3帧的格式差异，明确MAC地址、VLAN的核心作用；
3.  基于RFC1122规则区分链路层广播与IP广播，识别二层环路的产生原因及典型危害；
4.  掌握二层链路的基础诊断方法（抓包、链路参数查看等）。

## 一、主流物理介质特性（规范与边界说明）
物理介质是二层链路传输的物理载体，RFC1122仅针对早期10Mbps以太网场景定义了基础兼容规则，**更高速率以太网（100Mbps及以上）的介质特性（如双绞线、光纤的具体参数）属于IEEE 802.3标准内容，本次来源未覆盖，仅梳理RFC1122明确的10Mbps以太网介质特性**：
- **同轴电缆（10BASE5/10BASE2）**：10BASE5（粗同轴）最大段长500米，10BASE2（细同轴）最大段长185米，采用总线型拓扑，信号为基带传输，同一网段内所有设备共享带宽，冲突概率高；
- **双绞线（10BASE-T）**：采用星型拓扑，最大段长100米，比同轴电缆更易部署，冲突检测机制更精准，降低了多设备同时传输的碰撞风险。

工程扩展补充：当前主流介质（如Cat5e、Cat6双绞线、多模/单模光纤）的参数来自IEEE 802.3，因来源未覆盖，此处不展开具体规范条文。

## 二、以太网标准与帧格式解析
以太网是最主流的二层链路技术，存在两种核心帧封装标准：DIX Ethernet II（以太网版本2）与IEEE 802.3，RFC1122明确了两者的区分规则与兼容性要求。

### 2.1 帧格式对比（RFC1122节2.2）
两种帧的前6字节为**目的MAC地址（DA）**，后6字节为**源MAC地址（SA）**，差异在于第13-14字节的字段含义，具体对比如下：

| 字段位置（字节偏移） | DIX Ethernet II 帧字段 | IEEE 802.3 帧字段 | RFC1122规则说明 |
|----------------------|-------------------------|-------------------|------------------|
| 12-13（第13-14字节） | Ether-Type（类型标识）  | Length（数据长度）| 若该字段值>1500，则为Ether-Type，标识上层协议（如0x0800=IP，0x0806=ARP）；若≤1500，则为数据长度字段（IEEE 802.3帧的Payload长度） |
| 后续字段             | 上层协议数据载荷        | LLC/SNAP头+数据  | IEEE 802.3帧需携带LLC（逻辑链路控制）头，RFC1042规范中IP需通过SNAP封装，**禁止使用IEEE预留的协议标识K1=6发送802系列报文**（RFC1122明确的强制要求） |

### 2.2 MTU差异与兼容性问题（RFC1122节2.2）
RFC1122定义了两种标准的MTU（最大传输单元）：
- DIX以太网帧：MTU为**1500字节**，数据Payload最大1500字节，帧总长度=14字节（头）+1500字节（Payload）+4字节（FCS校验）=1518字节；
- IEEE 802.3帧：MTU为**1492字节**，因Length字段限制，数据Payload最大1492字节，帧总长度同DIX以太网（≤1518字节）。

**兼容性规则**：RFC1122明确指出，两种帧在同一10Mbps电缆上可物理共存，但接收器通过第13-14字节的数值区分帧类型：若数值>1500则判定为DIX以太网帧，若≤1500则判定为IEEE 802.3帧。若网络中同时存在两种封装，需统一封装标准，否则会导致上层协议解析失败（如ARP请求被误判为IEEE 802.3帧的Payload）。

### 2.3 MAC地址核心作用
MAC地址是二层链路的硬件地址，共48位（6字节），核心作用包括：
1.  **唯一标识链路层设备**：全球唯一（前3字节为厂商OUI，后3字节为设备序列号），是二层帧转发的核心依据；
2.  **地址转换的目标锚点**：ARP协议中，IP地址转MAC地址，通过MAC地址确定链路层的真实通信设备；
3.  **广播/多播/单播区分**：第1字节最低位为0是单播地址（设备唯一），为1是多播/广播地址；全F（`FF:FF:FF:FF:FF:FF`）为二层广播地址，网段内所有设备都会接收该帧。

## 三、VLAN的核心作用（边界说明）
VLAN（虚拟局域网）基于IEEE 802.1Q标准，核心作用是**分割广播域**：同一VLAN内的设备可直接通信，不同VLAN需通过三层设备（路由器或三层交换机）转发，从而减少广播风暴的影响、提升网络安全性。**IEEE 802.1Q的帧格式（如VLAN标签的具体结构、优先级字段）未在来源中提供，仅明确其核心功能**：
- 基于12位VLAN ID标识不同广播域，支持最大4096个VLAN；
- 二层交换机通过VLAN标签（插入在源MAC地址与EtherType/Length字段之间）转发帧，仅将帧转发到对应VLAN的端口，避免跨VLAN的广播扩散。

工程常识补充：VLAN标签占用4字节，因此带VLAN标签的以太网帧总长度比无标签帧多4字节，需确保链路支持更大的MTU（如调整为1504字节），否则会产生IP分片。

## 四、二层环路产生原因与危害
二层环路是指二层网络存在冗余链路但未配置环路避免机制，导致帧在环路中无限循环，进而引发广播风暴。结合RFC1122对广播问题的描述（如广播风暴导致网络瘫痪），其核心产生原因：
1.  交换机之间部署了多条冗余链路（为提升可靠性），但未启用环路避免协议（如STP，属于IEEE 802.1D标准，来源未覆盖具体规范）；
2.  环路存在时，二层广播帧会在环路中持续转发，占用所有链路带宽，导致正常单播帧无法传输，最终引发网络中断。

**推演例子**：交换机A与交换机B通过两根网线连接，未配置STP。当交换机A发送广播帧时，帧会沿链路A→B转发，交换机B会同时将该帧沿另一链路回传给交换机A，形成`A→B→A→B…`的无限循环，所有设备的带宽被广播帧占满，正常业务完全中断，这与RFC1122中讨论的“广播风暴导致网络失效”的场景一致。

## 五、诊断方法（可操作步骤）
针对二层链路的常见问题（帧格式不兼容、环路、MTU不匹配等），提供以下可落地的诊断命令与方法：

### 5.1 查看接口MTU（确认帧格式兼容性）
使用Linux命令`ip link show`查看以太网接口的MTU，判断封装类型：
```bash
# 查看网卡eth0的链路参数与MTU
ip link show eth0
# 输出示例（DIX以太网封装，MTU=1500）：
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 00:1a:2b:3c:4d:5e brd ff:ff:ff:ff:ff:ff
```
接口的MTU是可配置的链路层最大数据单元，与以太网封装类型无直接对应关系，仅通过MTU无法判断封装类型；需通过抓包查看以太网帧的第13-14字节区分两种封装：若该字节数值>1500则为DIX以太网帧（字段为Ether-Type标识上层协议），若≤1500则为IEEE 802.3帧（字段为Length标识数据载荷长度）。

### 5.2 抓包分析帧格式（区分两种封装）
使用Wireshark或`tcpdump`抓包，定位第13-14字节（字节偏移12）的数值，区分帧类型：
```bash
# 抓eth0接口的ICMP报文，显示详细帧结构
tcpdump -i eth0 -vv -c 1 icmp
```
- 若抓到的帧中，第13-14字节为`0x0800`（十进制2048，>1500），则为DIX以太网IP帧；
- 若第13-14字节为`0x05DC`（十进制1500，≤1500），则为IEEE 802.3帧，Payload长度为1500字节。

### 5.3 排查二层环路（网络带宽异常）
通过以下步骤排查环路：
1.  统计接口广播包占比：使用`ethtool -S eth0`查看收发包统计，若`rx_broadcast_pkts`数值远大于`rx_unicast_pkts`且持续增长，可能存在环路；
2.  交换机MAC地址表检查：登录交换机，执行`show mac address-table`，若同一MAC地址出现在多个端口，则环路导致交换机误转发帧到多个端口，需排查冗余链路的STP配置。

## 六、常见误区
1.  **混淆EtherType与Length字段**：部分设备误将IEEE 802.3帧的Length字段当协议标识解析，导致上层协议识别失败，RFC1122明确要求接收器必须通过数值大小（>1500为EtherType，否则为Length）区分，避免此类错误；
2.  **MAC地址唯一性误解**：MAC地址前3字节是厂商OUI，但后3字节为全球唯一序列号，需完整48位匹配才是唯一设备，部分人误以为前24位相同则重复，实则仅前24位是厂商标识，后24位唯一；
3.  **VLAN标签位置错误**：VLAN标签需插入在源MAC地址与EtherType/Length字段之间，若插入到IP头后，交换机无法识别VLAN，会导致跨VLAN通信失败。

## 七、边界与安全
1.  **广播风暴安全风险**：二层环路产生的广播风暴会消耗90%以上的链路带宽，导致DDoS类故障，RFC1122明确禁止向广播地址发送非法报文，需通过STP或VLAN隔离减少此类风险；
2.  **VLAN边界安全**：VLAN虽能隔离广播域，但存在VLAN跳跃攻击（需IEEE 802.1Q细节，来源未覆盖），工程中需将交换机端口配置为Access模式（仅属于一个VLAN），禁止未授权的Trunk模式；
3.  **物理介质故障**：双绞线损坏、光纤断裂会导致链路中断，可通过网卡指示灯或`ethtool eth0`的`link detected`字段判断链路是否连通，RFC1122未涉及现代介质的故障诊断，属于工程经验。
