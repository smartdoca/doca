# 网络进阶技术：组播技术
## IP组播：IGMP与PIM协议机制
### 学习目标
1. 解释IP组播在节约网络带宽方面的核心作用；
2. 掌握IGMP协议的组成员管理逻辑与不同版本的差异；
3. 区分PIM-Sparse Mode（PIM-SM）与PIM-Dense Mode（PIM-DM）的适用场景与行为差异。

### 1 IP组播核心概述
IP组播是一种一对多/多对多的通信模式，仅将数据包传递给特定的目标接收者组，避免全网广播的带宽浪费与单播复制的发送者负载。其核心价值在于：**减少冗余流量（相比广播）、降低发送者的资源消耗（相比单播复制）**，典型应用包括视频会议、IP直播、金融信息推送等。

IP组播的依赖基础分为两层：
1. **组成员管理**：接收者通过IGMP协议向本地路由器报告组加入/离开意愿；
2. **组播路由**：路由器通过PIM等协议建立、维护组播分发树，确保数据包仅流向有接收者的链路。

### 2 互联网组管理协议（IGMP）：组成员管理机制
IGMP是IPv4网络中主机与组播路由器之间的控制协议，负责维护路由器对直连网络上组播组成员的认知。由**RFC 3376（IGMPv3）**定义，向前兼容IGMPv1（RFC 1112）与IGMPv2（RFC 2236），核心目标是让路由器高效感知“哪些链路上有组播接收者”。

#### 2.1 IGMPv3核心服务接口与过滤逻辑
IGMPv3引入`IPMulticastListen`作为组成员的服务接口，替代旧版简单的Join/Leave操作，新增**源过滤**能力——允许主机仅接收来自指定源的组播数据包，这是支持源特定组播（SSM）的基础。接口参数定义如下（RFC 3376第2节）：
| 参数 | 说明 |
|------|------|
| 网络接口 | 主机上接收组播流量的物理/虚拟接口 |
| 组播地址 | 目标组播组的IPv4地址（D类地址224.0.0.0/4范围） |
| 过滤模式 | 分为`INCLUDE`（仅接收指定源的数据包）和`EXCLUDE`（接收除指定源外所有源的数据包） |
| 源列表 | 符合过滤模式的源IP地址集合（空列表对应旧版Join/Leave） |

**旧IGMP版本兼容逻辑**：
- `Join`等价于`IPMulticastListen( socket, interface, G, EXCLUDE, {} )`；
- `Leave`等价于`IPMulticastListen( socket, interface, G, INCLUDE, {} )`（空源列表表示停止接收该组所有源）。

#### 2.2 组成员状态的合并逻辑（RFC 3376第3节）
IGMP维护两层状态，核心是**接口级全局状态**，由多个应用的套接字状态合并而来：
1. **套接字状态**：每个调用`IPMulticastListen`的套接字对应一条（接口，组地址，过滤模式，源列表）记录，后续调用会完全覆盖旧记录；
2. **接口状态**：每个网络接口的全局组播接收状态，是该接口所有套接字状态的并集。

**例子推演**：主机H的两个应用对同一组的不同源要求：
- 应用A：调用`IPMulticastListen(s1, eth0, 239.1.1.1, INCLUDE, {192.168.1.10})`（仅收源192.168.1.10的239.1.1.1）；
- 应用B：调用`IPMulticastListen(s2, eth0, 239.1.1.1, INCLUDE, {192.168.1.20})`（仅收源192.168.1.20的239.1.1.1）；
→ 接口`eth0`对组239.1.1.1的最终状态为：`INCLUDE，源列表={192.168.1.10, 192.168.1.20}`，即该接口需要转发来自这两个源的流量。

#### 2.3 IGMP协议行为与定时器（RFC 3376第5、6、8节）
IGMP分为**组成员（主机）**和**组播路由器**两种角色，行为不对称：
1. **主机行为**：
   - 监听路由器周期性发送的**成员查询**消息，随机延迟后发送**成员报告**响应（避免流量冲突）；
   - 本地组成员状态变化时，立即发送报告；
   - 最后一个应用离开组时，直接发送**离开组**消息（IGMPv2/v3支持快速离开，无需等待查询超时）；
   - 默认定时器：成员查询间隔125秒，报告延迟0-10秒随机。
2. **路由器行为**：
   - 每125秒（默认通用查询间隔，IGMPv3规范标准值）发送通用成员查询，确定直连网络的活跃组；
   - 维护每个直连网络的组状态，向PIM等组播路由协议汇报有接收者的组与源。

#### 2.4 IGMP版本兼容性（RFC 3376第7节）
当IGMPv3主机与IGMPv2路由器通信时：
- 路由器仅发送IGMPv2查询，主机用IGMPv2报告响应；
- 主机的源过滤功能被禁用，仅支持`EXCLUDE`空列表（接收组所有源），旧IGMP版本的Join/Leave逻辑生效。

### 3 协议无关组播（PIM）：组播路由机制
PIM是与底层单播路由协议无关的组播路由协议，核心是利用单播路由表确定组播树的路径。分为两大模式：**密集模式（PIM-DM，RFC 3973）**和**稀疏模式（PIM-SM，RFC 7761，基于RFC 4601修订）**。

#### 3.1 PIM关键术语与基础（RFC 7761第2节）
| 术语 | 说明 |
|------|------|
| 汇聚点（RP） | PIM-SM的根节点，是发送者与接收者的汇合点：发送者将组播包发送到RP，RP转发给接收者 |
|  designated Router（DR） | 每个子网选举出的路由器，代表子网内主机与PIM域通信（发送Join/Prune消息），选举规则：接口PIM优先级最高，相同则IP地址最高 |
| RPF（反向路径转发） | PIM Join消息的下一跳由单播路由表（MRIB）确定，确保Join沿发送者的反向路径传播，避免环路 |

#### 3.2 PIM-SM核心工作流程（RFC 7761第3、4节）
PIM-SM适用于接收者分散的场景，核心是通过“RP共享树→源最短路径树（SPT）”优化流量路径，典型分三阶段：
1. **阶段1：构建RP共享树（(*,G)树）**
   - 子网内主机发送IGMP Join后，DR向RP方向发送`(*,G) Join`消息（代表所有源的组G）；
   - Join沿MRIB路径逐跳转发，沿途路由器创建(*,G)状态；
   - RP成为共享树根，所有发送者的流量先到RP，再转发到接收者。
2. **阶段2：源发现与注册**
   - 组播发送者的DR将数据包封装成**Register**消息发送到RP；
   - RP解封装后，向发送者方向发送`(S,G) Join`，建立以发送者S为根的路径。
3. **阶段3：切换到最短路径树（可选，SSM强制）**
   - 当接收者流量超过阈值（默认1kbps），DR向发送者方向发送`(S,G) Join`；
   - SPT建立后，路由器向RP发送`(*,G) Prune`，停止使用共享树，切换到最优路径。

**SSM模式补充**（RFC 7761第4.8节）：组播地址232.0.0.0/8为SSM专用，PIM-SM在此范围不使用(*,G)树，直接基于(S,G)树，无需RP，适用于已知发送者的场景（如视频点播）。

**例子推演**：组播域拓扑：Sender S(172.16.0.1) → R1 → RP(10.0.0.1) → R2 → Receiver H(192.168.2.10)（R2的子网）：
1. H发送IGMP Join 239.1.1.1，R2作为DR向RP（10.0.0.1）发送(*,G) Join；
2. Join经R1到达RP，RP创建(*,G)状态；
3. S发送239.1.1.1的数据包，R1封装成Register消息发送到RP；
4. RP解封装后，向S方向发送(S,G) Join，R1创建(S,G)状态；
5. R2监测到流量达标，向S方向发送(S,G) Join，同时向RP发送(*,G) Prune，完成树切换。

#### 3.3 PIM-DM与PIM-SM的核心差异
| 维度 | PIM-Dense Mode（PIM-DM） | PIM-Sparse Mode（PIM-SM） |
|------|---------------------------|---------------------------|
| 适用场景 | 组规模大、接收者密集（如企业内部广播） | 组规模小、接收者分散（如会议直播） |
| 核心机制 | 泛洪（所有链路转发组播包）→ 剪枝（无接收者的链路显式剪枝） | 基于RP的共享树，按需切换源树 |
| 信令开销 | 高（定期泛洪刷新，修剪超时恢复泛洪） | 低（仅在加入/切换时发送Join/Prune） |
| 状态维护 | 依赖超时刷新，不支持RP | 显式维护树状态，支持SSM |

### 4 协议观测与诊断方法
#### 4.1 IGMP诊断
1. **抓包分析**：使用`tcpdump`捕获接口IGMP消息：
   ```bash
   tcpdump -i eth0 igmp -vvv  # 查看IGMPv2/v3的类型与内容
   ```
   常见消息：成员查询（类型0x11）、成员报告（v2:0x22，v3:0x22）、离开组（v2:0x17，v3:0x17）。
2. **路由器命令（Cisco示例）**：
   ```ios
   show ip igmp groups detail  # 查看IGMP组的源过滤状态
   show ip igmp interface eth0   # 查看接口IGMP版本与定时器
   ```

#### 4.2 PIM诊断
1. **邻居与RP状态**：
   ```ios
   show ip pim neighbor  # 验证PIM邻居是否建立
   show ip pim rp mapping  # 查看RP映射关系（PIM-SM核心）
   ```
2. **组播路由表**：
   ```ios
   show ip mroute  # 查看(*,G)和(S,G)状态，对应组播树
   ```

#### 4.3 常见问题定位
- IGMP版本不兼容：强制统一接口IGMP版本（`ip igmp version 3`）；
- PIM RPF失败：用`show ip route`确认单播表中到RP/S的路径，确保Join下一跳正确；
- 组播流量未转发：检查接口是否启用PIM模式（`ip pim sparse-mode`），DR选举是否正确。

### 5 安全与边界问题
1. **IGMP安全**：
   - IGMP Snooping（交换机功能）：阻止组播帧向非指定端口转发，避免二层泛洪；
   - 源过滤验证：IGMPv3依赖主机正确维护源列表，需结合ACL防止伪造源加入。
2. **PIM安全**：
   - RFC 7761移除了RFC 4601中的IPsec认证（部署经验不足），建议用ACL控制PIM消息；
   - RP安全：静态配置RP或使用BSM认证，避免恶意RP干扰。
3. **边界限制**：224.0.0.0/24为链路本地组播，路由器不转发，仅用于网关发现等协议。

### 6 自测题（含答案）
1. **问题**：IGMPv3与IGMPv2的核心差异是什么？
   **答案**：IGMPv3新增**源过滤功能**，支持`INCLUDE`（仅收指定源）和`EXCLUDE`（排除指定源）模式，可精细控制组成员的接收源；而IGMPv2仅支持接收组所有源，无源级过滤能力。此外，IGMPv3的成员报告机制更灵活，能更快响应组成员变化。

2. **问题**：PIM-SM中Designated Router（DR）的核心作用是什么？
   **答案**：DR是每个子网的PIM代表，职责包括：（1）接收主机的IGMP Join/Leave消息；（2）向RP（或发送者方向）发送PIM Join/Prune，维护组播树；（3）监测子网内的组播流量，触发源树切换等操作。DR选举确保每个子网仅发送一次Join消息，避免冗余。

3. **问题**：为什么PIM-SM比PIM-DM更适合稀疏组（接收者分散）？
   **答案**：PIM-DM采用泛洪-剪枝机制，当接收者分散时，泛洪会产生大量冗余流量，浪费带宽；而PIM-SM通过RP构建共享树，仅在有接收者的链路上转发流量，信令开销低，且支持SSM模式直接建立最优源树，适配稀疏组的场景。
